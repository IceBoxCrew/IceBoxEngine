## 1. Введение

Редактор IceBox — это программа, которую вы запускаете, чтобы делать игру. Это
**единое окно**, разделённое на докуемые панели, со строкой меню и панелью
инструментов наверху. Всё, что вы делаете — строите уровень, редактируете сущность,
настраиваете физику, тестируете геймплей — происходит внутри этого окна.

Рабочий процесс строится вокруг одной идеи: **уровень** (файл `.icemap`) — это
сцена, которую вы редактируете. Вы населяете её **сущностями** (объектами из
компонентов), организуете их в **Иерархии уровня**, редактируете в панели
**Свойства**, предпросматриваете результат во **Вьюпорте** и нажимаете **ИГРАТЬ**,
чтобы запустить уровень ровно так, как это сделает собранная игра. Ассеты, которые
потребляет уровень — спрайты, тайлмапы, материалы, классы, виджеты — берутся из
**Браузера контента**.

> Язык и тема самого редактора настраиваются (см.
> [Настройки → Редактор](#104-редактор)); в этом документе используются русские
> подписи интерфейса. Все они локализованы на каждый поддерживаемый язык редактора.

## 2. Редактор в общих чертах

### 2.1 Области окна

Свежее окно редактора состоит из пяти областей:

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ Файл Правка Окно Инструменты Справка │ Q E R │ 🔊 100% ▦ │ Скриншот … ИГРАТЬ   │  ← Меню + панель инструментов
│                     │ Удалённый предпросмотр │ MyNewGame    Pre-Release 0.9.1 │
├───────────────────────────────────────────────────┬───────────────────────────┤
│                                                   │  Иерархия уровня          │
│                                                   │  Настройки мира           │  ← Правый док
│                  Вьюпорт                          │  Свойства                 │     (вкладки)
│         (уровень, который вы редактируете)        │                           │
│                                                   │                           │
├───────────────────────────────────────┬───────────┴───────────────────────────┤
│  Браузер контента │ Консоль           │              Статистика               │  ← Нижний док
└───────────────────────────────────────┴───────────────────────────────────────┘
```

| Область | Что это |
| ------- | ------- |
| **Строка меню** | `Файл`, `Правка`, `Окно`, `Инструменты`, `Справка` — см. [Раздел 3](#3-главное-меню). |
| **Панель инструментов** | Кнопки гизмо, аудиомонитор редактора, переключатель сетки, кластер **Скриншот / Пауза / ИГРАТЬ / Извлечь**, кнопка **Удалённый предпросмотр**, кнопки плагинов, имя проекта и версия — см. [Раздел 4](#4-панель-инструментов). |
| **Вьюпорт** | Центральный вид сцены, где вы редактируете уровень — см. [Раздел 5](#5-вьюпорт). |
| **Правый док** | Панели **Иерархия уровня**, **Настройки мира** и **Свойства** (по умолчанию во вкладках). |
| **Нижний док** | **Браузер контента** и **Консоль** (во вкладках), а также панель **Статистика**. |

Строка меню и панель инструментов — это одна общая главная строка ImGui: слева
меню, затем гизмо/аудио/сетка, по центру кластер игры, а имя проекта и версия
прижаты к правому краю.

Панели **Браузер контента** и **Статистика** описаны отдельно
([Ассеты](Assets-RU-DOC.md) и
[Профайлинг и сборка](Profiling-And-Building-RU-DOC.md) соответственно).

### 2.2 Докинг и раскладка

Весь интерфейс — это **док-пространство**. Каждая панель — это окно, которое можно:

* **Перетащить за вкладку**, чтобы передокировать в любое место (разделить область,
  сложить во вкладку или открепить от главного окна).
* **Изменить размер**, потянув за разделитель между областями.
* **Закрыть** крестиком `X` и снова открыть из меню [Окно](#33-окно).

**Раскладка по умолчанию** создаётся автоматически при первом запуске редактора
(когда нет файла `imgui.ini`):

* **Вьюпорт** заполняет центр.
* **Иерархия уровня**, **Настройки мира** и **Свойства** докированы **справа** как
  вкладки (25 % ширины).
* **Браузер контента** и **Консоль** докированы **снизу** как вкладки (30 %
  высоты).
* **Статистика** докирована **снизу справа**.

Каждый редактор ассета (Редактор спрайтов, Редактор классов, Редактор материалов, …)
открывается как свободное окно, которое можно докировать куда угодно. Повторное
открытие того же ассета не создаёт второе окно — фокус переходит на существующее.

### 2.3 Сохранение состояния панелей

Ваше рабочее пространство и настройки между сессиями хранят несколько файлов:

| Файл | Что запоминает |
| ---- | -------------- |
| `imgui.ini` | Раскладку доков — позиции, размеры панелей, какие из них во вкладках, какие плавающие. Удалите его, чтобы сбросить к раскладке по умолчанию. |
| `Config/Editor.json` | Какие панели открыты, последний открытый уровень, список открытых редакторов ассетов, настройки консоли (авто-прокрутка, метки времени, перенос слов, regex, сворачивание повторов, маска уровней, лимит буфера), режим гизмо, видимость сетки, флаги отладочных оверлеев уровня, громкость/мьют аудиомонитора, **Обновить все ассеты при запуске**, **Авто-компиляция при запуске** и все поля Сборки игры / Упаковщика DLC. |
| `Config/Engine.json` | Всё с вкладок [Настроек](#10-настройки-preferences), кроме групп коллизий, — окно, рендеринг, оптимизация, аудио, спецвозможности и сетевые значения по умолчанию. Собранная игра читает тот же файл. |
| `Config/CollisionGroups.json` | Имена групп коллизий и матрицу коллизий ([Настройки → Коллизия](#103-коллизия)). |
| `<Проект>.iceproject` | Манифест проекта. Редактор держит `StartScene` указывающим на открытый уровень и обновляет `EngineVersion` при открытии проекта. |

`Config/Editor.json` записывается **автоматически каждые 5 секунд** и ещё раз при
выходе, поэтому состояние панелей и настройки сборки переживают даже аварийное
завершение. Переключение режима гизмо, сетки или аудиомонитора сохраняет файл сразу.

Открытые **редакторы ассетов** (Редактор спрайтов, Редактор материалов и т. д.)
тоже восстанавливаются: при повторном запуске редактора панели ассетов снова
открываются на тех же ассетах.

### 2.4 Живое отслеживание контента

Пока редактор запущен, он рекурсивно следит за всей папкой `Content/`.
Отслеживаются все типы ассетов движка (`.ice_*` и `.icemap`), а также исходные
форматы — `.png`, `.jpg`, `.jpeg`, `.wav`, `.ogg`, `.mp3`, `.flac`, `.ttf`, `.otf`,
`.mp4`, `.avi`, `.mkv`, `.mov`, `.webm`, `.lua` и `.txt`.

Когда что-то меняется на диске:

* Небольшое плавающее окно **Изменения файлов** перечисляет свежие записи
  `Created` / `Modified` / `Deleted`. Каждая строка живёт 5 секунд; **Очистить**
  опустошает список, а закрытие окна убирает его. Окно показывается только вне
  режима игры.
* Для **вновь созданного** исходного файла автоматически создаётся его сайдкар —
  изображения получают настройки импорта `.ice_texture`, аудио — `.ice_sound`,
  шрифты — `.ice_font`, видео — `.ice_video`. Что такое сайдкары, см. в
  [Ассетах](Assets-RU-DOC.md).
* Изменённый `.ice_localization` перезагружает игровую локализацию проекта.
* Все ассеты обновляются, а каждый экземпляр класса в открытом уровне
  перезагружается, так что внешние правки видны во вьюпорте без перезапуска.

Сохранение из самого редактора на несколько секунд подавляет наблюдатель, чтобы
ваши собственные записи не вызывали лишнюю перезагрузку.

Отдельно **скрипты классов** (`.ice_class`) горячо перезагружаются при изменении,
когда включена [Авто-компиляция при запуске](#32-правка) — точное поведение см. там.

### 2.5 Язык, шрифты и RTL-раскладка

Язык интерфейса выбирается в [Настройки → Редактор](#104-редактор) и охватывает
**14 языков**: английский, русский, украинский, китайский, арабский, хинди,
испанский, португальский, японский, французский, немецкий, итальянский, польский и
иврит.

* Шрифт редактора загружается из `Config/Fonts` с объединённым набором глифов,
  покрывающим латиницу, **кириллицу**, **китайский (упрощённый, частотный)**,
  **японский**, **арабский**, **иврит** и **деванагари**, поэтому ни один язык не
  превращается в квадратики.
* Для языка с письмом справа налево (арабский, иврит) редактор зеркалит свою
  раскладку: заголовки окон, текст кнопок и выделяемых элементов выравниваются
  вправо, а кнопка сворачивания/меню окна переезжает вправо.
* При активном **Шрифте для дислексии** редактор пересобирает UI-шрифт: ваш
  дислексия-шрифт становится основным, а обычный шрифт редактора остаётся резервом
  для недостающих глифов (см.
  [Настройки → Специальные возможности](#108-специальные-возможности)).
* При открытии и закрытии панели плавно появляются и исчезают за доли секунды —
  это чисто косметика и настройки не требует.

Файл шрифта, его размер и цвет, а также масштаб UI (1×–4×) тоже находятся на
вкладке [Редактор](#104-редактор). Смена шрифта или языка пересобирает атлас
шрифтов.

## 3. Главное меню

Строка меню идёт по самому верху окна.

### 3.1 Файл

| Пункт | Клавиша | Действие |
| ----- | ------- | -------- |
| **Новый уровень** | — | Открывает диалог **Новый уровень**: выберите папку назначения, введите имя, и редактор покажет живой предпросмотр итогового пути `…/Имя.icemap` (с предупреждением, если такой уже существует). **Создать** создаёт и открывает пустой уровень. Если запущен режим игры, он сначала останавливается. |
| **Открыть уровень** | — | Открывает диалог **Открыть уровень** с выбором ассета `.icemap`. **Открыть** загружает выбранный уровень. Если запущен режим игры, он сначала останавливается. |
| **Сохранить уровень** | `Ctrl+S` | Сохраняет текущий уровень (сущности, папки Иерархии, размещённые объёмы view/cinema, Настройки мира и скрипт уровня) в его `.icemap`. |
| **Редактор скриптов уровня** | — | Переключает окно **Скрипт уровня** — Lua- (или Visual Script-) редактор для собственных колбэков уровня `OnLevelStart` / `OnLevelUpdate(dt)` / `OnLevelEnd`. См. [Раздел 14](#14-уровни-диалоги-и-скрипты). |
| **Обновить все ассеты** | — | Сохраняет уровень и все «грязные» редакторы ассетов, обновляет ассеты, **компилирует все скрипты классов**, пересобирает объёмы пост-обработки и перезагружает все экземпляры классов в уровне. Это ручная кнопка «привести всё в актуальное состояние». |
| **Обновить все ассеты при запуске** | (переключатель) | Когда **включено** (по умолчанию), нажатие **ИГРАТЬ** сначала выполняет тот же проход сохранения и обновления, чтобы режим игры всегда отражал ваши последние правки. Отключите для более быстрого старта, когда уверены, что ничего не менялось. |
| **Выход** | `Alt+F4` | Закрывает редактор. Если в уровне есть несохранённые изменения, сначала появляется диалог **Несохранённые изменения** (Сохранить / Не сохранять / Отмена). |

Между **Сохранить уровень** и **Редактор скриптов уровня** стоит разделитель.

### 3.2 Правка

| Пункт | Клавиша | Действие |
| ----- | ------- | -------- |
| **Отменить** | `Ctrl+Z` | Откатывает последнее изменение. Какой стек используется — зависит от фокуса, см. примечание ниже. |
| **Повторить** | `Ctrl+Y` (или `Ctrl+Shift+Z`) | Повторно применяет последнее отменённое изменение. |
| **Компилировать все скрипты** | `Ctrl+R` | Компилирует все скрипты классов и сообщает число ошибок. Недоступно, пока идёт режим игры. (`Ctrl+R` в редакторе также обновляет ассеты — выполняется тот же проход, что и **Обновить все ассеты**.) |
| **Авто-компиляция при запуске** | (переключатель) | Два эффекта, оба включены по умолчанию: (1) скрипты классов **горячо перезагружаются** на живых сущностях при изменении их `.ice_class` — включая сущности, чей класс наследуется от изменённого; (2) если **Обновить все ассеты при запуске** выключено, вход в режим игры сначала компилирует все скрипты классов и предупреждает в Консоли о неудачах. |
| **Настройки** | — | Открывает окно [Настройки](#10-настройки-preferences). |

> **Три независимых стека отмены.** Редактор не держит одну общую историю:
> * Стек **сцены** (перемещение/масштаб/поворот/создание/удаление сущностей,
>   правки папок и мировых объёмов) — используется, когда в фокусе вьюпорт или
>   Иерархия.
> * Стек **файловых операций Браузера контента** (создание/переименование/
>   перемещение/копирование/удаление) — используется, пока в фокусе Браузер
>   контента. Операции, выполненные одной пачкой, и отменяются целиком одной пачкой.
> * **Собственный стек** внутри каждого редактора ассетов (Спрайт, Тайлмап,
>   Материал, Виджет, …). Пока эта панель в фокусе, `Ctrl+Z`/`Ctrl+Y` работают с
>   ней, а глобальные стеки не трогаются.
>
> Каждый стек хранит до **50 состояний**. Перетаскивания объединяются в один шаг,
> поэтому протаскивание гизмо по вьюпорту — одна отмена. Отмена сцены и файлов
> заблокирована в режиме игры, а оба стека очищаются при создании или открытии
> уровня.

## 4. Панель инструментов

Справа от меню панель инструментов содержит самые часто используемые элементы.
Слева направо:

### 4.1 Режим гизмо (Q / E / R)

Три кнопки выбирают поведение [гизмо трансформации](#53-гизмо-трансформации-и-привязка)
во вьюпорте. Активный режим подсвечен синим.

| Кнопка | Режим | Клавиша |
| ------ | ----- | ------- |
| **Q** | **Перемещение** (translate) | `Q` |
| **E** | **Масштаб** (scale) | `E` |
| **R** | **Поворот** (rotate) | `R` |

Выбор сразу сохраняется в `Config/Editor.json` и восстанавливается между сессиями.
Клавиши `Q`/`E`/`R` переключают режимы только когда **вьюпорт под курсором** и ни
одно текстовое поле не в фокусе, поэтому ввод имени в Иерархии никогда не меняет
гизмо. У Редактора классов свой независимый режим гизмо.

### 4.2 Аудиомонитор редактора

Небольшая **иконка динамика**, за которой следует **ползунок громкости** (показан в
процентах, например `100%`). Это управляет **аудиомониторингом редактора** — звуком,
который вы слышите при редактировании (предпросмотр звуков, анимаций, FX). Он **не**
меняет настройки проекта и никак не влияет на сборки игры.

* Кликните по **динамику**, чтобы выключить/включить монитор редактора (иконка
  краснеет в выключенном состоянии).
* Тяните **ползунок**, чтобы задать громкость монитора от 0 до 100 %.

Обе настройки хранятся в `Config/Editor.json`.

### 4.3 Переключатель сетки

**Иконка сетки**, которая показывает или скрывает редакторскую сетку вьюпорта. Это
только для редактора и никогда не влияет на игру. Размер сетки, цвет, толщина линий
и привязка к сетке находятся в [Настройки → Редактор](#104-редактор); сетка рисуется
только в режиме редактирования.

### 4.4 Скриншот

Кнопка **Скриншот** захватывает текущее изображение вьюпорта и открывает системный
диалог сохранения, по умолчанию в файл с меткой времени
`screenshot_ГГГГММДД_ЧЧММСС.png`. Важные детали:

* Захватывается **фреймбуфер сцены** в его физическом разрешении, поэтому
  **Масштаб рендера** (см. [Настройки → Движок](#101-движок)) меняет размер
  результата.
* Захватывается только отрисованная сцена — без интерфейса редактора и без гизмо.
* Изображение сохраняется как **RGBA PNG**; если вы введёте имя без `.png`,
  расширение будет добавлено. Путь сохранения выводится в Консоль.

### 4.5 Play, Pause и Eject

Центральный кластер запускает и контролирует режим игры. **Режим игры** запускает
уровень ровно так, как это сделал бы собранный рантайм: выполняются скрипты,
симулируется физика, перехватывается ввод.

| Кнопка | Состояние | Действие |
| ------ | --------- | -------- |
| **ИГРАТЬ** / **СТОП** | всегда активна | Входит в режим игры или выходит из него (`F3`). |
| **Пауза** / **Продолжить** | только в игре | Ставит на паузу или возобновляет идущую симуляцию (`F5`). |
| **Извлечь** / **Внедрить** | только в игре | Отсоединяет камеру, чтобы вы могли облетать запущенную игру через `ПКМ + WASD`, не влияя на неё; **Внедрить** возвращает управление игре (`F2`). |

**Вход в игру** выполняет по порядку:

1. Если включено **Обновить все ассеты при запуске** — сохраняет и обновляет все
   ассеты.
2. Записывает шаг отмены и делает **полный текстовый снимок сцены** плюс текущее
   выделение.
3. Если включена **Авто-компиляция при запуске**, а шаг 1 был пропущен —
   компилирует все скрипты классов и предупреждает о неудачах.
4. Применяет действующие настройки физики (переопределение
   [Настроек мира](#8-настройки-мира), если оно включено, иначе глобальные значения
   Настроек) и переопределение рендеринга.
5. Передаёт скрипт уровня в скриптовый движок и отдаёт проигрывателю кат-сцен
   размещённые объёмы **cinema** (флаги авто-воспроизведения, «один раз», триггера).
6. Применяет **пользовательский курсор** из Настроек либо восстанавливает
   стандартный.
7. Скрывает системный курсор, переключается в режим относительной мыши и запускает
   рантайм.
8. Сообщает отладчикам Lua и Visual Script, что игра началась.

**Выход из игры** останавливает рантайм, сбрасывает паузу и извлечение камеры,
уничтожает живые эмиттеры FX, очищает реестр и **восстанавливает снимок до
запуска** — любое изменение, сделанное во время игры, отбрасывается, — после чего
возвращает курсор.

> **Курсор в режиме игры.** Вход в игру скрывает системный курсор и переключает в
> режим относительной мыши (для обзора в стиле FPS). Нажмите `Shift+F1`, чтобы
> вернуть курсор, не выходя из игры.

> **Редактирование во время игры.** С **извлечённой** камерой вы можете выбирать и
> двигать сущности во время игры; гизмо пишет прямо в живую симуляцию (и
> синхронизирует физическое тело при перемещении и повороте). Помните, что эти
> правки отбрасываются при остановке игры.

> **Живые Настройки мира.** Правка переопределения Настроек мира во время игры
> применяется к работающему миру немедленно, так что гравитацию или освещение можно
> подбирать прямо на ходу.

### 4.6 Кнопка удалённого предпросмотра

Переключатель, запускающий/останавливающий сервер стриминга
[Удалённого предпросмотра](#12-удалённый-предпросмотр). Когда он активен, кнопка
становится **зелёной**, а её подпись отражает состояние соединения:
`Удалённый предпросмотр` → `Удалённый (ожидание...)` → `Удалённый (подключено)`.
Наведите на неё, чтобы увидеть команду `adb reverse`, а при подключённом устройстве —
живые FPS стрима и пропускную способность. Подробная панель настроек открывается
через **Инструменты → Удалённый предпросмотр**.

На сборках для **macOS этой кнопки нет**.

### 4.7 Имя проекта и версия

* **Имя проекта** (например, `MyNewGame`) показано после разделителя — это поле
  `Name` из манифеста `.iceproject`.
* **Версия движка** (например, `Pre-Release 0.9.1`) прижата к правому краю строки. Она
  читается из `Config/Updater.json` (`PR-0.9.1` → `Pre-Release 0.9.1`), с откатом на
  версию, с которой был собран редактор.

Любые **кнопки панели инструментов, зарегистрированные плагинами**, появляются между
кнопкой удалённого предпросмотра и именем проекта.

## 5. Вьюпорт

**Вьюпорт** — это центральная панель с заголовком `Вьюпорт - <ИмяУровня>`
(звёздочка `*` отмечает несохранённые изменения). Он показывает отрисованный уровень
и является местом, где вы размещаете, выбираете и трансформируете сущности.

### 5.1 Навигация камерой

Редакторская камера — это 2D-ортографическая камера. Навигация работает, когда
вьюпорт под курсором:

| Ввод | Действие |
| ---- | -------- |
| **ПКМ + W/A/S/D** | Панорамирование камеры (удерживайте ПКМ, затем используйте WASD). Скорость = **Скорость камеры редактора** × время кадра × текущий зум, поэтому при отдалении панорамирование остаётся удобным. Панорамирование следует текущему наклону, поэтому W всегда двигает «вверх по экрану». |
| **ПКМ + Q / E** | Наклон вида против / по часовой стрелке — сцена на экране поворачивается в ту же сторону. Скорость наклона = 90°/с × (**Скорость камеры редактора** ÷ её значение по умолчанию), поэтому тот же `Left Shift+Scroll`, что настраивает панорамирование, настраивает и наклон. Градусы по часовой стрелке — плюс, ровно как у `SetCameraRotation` в рантайме. |
| **ПКМ + R** | Мгновенно вернуть наклон в ноль. |

> Пока удерживается правая кнопка мыши, вьюпорт находится в режиме камеры, поэтому `Q` / `E` / `R` наклоняют камеру, а не
> переключают гизмо. Отпустите ПКМ — и это снова горячие клавиши гизмо.
>
> Наклон — это состояние вида в редакторе: он не сохраняется в уровень, не пишется в `editor.json` и никогда не трогает
> `Rotation` ни у одного компонента камеры в сцене. Пикинг, рамка выделения, гизмо и перетаскивание ассетов следуют
> наклонённому виду, поэтому всё остаётся под курсором там, где вы ожидаете.
| **Колесо мыши** | Зум с привязкой к курсору — точка мира под указателем остаётся на месте. |
| **Левый Shift + Колесо** | Изменение **скорости** панорамирования камеры на лету (ограничена минимумом движка и удвоенной настроенной скоростью). |
| **F** | Сфокусировать камеру на выбранной сущности (центрирует её во вьюпорте). |

Пределы зума и шаг зума настраиваются в [Настройки → Редактор](#104-редактор). В
режиме игры зум отключён, если камера не **извлечена**.

### 5.2 Выделение сущностей

| Ввод | Результат |
| ---- | --------- |
| **ЛКМ** | Выбрать верхнюю сущность под курсором. Попадание считается по **видимым границам** (инстансы спрайтов, флипбуков или тайлмапов, иначе бокс по умолчанию), а побеждает кандидат с **наибольшим Z** трансформа. |
| **Ctrl + Клик** | **Переключить** кликнутую сущность в множественном выделении — клик по уже выбранной убирает её. |
| **ЛКМ + Перетаскивание** | Нарисовать **рамку** выделения; выбираются все сущности, чьи границы её пересекают (удерживайте `Ctrl`, чтобы добавить к текущему выделению). Меши скелета тоже учитываются. |
| **Клик по пустому месту** | Снимает выделение — если только клик не попал внутрь размещённого объёма **view** (границы пост-обработки или нав-сетки) либо в маркер-бокс объёма **cinema**: тогда выбирается этот мировой ассет. |

Перетаскивание короче 5 px считается кликом, поэтому лёгкое дрожание руки не мешает
выделять. Выделение разделяется с [Иерархией уровня](#6-иерархия-уровня) и управляет
панелью [Свойства](#7-панель-свойств). Клик во вьюпорте также снимает выделение в
Браузере контента.

### 5.3 Гизмо трансформации и привязка

Когда сущность выбрана, в её начале координат появляется **гизмо трансформации**,
рисуемое в **мировых координатах**. Активный
[режим гизмо](#41-режим-гизмо-q--e--r) решает, что оно делает:

* **Перемещение** — тяните за оси, чтобы двигать.
* **Масштаб** — тяните, чтобы масштабировать; каждая ось ограничена **0.01 – 10**.
* **Поворот** — тяните за кольцо; результат ограничен **±360°**.

При **множественном выделении** перетаскивание гизмо применяет одну и ту же дельту
(перемещение, масштаб или поворот) ко всем выбранным сущностям. Завершение
перетаскивания записывает один шаг отмены. Переворот осей отключён, поэтому ручки
не «прыгают» посреди перетаскивания.

**Привязка.** Когда в [Настройки → Редактор](#104-редактор) включена **привязка к
сетке**, к размеру сетки привязывается **перемещение**, а также ассеты, брошенные
во вьюпорт. Масштаб и поворот не привязываются никогда.

**Мировые ассеты.** У выбранного объёма **view** или **cinema** тоже есть гизмо, но
только **перемещения** — и только если объём ограничен (у бесконечного view-объёма
нет позиции, которую можно тянуть). Перемещение view-объёма сразу пересобирает
список объёмов пост-обработки.

### 5.4 Контекстное меню вьюпорта

**Короткий правый клик** (быстрое нажатие без панорамирования — меньше 0,2 с и
меньше 5 px смещения) открывает контекстное меню вьюпорта:

* Приглушённая подсказка, что во вьюпорт можно перетащить `.ice_class`, чтобы
  создать сущность.
* **Редактировать класс** — если выбрана ровно одна сущность, созданная из класса,
  открывает её ассет класса в Редакторе классов (следуя редиректору ассетов, если
  класс был перемещён).
* **Удалить выбранное** (`Del`) — удаляет выбранные сущности.
* Для выбранного объёма **view/cinema**: его имя, затем **Открыть в редакторе** и
  **Удалить**.
* Любые контекстные пункты плагинов для контекстов `viewport` и `entity`.

Пока идёт режим игры без извлечённой камеры, показываются только пункты плагинов.
**Долгий правый клик или правое перетаскивание** вместо меню панорамирует камеру.

### 5.5 Перетаскивание ассетов в сцену

Перетаскивайте из **Браузера контента** во вьюпорт:

| Перетаскиваемый ассет | Результат |
| --------------------- | --------- |
| **Класс** (`.ice_class`) | Инстанцирует класс как новую сущность в точке броска (с привязкой к сетке, если включена), затем выбирает её. |
| **View** (`.ice_view`) | Размещает **объём пост-обработки / нав-сетки** в точке броска (появляется в Иерархии в разделе *Мировые ассеты*). |
| **Cinema** (`.ice_cinema`) | Размещает **триггер кат-сцены** в точке броска (тоже *Мировой ассет*). |

Любой другой тип ассета, брошенный во вьюпорт, игнорируется. Броски заблокированы,
пока идёт режим игры без извлечённой камеры. Другие типы ассетов размещаются через
Редактор классов; см. [Ассеты](Assets-RU-DOC.md).

### 5.6 Режим игры во вьюпорте

В режиме игры вьюпорт показывает **запущенную игру**. Панели Иерархии и Свойств
приглушены (только для чтения), пока вы не **Извлечёте** камеру — тогда снова
работают выделение, гизмо, `F`, `Delete` и `Ctrl+C/X/V` для отладки. См.
[Play, Pause и Eject](#45-play-pause-и-eject).

### 5.7 Отладочный текст на экране

Игровые скрипты могут печатать текст поверх вьюпорта — фиксированные сообщения в
стиле HUD, привязанные к левому верхнему углу, и метки в мировых координатах (через
`PrintScreen` / `PrintScreenEx` / `DrawWorldText`). Оба вида рисуются прямо поверх
вьюпорта в режиме редактирования и в режиме игры, с тенью, собственным цветом и
масштабом сообщения и затуханием по мере истечения таймера. Мировые метки за
пределами вьюпорта пропускаются. Функции входят в рантайм-API отладки,
перечисленный в панели [Горячие клавиши](#131-горячие-клавиши) и описанный в
[Lua API](LuaAPI-RU-DOC.md).

### 5.8 Отладочные оверлеи во вьюпорте

Раздел *Отладка* панели **Статистика** содержит около 23 переключателей оверлеев,
рисующихся во вьюпорте: коллайдеры, нав-сетка, маркеры сущностей, радиусы света,
дальность звука, фрустум камеры, соединения, контакты физики, спящие тела, векторы
скорости, сетка тайлмапа, границы FX/виджетов, окраска по Z, каркасный режим,
заморозка отсечения, плюс продвинутая группа (карты теней, рёбра теней, тепловая
карта света, тепловая карта нав-сетки, состояние/восприятие/пути ИИ).

Со стороны редактора важны две вещи:

* Переключатели **сохраняются на проект** в `Config/Editor.json` и
  восстанавливаются при следующем запуске.
* Они также читаются и пишутся из скриптов по имени
  (`GetDebugFlag` / `SetDebugFlag` / `ToggleDebugFlag`), поэтому скрипт уровня может
  включить оверлей во время теста.

Сами оверлеи описаны в
[Графика → Отладочная визуализация](Graphics-RU-DOC.md#12-отладочная-визуализация);
панель, где они живут, — в
[Профайлинге и сборке](Profiling-And-Building-RU-DOC.md#34-отладочная-визуализация).

## 6. Иерархия уровня

**Иерархия уровня** (`Окно → Иерархия уровня`) — это иерархия сцены: каждая сущность
уровня, организованная в опциональные папки, плюс любые размещённые мировые объёмы.

**Верхние элементы управления**

* **Поиск…** — живой регистронезависимый фильтр сущностей по имени. Папки остаются
  видимыми; скрываются только их несовпадающие дети.
* **Создать папку** — добавляет организационную папку с именем `New Folder`.
* Приглушённая подсказка: *Перетащите .ice_class во вьюпорт*.
* **Удалить** — появляется, только когда выбраны сущности; удаляет их.

**Дерево**

* **Сущности** перечислены по их тегу (имени) с однобуквенной иконкой: `[C]` —
  камера, `[S]` — спрайт-рендерер, `[L]` — сущность из класса/со скриптом, `[E]` —
  остальные. Если сущность была создана из класса и потом переименована, строка
  показывает `Тег (ИмяКласса)`, чтобы было понятно, что это.
* **Папки** (`[F]`) — чисто организационные группировки. Перетащите сущности на
  папку, чтобы поместить их туда; папки можно вкладывать (дерево перестаёт
  рекурсивно раскрываться глубже 10 уровней). Состояние раскрытия и состав
  сохраняются вместе с уровнем.
* **Мировые ассеты** — размещённые объёмы **view** (`[V]`) и **cinema** (`[C]`)
  появляются в собственном разделе внизу под заголовком *Мировые ассеты*. При
  наведении показывается путь ассета и позиция (а для ограниченного view-объёма —
  ещё и масштаб, либо *Бесконечно* для неограниченного).

**Операции**

| Ввод | Действие |
| ---- | -------- |
| **Клик** | Выбрать сущность, папку или мировой ассет — три вида выделения взаимоисключающие. |
| **Ctrl + Клик** | Переключить сущность в множественном выделении. |
| **Shift + Клик** | Выбрать весь видимый диапазон между последней кликнутой сущностью и этой. |
| **Двойной клик** | На сущности из класса — открывает её ассет класса. На мировом ассете — открывает `.ice_view` / `.ice_cinema`. |
| **F2** | Переименовать выбранную сущность или выбранную папку. |
| **Delete** | Удалить выбранную сущность, папку или мировой ассет. |
| **Ctrl + C / X / V** | Копировать / вырезать / вставить сущности (вставленные копии слегка смещаются и переименовываются). Работает и когда в фокусе вьюпорт. |
| **Ctrl + A** | Выбрать все сущности. |
| **Перетаскивание** | Переместить сущность (или всё множественное выделение) в папку, либо папку в другую папку. Бросок на пустое место панели выносит объекты из всех папок. |
| **Правый клик по сущности** | Копировать / Вырезать / Вставить и **Переместить в папку ▸** с пунктом `(Нет)` и всеми папками. |
| **Правый клик по папке** | **Переименовать папку**, **Создать подпапку**, **Удалить папку** и **Переместить в корень** для вложенной папки. |
| **Правый клик по мировому ассету** | **Удалить**, **Открыть в редакторе**. |
| **Правый клик по пустому месту** | **Создать папку** и подсказки по перетаскиванию. |

Все сочетания работают, когда Иерархия в фокусе, не открыт попап и не активно
текстовое поле.

> Перетаскивание ассета **класса** на Иерархию инстанцирует его в начале координат
> (бросьте на папку, чтобы сразу поместить туда); перетаскивание ассета **view**
> добавляет мировой объём. Объёмы **cinema** нужно бросать во
> [вьюпорт](#55-перетаскивание-ассетов-в-сцену), где они получают позицию.

## 7. Панель свойств

Панель **Свойства** (`Окно → Свойства`) редактирует то, что сейчас выбрано —
сущность, несколько сущностей или размещённый мировой объём.

### 7.1 Заголовок сущности и переопределения класса

Для одиночной сущности наверху панели показано:

* **Тег** — имя сущности, редактируемое прямо на месте.
* Если сущность была **инстанцирована из класса** — раздел **синхронизации с
  классом**:
  * **Переопределить значения класса** — когда **включено**, ваши правки здесь
    хранятся пер-сущностно в уровне и *не* перезаписываются шаблоном класса при
    сохранении/перезагрузке. Когда **выключено**, янтарное предупреждение отмечает,
    что значения класса главенствуют и локальные правки сбросятся при перезагрузке.
  * Живая строка состояния: зелёное **«Синхронизировано со значениями класса»** или
    янтарный сворачиваемый заголовок **«Изменено относительно класса (N)»** со
    списком именно тех компонентов, что отличаются. Компонент, который есть в
    классе, но которого больше нет у сущности, отмечается как `… (removed)`.
  * Раздел [переопределения скрипта на уровне
    экземпляра](#75-переопределения-скрипта-на-уровне-экземпляра).

Сравнение намеренно **игнорирует Position в Transform**, поэтому простое размещение
экземпляра на уровне никогда не считается «изменением относительно класса».
Идентификационные компоненты (ID, тег, иерархия) тоже игнорируются, а сравнение
идёт с **полностью слитым** шаблоном класса, поэтому наследуемые классы
сравниваются корректно.

### 7.2 Компоненты

Ниже заголовка каждый **компонент** сущности — это сворачиваемый раздел со своими
полями, по умолчанию раскрытый. Доступные типы компонентов:

| Компонент | Назначение |
| --------- | ---------- |
| **Transform** | Позиция, масштаб, поворот (пространственный корень каждой сущности). |
| **Sprite Renderer** | Рисует один или несколько спрайтов с материалом/затенением/смешиванием/оттенком и пер-инстансными трансформами. |
| **Flipbook** | Воспроизводит покадровые спрайтовые анимации. |
| **Animator** | Управляет флипбуками из машины состояний анимации (`.ice_animation`). |
| **Skeleton** | 2D-скелетная анимация (кости, слоты, скины, IK, физические кости). |
| **Tilemap Renderer** | Рендерит тайлмап (`.ice_tm`), опционально генерируя коллизию. |
| **Camera** | Игровая камера (флаг основной, зум, прямоугольник вьюпорта, индекс игрока для разделённого экрана). |
| **Rigidbody** | Тело Box2D (Static / Kinematic / Dynamic) с массой, затуханием, гравитацией, bullet (CCD), сном. |
| **Collider** | Формы Box / Circle (сфера) / Capsule с физматериалом, сенсорами, односторонностью и группами коллизий. |
| **Destructible** | Разрушаемая геометрия, дробящаяся при ударе. |
| **Audio** | Прикреплённый источник звука (2D или пространственный 3D). |
| **FX** | Экземпляр системы частиц (`.ice_fx`). |
| **Widget** | Прикреплённый UI-виджет (`.ice_widget`). |
| **Light** | Точечные и конусные источники света (цвет, интенсивность, радиус, тени, световой куки). |
| **Point Marker** | Именованные локальные якори для скриптинга/прикрепления. |
| **AI** | Экземпляр дерева поведения (`.ice_ai`) со своим блэкбордом. |
| **Joint** | Физическое соединение, связывающее два тела. |
| **Stencil** | Управление маской/отсечением по трафарету для маскированного рендеринга. |
| **Replication** | Настройки сетевой репликации для всей сущности: реплицируется ли она, кто владелец, какие аспекты синхронизируются (трансформ, скорость, визуал, полное состояние), выполняется ли Lua на репликах и релевантность по области интереса. По умолчанию выключено, поэтому синглплеерные проекты не затрагиваются. |
| **Class Component** | Встраивает другие классы как под-объекты (композиция). У каждого экземпляра есть имя, трансформ и путь класса; под списком сводка *Предоставляет (резолвится в рантайме)*, сгруппированная по вкладу встроенных классов (спрайты, коллайдеры, свет, …). |

> **Откуда берутся компоненты.** Панель Свойств редактирует компоненты, которые у
> сущности **уже есть**, — кнопки *Добавить компонент* здесь нет. Компоненты
> добавляются и удаляются у **Класса** в [Редакторе классов](Assets-RU-DOC.md), и
> каждый экземпляр этого класса подхватывает изменение. Именно это удерживает
> экземпляры в синхронизации с шаблоном и именно это измеряет индикатор «Изменено
> относительно класса».

> Данные, которые каждый компонент рендерит/симулирует, подробно описаны в документе
> [Графика, рендеринг и физика](Graphics-RU-DOC.md) (рендеринг, свет, физика) и в
> документе [Ассеты](Assets-RU-DOC.md) (ассеты, на которые они ссылаются). Скриптовые
> компоненты описаны в [Lua API](LuaAPI-RU-DOC.md).

### 7.3 Редактирование при множественном выделении

С несколькими выбранными сущностями панель показывает заголовок *N сущностей
выбрано* и единственный раздел **Transform** со значениями позиции, масштаба и
поворота первой из них. Правка поля применяет **дельту** к каждой выбранной
сущности, у которой есть Transform, а изменения позиции и поворота во время игры
сразу пишутся в живое физическое тело. Разделы компонентов при множественном
выделении не показываются — используйте гизмо или редактируйте сущности по одной.

Для массового редактирования *ассетов* (а не сущностей) используйте
**Property Matrix** из Браузера контента (см. [Ассеты](Assets-RU-DOC.md)).

### 7.4 Свойства мировых ассетов (View и Cinema)

Когда выбран размещённый объём **view** или **cinema** (вместо сущности), панель
Свойств показывает его размещение: **имя**, **путь ассета** и редактируемую
**Позицию**. Всё остальное живёт в других местах:

* Стек пост-обработки и параметры нав-сетки принадлежат ассету `.ice_view` —
  дважды кликните по объёму (или используйте **Открыть в редакторе**), чтобы
  править их в Редакторе View. Сам стек описан в
  [Графика → Пост-обработка](Graphics-RU-DOC.md#9-пост-обработка).
* Флаги cinema **Авто-воспроизведение / Один раз / Триггер при пересечении / Тег
  триггера** относятся к конкретному размещению и находятся в
  [Настройки мира → Кат-сцена](#8-настройки-мира); сам таймлайн кат-сцены — в
  Редакторе Cinema.

### 7.5 Переопределения скрипта на уровне экземпляра

Под заголовком синхронизации с классом у сущности, созданной из класса, есть раздел
**Lua-скрипт (переопределение класса)**. Он нужен, чтобы один экземпляр вёл себя
иначе, чем его класс, без клонирования класса — например, чтобы связать конкретную
кнопку с конкретной дверью.

**Проекты на Lua**

* Когда **Переопределить Lua-скрипт** выключено, скрипт класса показан **только для
  чтения**, а кнопка **Очистить сохранённое переопределение** появляется, если в
  уровне ещё лежит устаревшее переопределение.
* Включение копирует скрипт класса в уровень как отправную точку и разблокирует
  редактор. В тулбаре появляются **Компилировать** с инлайновым значком
  `OK`/`Ошибка` (ошибки отмечаются на нужной строке и показываются во всплывающей
  подсказке), **Сбросить к скрипту класса** и **Показать родителя** /
  **Скрыть родителя**, открывающая доступную только для чтения панель скрипта
  класса для сравнения.
* Текст переопределения хранится в `.icemap`, а не в файле класса.

**Проекты на Visual Script**

* Тот же флажок переключает между графом класса и его пер-экземплярной копией.
* **Edit Visual Graph** открывает граф в отдельном окне с кнопкой **Компилировать**
  и строкой статуса; рядом показано число узлов. Правки на лету компилируются в Lua
  и сохраняются вместе с сущностью.
* **Сбросить к скрипту класса** заново копирует граф класса.

## 8. Настройки мира

Панель **Настройки мира** (`Окно → Настройки мира`) содержит **переопределения для
уровня** — настройки, применяемые только к редактируемому уровню, поверх глобальных
[Настроек](#10-настройки-preferences). Наверху показаны имя и путь текущего уровня;
если уровень не открыт — *Уровень не загружен. Откройте или создайте уровень.*

**Переопределение физики** — поставьте галочку **Переопределить физику уровня**,
чтобы дать уровню собственную физику. Поля зеркалят
[Настройки → Физика](#102-физика): Пиксели-на-метр, Гравитация X/Y, Подшаги
решателя и Фиксированный шаг, а также флаги мира (Сон, Непрерывная коллизия/CCD,
Порог реституции, Порог события удара, Контактная частота, Коэффициент демпфирования
контакта, Макс. скорость выталкивания контакта, Максимальная линейная скорость).
**Сбросить к глобальным значениям** копирует текущие глобальные значения. Когда
переопределение выключено, панель так и пишет, а уровень использует глобальную
физику.

> **Рабочие потоки физики** намеренно *не* переопределяются на уровне — эта
> настройка глобальна для движка и фиксируется при создании физического мира. См.
> [Настройки → Физика](#102-физика).

**Переопределение рендеринга** — поставьте галочку **Переопределить рендеринг
уровня**, чтобы дать уровню собственный вид. Это зеркалит
[Настройки → Рендеринг](#105-рендеринг):

* **Режим освещения** (Без освещения / С освещением) и, в режиме «С освещением»:
  цвет и интенсивность **фонового** света.
* **2D-тени** — включение, качество лучей (Низкое/Среднее/Высокое/Ультра), мягкость,
  интенсивность, смещение (bias, X/Y), сэмплы PCF, **длина направленной тени**,
  **затухание направленной тени по глубине** и **коллайдеры блокируют тени**.
* **Трассировка лучей** (только если поддерживается аппаратно, иначе раздел так и
  сообщает) — включение, качество, интенсивность, отскок, макс. отскоки, отражение,
  макс. расстояние, трассируемое AO и его радиус, отклик альбедо, свет неба,
  резкость деталей, растекание цвета с экрана, шумоподавление, теневые лучи.
* **Направленный свет** — включение, отбрасывание теней, цвет, интенсивность,
  направление X/Y.
* **Плоскости отсечения** (ближняя / дальняя) и **цвет очистки** (фон).

**Сбросить рендеринг к глобальным значениям** копирует текущие глобальные значения.

**Раздел кат-сцен** — если на уровне есть размещённые объёмы **cinema**, заголовок
*Кат-сцена* перечисляет каждый из них с путём и позицией и позволяет задать
**Авто-воспроизведение**, **Один раз**, **Триггер при пересечении** и, когда
пересечение включено, **Тег триггера**.

Все Настройки мира сохраняются внутри `.icemap`. Они применяются автоматически при
загрузке уровня и при нажатии ИГРАТЬ — а пока идёт игра, любая правка применяется к
живому миру немедленно. Любое изменение здесь также помечает уровень изменённым и
записывает шаг отмены.

## 9. Консоль

**Консоль** (`Окно → Показать консоль`, или вкладка нижнего дока) показывает логи
движка и игры и позволяет выполнять команды. По умолчанию она во вкладке с Браузером
контента.

### 9.1 Строка меню

* **Правка** — Копировать (`Ctrl+C`), Копировать видимое, Выбрать всё (`Ctrl+A`),
  Сохранить лог…, Сохранить видимое…, Очистить (`Ctrl+L`). Пункты гаснут, когда им
  не с чем работать.
* **Вид** — переключатели **Автопрокрутка**, **Показывать метки времени**,
  **Перенос слов**, **Сворачивать повторы** (складывать одинаковые подряд идущие
  строки в счётчик `(xN)`) и **Лимит буфера (строк)** — максимум хранимых строк,
  100–50000, по умолчанию 2000.

Все эти настройки сохраняются в `Config/Editor.json`.

### 9.2 Панель инструментов и фильтры

| Элемент | Функция |
| ------- | ------- |
| **Пауза / Продолжить** | Заморозить входящие логи. На паузе они буферизуются (в пределах того же лимита) и сбрасываются при возобновлении. |
| **Очистить** | Опустошить лог (`Ctrl+L`). |
| **Автопрокрутка** | Прилипать к новейшей строке. Прокрутка колесом вверх отпускает прилипание; возврат вниз включает его снова. |
| **Trace / Info / Warn / Error** | Кнопки-переключатели уровней с живыми счётчиками, окрашенные по уровню. ЛКМ переключает уровень; **ПКМ оставляет соло** только этот уровень. |
| **Фильтр…** | Живой регистронезависимый фильтр по подстроке в тексте сообщения. |
| **.\*** | Включить режим **regex** для фильтра (ECMAScript, без учёта регистра). Некорректный шаблон просто ничего не показывает, пока вы его не исправите. |
| **[категория]** | Когда вы фильтруете по ведущему тегу строки в квадратных скобках из её контекстного меню, здесь появляется чип с крестиком `x` для удаления. |

### 9.3 Список логов

Каждая строка имеет префикс — букву уровня (`T`, `I`, `W`, `E`), опционально метку
времени (`ЧЧ:ММ:СС.ммм`) и суффикс `(xN)`, когда повторы свёрнуты. Текст окрашен по
уровню — Trace серый, Info белый, Warn янтарный, Error красный, — а строки Warn и
Error дополнительно получают тонированный фон, чтобы выделяться при прокрутке.

* **Клик** выбирает строку; `Ctrl+Клик` добавляет отдельные строки, `Shift+Клик`
  расширяет диапазон, а перетаскивание выделяет диапазон (с авто-прокруткой за
  краями).
* **Двойной клик** копирует строку.
* **F3 / Shift+F3** прыгают к следующей/предыдущей строке, совпадающей с текущим
  фильтром, прокручивая её в вид и выделяя.
* **Правый клик** по строке: Копировать, Копировать видимое, Выбрать всё, **Фильтр
  по категории** (только если сообщение начинается с тега в скобках), **Скрыть это
  сообщение** (навсегда скрывает в текущей сессии все строки ровно с этим текстом),
  **Открыть исходник** (`файл:строка` — разбирается из сообщения и открывается в
  подходящем редакторе), Сохранить лог…, Сохранить видимое… и Очистить.

**Строка состояния** внизу сообщает счётчики Всего / Показано, счётчики по уровням
(T/I/W/E, где warn и error подсвечиваются при ненулевом значении), число выбранных
строк и значок `[ПАУЗА]`, когда на паузе.

Длинные логи не тормозят: строки отсекаются до видимых, а отфильтрованный вид
кэшируется и пересобирается только когда лог или фильтр действительно меняются.

### 9.4 Строка ввода и команды

Нижняя строка ввода выполняет код или команды. **Кнопка языка** циклически
переключает режим ввода между **Lua**, **Py** (Python) и **Sh** (системная
оболочка) — по умолчанию **Sh**, — и обычный ввод выполняется на выбранном языке.
**Вверх/Вниз** листают историю ввода (последние 200 записей), **Esc** очищает поле,
а **Enter** или кнопка **Выполнить** запускает. После выполнения фокус возвращается
в поле.

Строки, начинающиеся с `/` (или `:`), — это **команды консоли**:

| Команда | Эффект |
| ------- | ------ |
| `/clear`, `/cls` | Очистить все логи. |
| `/help`, `/?` | Список команд. |
| `/pause`, `/resume` | Пауза/возобновление входящих логов. |
| `/filter <текст>` | Задать быстрый фильтр. |
| `/level <T\|I\|W\|E\|*>` | Соло-уровень лога (`*` показывает все). |
| `/save` | Сохранить полный лог в файл. |
| `/echo <текст>` | Напечатать текст. |
| `/lua <код>` | Выполнить строку Lua. |
| `/py <код>` (`/python`) | Выполнить строку Python. |
| `/sh <команда>` (`/cmd`, `/shell`, `/bash`) | Выполнить команду системной оболочки (поддерживает пайпы, `&&`, `.bat`, …). Вывод и код возврата попадают в лог. |
| `/cd [папка]`, `/pwd` (`/cwd`) | Сменить / показать рабочую папку оболочки. `~` и относительные пути разрешаются, папка сохраняется между командами. |
| `/mode <lua\|py\|sh>` | Задать язык по умолчанию для обычного ввода. |

Неизвестная команда печатает предупреждение с указанием на `/help`.

> Сами языки Lua и Python описаны в [Lua API](LuaAPI-RU-DOC.md) и
> [Python API](PythonAPI-RU-DOC.md). Консоль — лишь одно из мест их вызова. Python
> доступен только в редакторских сборках.

> Панель **Консоль** здесь — это лог-вид редактора. Отдельная внутриигровая
> **консоль разработчика** (оверлей, который ваша собранная игра может открыть в
> рантайме) — часть рантайма, а не этой панели редактора.

### 9.5 Откуда берётся вывод консоли

Консоль подключена как **лог-приёмник** к обоим логгерам движка на уровне trace,
поэтому получает всё, что выводят движок и ваша игра, включая сообщения из Lua,
Python и плагинов. Каждая строка приходит уже отформатированной как
`[ЧЧ:ММ:СС] [логгер] сообщение` — именно отсюда действие *Фильтр по категории*
берёт свой тег.

Записи лога принимаются на том потоке, который их породил, и сливаются под
блокировкой, поэтому фоновая работа (загрузка ассетов, сборки, сетевые потоки)
попадает в лог безопасно и по порядку.

## 10. Настройки (Preferences)

**Правка → Настройки** открывает окно настроек редактора. Оно организовано в
**девять вкладок**, и каждая вкладка заканчивается тремя кнопками:

* **Сохранить** — записать настройки этой вкладки на диск (`Config/Engine.json`,
  либо `Config/CollisionGroups.json` для вкладки Коллизия), чтобы они сохранились.
* **Применить** — применить настройки этой вкладки к работающему редактору
  немедленно.
* **Сбросить** — восстановить значения по умолчанию для этой вкладки.

Под вкладками три кнопки действуют сразу на **все** вкладки: **Сохранить всё**,
**Применить всё** и **Сбросить всё к умолчанию** (последняя сбрасывает, сохраняет и
применяет за один шаг).

Некоторым настройкам нужен **перезапуск** — сглаживанию, когда задействован MSAA,
значениям лимитов шейдеров на вкладке Оптимизация и числу рабочих потоков физики.

### 10.1 Движок

Окно и производительность верхнего уровня:

* **Ширина / Высота окна**, **Целевой FPS** (1–240).
* **Масштаб рендера** (1–200 %) — множитель внутреннего разрешения
  (повышение/понижение).
* **VSync**, **Режим низкой задержки**, **Прогрев проекта при запуске** (прогрев
  кэшей при загрузке).
* Вывод **HDR10**, где поддерживается, с уровнями **paper-white** (80–400 нит) и
  **макс. яркости** (400–10000 нит). Применяется сразу — и в редакторе, и в собранной
  игре, — поэтому всё окно редактора и вьюпорт выводятся через сигнал HDR10, а строка
  состояния сообщает, действительно ли свопчейн получил HDR-поверхность. См.
  [Графика → Вывод HDR10](Graphics-RU-DOC.md#103-вывод-hdr10).
* **Режим окна** — Оконный / Полноэкранный / Безрамочный.
* **Сглаживание** — Off, FXAA (Post), MSAA 2×/4×/8×, SSAA 2×/4×. Переключение на
  MSAA или с него показывает предупреждение о перезапуске; MSAA также открывает
  **Alpha-to-Coverage**.
* **Масштабирование** — **FSR** (AMD FidelityFX Super Resolution 1.0) или **NIS**
  (NVIDIA Image Scaling), с пресетом качества (Ультрапроизводительность 33 % /
  Производительность 50 % / Сбалансированное 59 % / Качество 67 % / Ультракачество
  77 % / Нативное 100 %), переключателем **Повышение резкости** и её силой 0–1. По
  умолчанию выключено. Это **только Vulkan, Direct3D 12, Metal и WebGPU
  и с гейтом по видеокарте** — NIS дополнительно требует карту NVIDIA — и раздел показывает причину
  недоступности, когда она есть. Пресет перемножается с масштабом рендера и режимами
  SSAA, а панель печатает получающееся внутреннее разрешение. См.
  [Графика → Масштабирование](Graphics-RU-DOC.md#102-масштабирование-fsr-и-nis).
* **Адаптивное качество** с целевым FPS (30–240) — авто-подстройка качества под
  кадровую частоту.
* **Автоопределение** — опрашивает машину и подставляет разумные значения FPS,
  масштаба рендера, AA, масштабирования, VSync, HDR10, низкой задержки, прогрева и
  качества звука.
* Пресет **Качество звука** — Очень низкое (8000 Hz) / Низкое (16000 Hz) /
  Средне-низкое (22050 Hz) / Среднее (44100 Hz) / Высокое (48000 Hz) /
  Очень высокое (96000 Hz).
* **Пользовательский курсор** — `.ice_sprite` или `.ice_flipbook`, горячая точка
  X/Y и масштаб (0.5–10). Применяется при старте режима игры и в собранной игре.

### 10.2 Физика

Глобальные значения Box2D по умолчанию (уровень может переопределить их в
[Настройках мира](#8-настройки-мира)): **Пиксели-на-метр**, **Гравитация X/Y**,
**Подшаги** решателя (1–16) и **Фиксированный шаг**, а также флаги мира: **Сон**,
**Непрерывная коллизия** (CCD), **Порог реституции**, **Порог события удара**,
**Контактная частота**, **Коэффициент демпфирования контакта**, **Макс. скорость
выталкивания контакта**, **Максимальная линейная скорость**. Они напрямую идут в
физический мир; см. [Графика → Физика](Graphics-RU-DOC.md#13-физика).

**Рабочие потоки физики** задают, сколькими потоками Box2D решает шаг физики,
считая главный поток. **Авто** (по умолчанию) подбирает безопасное значение по
числу ядер CPU — не более 8 на десктопе и не более 4 на мобильных, — а `1`
полностью выключает многопоточность физики. В отличие от остальных полей, эта
настройка глобальна для движка, не переопределяется на уровне и применяется только
после перезапуска движка, потому что число рабочих потоков фиксируется при создании
физического мира. Выигрыш заметен в сценах с большим числом активных тел и
контактов; на маленьких сценах разницы нет. Реально используемое число показывает
секция **Физический мир** в панели Статистики. В веб-сборках физика всегда
однопоточная.

### 10.3 Коллизия

Управляет **группами коллизий** и **матрицей коллизий**:

* Добавление, переименование и удаление именованных групп коллизий (группа `0` —
  по умолчанию и не может быть удалена).
* **Матрица** — это сетка флажков, решающая, какие группы сталкиваются с какими.
* **Сохранить / Применить / Сбросить** записывают `Config/CollisionGroups.json`.

Коллайдеры ссылаются на эти группы по индексу; см.
[Графика → Физика](Graphics-RU-DOC.md#13-физика).

### 10.4 Редактор

Внешний вид самого редактора:

* **Тема** — Тёмная / Светлая / **Своя**. Выбор «Своей» берёт за основу текущую
  палитру и открывает полный редактор цветов ImGui, сгруппированный по разделам:
  **Общее** (текст, приглушённый текст, фон окна/дочернего окна/попапа, рамка,
  строка меню), **Рамки** (фон поля и его состояния при наведении/нажатии,
  скроллбар, галочка, ползунок), **Кнопки**, **Заголовки** (состояния заголовка и
  разделитель), **Вкладки** и **Заголовок окна** (обычный, активный, свёрнутый).
* **Язык** — язык интерфейса редактора, из 14 поддерживаемых.
* **Шрифт** — файл (сканируется из `Config/Fonts`), размер (8–72 px) и цвет, с
  кнопкой **Обновить** для пересканирования папки.
* **Масштаб UI** (1×–4×).
* **Сетка** — размер (1–1000), толщина линий (0.01–1), цвет, **привязка к сетке**,
  **показывать сетку**.
* **Камера** — скорость камеры редактора, мин. и макс. зум (они ограничивают друг
  друга) и шаг зума.

### 10.5 Рендеринг

Глобальные значения рендеринга по умолчанию (уровень может переопределить их в
[Настройках мира](#8-настройки-мира)):

* **Режим освещения** (Без освещения / С освещением).
* **Рендер-бэкенд** — список зависит от платформы и сборки: OpenGL 4.6 /
  OpenGL 3.3 (/ Vulkan, если он скомпилирован, / Direct3D 12 на Windows, если он
  скомпилирован) на Windows и Linux, а на macOS — Metal (нативный, по умолчанию) /
  Metal (ANGLE) / Metal (MoltenVK). Выбор
  записывается в `Config/Engine.json` и применяется при следующем запуске редактора, а
  если выбранный бэкенд на машине недоступен, срабатывает автоматическая цепочка
  отката.
* **Активный рендерер** — только для чтения: бэкенд, на котором редактор рисует
  *прямо сейчас*, и **видеокарта** за ним. Проект, у которого рендерер ещё не
  зафиксирован, получает его при первом открытии — проходом цепочки платформы сверху
  (Windows: Direct3D 12 → Vulkan → OpenGL 4.6 → OpenGL 3.3; Linux: Vulkan → OpenGL 4.6 →
  OpenGL 3.3; macOS: Metal → Metal (MoltenVK) → Metal (ANGLE)); новые проекты несут
  результат пробы уже с момента создания в лаунчере. Если в списке выше выбран не тот
  бэкенд, что активен, под этой строкой появляется напоминание перезапустить редактор.
  Подробности — в
  [Графике → Бэкенды и платформы](Graphics-RU-DOC.md#22-бэкенды-и-платформы).
* В режиме «С освещением»: **Фоновый** свет (цвет и интенсивность); **2D-тени**
  (включение, качество лучей, мягкость, интенсивность, смещение, сэмплы PCF, длина
  и затухание направленной тени, «коллайдеры блокируют тени»); **Трассировка
  лучей** (если поддерживается); **Направленный свет** (включение, тени, цвет,
  интенсивность, направление).
* **Плоскости отсечения** (ближняя / дальняя) и **цвет очистки** (фон).

Полный смысл каждого параметра — в документе
[Графика, рендеринг и физика](Graphics-RU-DOC.md).

### 10.6 Оптимизация

Тонкие настройки рендерера и памяти:

* **Отсечение** — отступ отсечения в пикселях и режим отсечения
  (**AABB (По умолчанию)** / **PerPixel (Точный)**).
* **Пакетирование** — макс. квадов / частиц / инстансов на пакет.
* **Текстурные слоты** — макс. текстурных юнитов для бэкендов GL и GLES.
* **Лимиты освещения** — макс. активных точечных источников света.
* **Отладка** — размер отладочного вершинного буфера.
* **Текстурный атлас** — размер страницы атласа, макс. размер спрайта, макс. размер
  текстуры.
* **Приостановка** — **Приостанавливать без фокуса**: когда включено (поведение по
  умолчанию), приложение ставит на паузу обновление, рендер и звук, пока окно не в
  фокусе, свёрнуто или в фоне, на всех шести платформах; когда выключено, игра
  продолжает работать и играть звук без фокуса. Также доступно из скриптов через
  `Settings.SetIsSuspended`.
* Сводка **жёстких лимитов** (compile-time), которые движок принудительно соблюдает
  (макс. точечных источников света, макс. текстурных слотов).

Изменение текстурных слотов, лимита точечных источников, отладочного буфера,
размеров атласа или любого размера пакета показывает янтарную пометку «требуется
перезапуск движка», потому что эти значения зашиваются в шейдеры при старте.

### 10.7 Аудио

Глобальный микшер:

* **Мастер-управление** — Выкл. всё, Мастер-громкость, Глобальное усиление (0–2).
* **Громкости групп** — Музыка, SFX, Голос, Эмбиент, UI.
* **3D-аудио** — переключатель пространственного аудио и, когда он включён, фактор
  Доплера, скорость звука и расстояния затухания по умолчанию (мин./макс.) со
  спадом.
* Сводка **информации об аудио**: имя активного устройства, частота дискретизации и
  число каналов (показывается после инициализации аудиосистемы).

### 10.8 Специальные возможности

Широкий набор спецвозможностей (мастер-переключатель **Специальные возможности
включены**, затем): Гамма, Контраст, Яркость, Насыщенность; **Поле зрения
(линза)** со слайдером угла; режим **Дальтонизм**
(Протанопия / Дейтеранопия / Тританопия / Ахроматопсия) с силой;
**Шрифт для дислексии**; **Синтез речи (TTS)** (включение, скорость, громкость, тон);
**Скорость игры** (0.25×–2×, применяется к игровому времени кадра); и
**Принудительное моно-аудио**. Эти настройки доступны играм, чтобы они учитывали
выбор игрока.

**Поле зрения** — это линза, а не фрустум камеры. 2D-камера остаётся
ортографической, поэтому отсечение, освещение, физика и пересчёт экран↔мир
не затрагиваются — слайдер управляет экранным искажением линзы. `90°` —
нейтраль, больше `90°` кадр выгибается наружу (широкий угол, бочка), меньше
`90°` вгибается внутрь (телеобъектив, подушка); диапазон `60°–120°`. Искажение
скорректировано по соотношению сторон, поэтому одно и то же значение выглядит
одинаково на 16:9, 21:9 и портретной мобиле, а кадр остаётся полностью
заполненным — без замыленных краёв и чёрных полос. Это один полноэкранный
проход в конце цепочки пост-обработки на всех рендер-бэкендах; он сам включает
путь пост-обработки (то есть работает и на уровне без объёма пост-обработки) и
полностью пропускается, пока переключатель выключен. Элементы виджетов
композитятся после пост-обработки, если не помечены как *Post Processed*,
поэтому HUD не искажается. Так как это экранное искажение, координаты мыши не
перепроецируются: на больших углах курсор и выбранная мировая точка расходятся
у углов кадра — ровно как у пост-эффектов Heat Haze и Underwater.

**Путь к шрифту для дислексии** указывает на `.ttf`/`.otf` внутри папки
`Content/` проекта (выбирается через пикер ассетов; хранится относительно
Content, но пути с префиксом `Content/` и абсолютные тоже работают). Пока
замена активна, UI-шрифт самого редактора пересобирается с дислексия-шрифтом
в качестве основного (обычный шрифт редактора остаётся резервом для
недостающих глифов), а все шрифты игрового рендера текста — элементы виджетов
со своими шрифтами и без, тултипы, выпадающие списки — подменяются и во
вьюпорте редактора, и в запущенной игре.

При включённом **Синтезе речи** редактор озвучивает текст под курсором и
тултипы после короткой задержки; в режиме Play и в собранной игре рантайм виджетов
автоматически проговаривает элемент виджета под курсором (включая неинтерактивные
текстовые подписи), тултипы, наведённые пункты выпадающих списков и элемент,
сфокусированный при навигации с геймпада/клавиатуры. Обе функции читаются из
`Config/Engine.json`, поэтому собранная игра подхватывает их автоматически —
нажмите **Сохранить** (или **Сохранить всё**), чтобы значения пережили текущую
сессию редактора.

### 10.9 Сеть

Значения по умолчанию для сетевой подсистемы, сгруппированные так:

* **Настройки сервера** — макс. игроков, порт.
* **Настройки соединения** — IP сервера, таймаут.
* **Переподключение** — включение, макс. попыток, интервал.
* **Производительность** — тикрейт, частота снэпшотов, задержка интерполяции.
* **Безопасность** — пароль, белый список, валидация сущностей, макс. скорость
  сущности.
* **Голосовой чат** — включение, режим близости, радиус близости, таймаут
  активности, макс. ретранслируемых голосов.
* **Расширенные** — режим выделенного сервера, **Порт WebSocket (0 = выкл.)** для
  веб-клиентов, **Модель доверия** (*Соревновательная (авторитетный сервер)* /
  *Кооперативная (доверенные пиры)*), компенсация задержки, дельта-компрессия,
  предсказание, макс. длительность истории.
* **Модерация** — фильтр мата, кулдаун чата, лимит серии сообщений, окно
  ограничения частоты.
* **Ограничения** — макс. история чата, макс. история сущностей, макс. нарушений
  лимита частоты.
* **Текущий статус** — роль, игроки онлайн, вместимость и пинг во время сессии;
  иначе примечание, что сеть не активна.

**Живой** тестовый клиент/хост — это [Менеджер сети](#11-менеджер-сети-enet).

## 11. Менеджер сети (ENet)

**Инструменты → Менеджер сети (ENet)** открывает живой стенд для теста мультиплеера
на базе ENet. У него своя строка меню с **Сеть → Очистить лог** и две вкладки
верхнего уровня.

**Тест сети** — захостить или подключиться к сессии и прогнать её:

* Цветная строка **Статус**: *Не в сети*, *Подключение…*, *Переподключение…*,
  *Ошибка подключения*, *Подключено* или *Сервер запущен*.
* Радиокнопки **Режим** — **Оффлайн / Хост / Клиент**. Хостинг открывает **Макс.
  игроков**, подключение — **IP сервера**. Оба режима открывают **Порт**
  (1024–65535) и скрытый **Пароль**. Всё это блокируется, пока сессия активна.
* **Запустить сервер** / **Подключиться** и **Остановить сервер** / **Отключиться**
  (красная) после подключения. События подключения/хостинга выводятся в лог чата как
  системные сообщения.
* Четыре внутренние вкладки:
  * **Чат** — лог сообщений с селектором **Режим**: **Общий / Канал / ЛС**. Режим
    канала добавляет поле имени канала с кнопками **Присоединиться** и
    **Покинуть** и показывает список каналов, в которых вы состоите; режим ЛС
    добавляет поле имени получателя. Сообщения окрашены по типу (системные, общие,
    `#канал`, личные), а вид авто-прокручивается.
  * **Пиры** — на сервере: подключённые игроки с кнопками **Кик**, **Бан** и
    **Заглушить голос** у каждого; на клиенте: адрес сервера и ваш RTT.
  * **Статистика** — тип соединения, пинг, тикрейт, частота снэпшотов, отправленные
    и полученные байты, число пиров, число сущностей, серверное время и задержка
    интерполяции, плюс флаги возможностей. На сервере здесь же живые ползунки и
    флажки: **Тикрейт** (1–128), **Частота снэпшотов** (1–60),
    **Дельта-компрессия**, **Предсказание** и **Валидация сущностей**.
  * **Голос** — есть только когда голосовой чат включён в конфиге: включить/заглушить
    себя, а также по каждому игроку — мьют, громкость (0–2) и индикатор передачи.
* **Диагностика отката** — сворачиваемый раздел, показывающий состояние
  rollback-нетокода, когда он работает: синхронизация/работа, дескриптор локального
  игрока, число игроков, текущий и подтверждённый кадр, предсказанные кадры,
  откатов в секунду, средняя и максимальная глубина отката и преимущество по кадрам.

**Профайлер сети** — вторая вкладка с живыми графиками, сэмплируемыми несколько раз
в секунду, и флажком **Пауза**, замораживающим сэмплирование:

* **Задержка** — пинг (зелёный/жёлтый/красный по порогам), задержка интерполяции и
  смещение синхронизации времени для клиентов, плюс график пинга.
* **Пропускная способность** — всего отправлено/получено байт, текущие скорости
  отправки/приёма и два графика скоростей.
* **Пакеты** — номер пакета, частота пакетов, тикрейт, частота снэпшотов и график
  частоты пакетов.
* **Синхронизация сущностей** — число реплицируемых сущностей (с графиком) и, на
  сервере, подключённые пиры относительно вместимости.
* **Возможности** — компенсация задержки, дельта-компрессия, предсказание, валидация
  сущностей и шифрование, плюс значок выделенного сервера.
* **Статистика по пирам** — на сервере разворачиваемый узел для каждого пира с
  временем в сети, RTT, потерянными пакетами и отправленными/полученными байтами.

> Значения сетевой конфигурации по умолчанию находятся в
> [Настройки → Сеть](#109-сеть); игровое сетевое API — в
> [Lua API](LuaAPI-RU-DOC.md). Скриптовая поверхность `NetworkProfiler.*`,
> зеркалящая эту панель, перечислена в панели
> [Горячие клавиши](#131-горячие-клавиши).

## 12. Удалённый предпросмотр

**Инструменты → Удалённый предпросмотр** (и кнопка на панели инструментов) стримят
запущенную игру на **Android-устройство по USB**, отправляя обратно сенсорный ввод
и данные датчиков — идеально для тестирования мобильного управления без полной
сборки. На **macOS функция недоступна**.

**Как это работает.** Редактор поднимает небольшой TCP-сервер, слушающий **только
localhost**, а приложение-компаньон на Android подключается к нему через
`adb reverse`. Пока идёт режим игры, редактор шлёт JPEG-кадры, игровой звук и
вибрацию на устройство, а устройство отправляет обратно касания, показания
акселерометра и гироскопа прямо в систему ввода движка. В режиме редактирования
ничего не стримится — чтобы увидеть картинку, войдите в режим игры.

**Вибрация.** Пока устройство подключено, `PlayHaptic`, `PlayHapticPreset`,
`PlayHapticPattern` и `StopHaptic` уходят на вибромотор телефона, а не на десктоп, и
`IsHapticSupported()` возвращает `true` — то есть привычная в игровом коде проверка
`if IsHapticSupported() then …` их не пропустит. Сила, пресеты и зацикленные
паттерны передаются по проводу целиком, поэтому мобильную вибрацию можно настраивать
прямо из редактора, без полной сборки. Маршрут разбирается — с предварительной
отправкой команды остановки — как только устройство отключается или заканчивается
режим игры, и локальный бэкенд снова берёт вибрацию на себя.

Панель показывает:

* **Состояние** — `Stopped` (остановлено), `Waiting for device...` (ожидание
  устройства), `Handshaking...` (рукопожатие) или `Device Connected` (устройство
  подключено), с цветовой индикацией. Эту строку отдаёт сам сервер, поэтому она
  всегда на английском.
* **Порт** (1024–65535, по умолчанию 7780). Если порт занят, сервер автоматически
  пробует следующие 15 портов и сообщает, какой действительно занял.
* **FPS стрима** (10–60), **Качество JPEG** (10–100) и **Масштаб разрешения**
  (0.1–1.0, по умолчанию 0.5), чтобы менять пропускную способность на точность.
* **Запустить сервер** / **Остановить сервер**.
* Пока сервер запущен: команда `adb reverse tcp:<порт> tcp:<порт>` и кнопка
  **Развернуть на устройство** в один клик.
* При подключении: живые **FPS стрима**, **пропускная способность** устройства и —
  только когда кадры реально пропускаются — янтарный счётчик **Пропущено**.

**Развернуть на устройство** делает всю подготовку за один шаг, показывая прогресс
на месте:

1. Проверяет, что `adb` доступен в `PATH` (и подсказывает установить Android SDK
   Platform-Tools, если нет).
2. Находит авторизованное устройство (и сообщает, если запрос на USB-отладку ещё не
   подтверждён).
3. Выполняет `adb reverse` для порта, на котором поднят сервер.
4. Убеждается, что APK-компаньон **IceBox Preview** на месте — обычно движок
   поставляется с уже собранным APK в `Tools/IceBoxPreview` и собирает его сам
   (для этого нужен Android SDK, и это может занять несколько минут) только тогда,
   когда готового APK нет, — затем устанавливает или обновляет его на устройстве,
   переустанавливая с нуля, если не совпали подписи.
5. Принудительно останавливает предыдущий экземпляр, запускает компаньон с нужным
   портом и ждёт рукопожатия до 25 секунд.

Соединение поддерживается heartbeat-пакетами и корректно закрывается, если
устройство пропало. Кнопка
[Удалённого предпросмотра на панели инструментов](#46-кнопка-удалённого-предпросмотра)
запускает/останавливает тот же сервер и отражает состояние соединения.

## 13. Панели справки

### 13.1 Горячие клавиши

**Справка → Горячие клавиши** открывает справочник по сочетаниям клавиш со
вкладками. Вкладок пять:

* **Редактор** — файл (`Ctrl+S`, `Alt+F4`), правка (`Ctrl+Z/Y/R`, `Del`), выделение
  (`F`, `Ctrl+Клик`, рамка ЛКМ).
* **Режим игры** — `F5` пауза/возобновление, `F3` переключить игру, `F2` переключить
  свободную камеру (Извлечь), `Shift+F1` переключить курсор.
* **Вьюпорт** — гизмо (`Q/E/R`), камера (`ПКМ+WASD`, колесо, `Shift+Колесо`), мышь
  (ЛКМ выбор, ПКМ контекстное меню).
* **Редактор тайлмапа** — рисование/стирание/заливка/пипетка, регион/штамп,
  поворот тайла (`Q`/`E`, `Ctrl+Q`/`Ctrl+E`), размер тайла
  (`Shift+W/A/S/D`, `Shift+колесо`) и `Ctrl+S`
  (см. Редактор тайлмапов в [Ассетах](Assets-RU-DOC.md)).
* **Runtime (отладка)** — не сочетания клавиш, а **поверхность рантайм-API
  отладки**: оверлейные вызовы `PrintScreen` / `PrintScreenEx` /
  `RemoveScreenMessage` / `ClearScreenMessages` / `DrawWorldText`, помощники
  `GetDebug…` / `ToggleDebug…`, `IsDebugBuild`, вызовы трассировки профайлера
  (`StartProfilerTrace`, `StopProfilerTrace`, `SaveChromeTrace`), вся таблица
  `NetworkProfiler.*` и список просмотрщиков, которые открывают экспортированную
  Chrome-трассу. Это справка для скриптинга — см. [Lua API](LuaAPI-RU-DOC.md).

Полный список сочетаний воспроизведён в
[Разделе 15](#15-справочник-клавиатуры-и-мыши).

### 13.2 Документация

**Справка → Документация** открывает встроенный просмотрщик Markdown для этого самого
набора документации. Он предоставляет:

* Верхнюю панель с селектором **Язык:**, кнопкой **Обновить** (пересканирует дерево
  папок) и полем **Поиск:**. Просмотрщик считает языком **каждую подпапку
  `Documentation/`**, поэтому добавление папки добавляет язык, и заранее выбирает ту,
  что совпадает с текущим языком редактора.
* Поиск подсвечивает все совпадения, показывает счётчик `текущее / всего` и даёт
  стрелки вверх/вниз для перехода между совпадениями плюс `x` для очистки. Если
  ничего не найдено, так и сообщает.
* **Боковую панель** с двумя вкладками: **Документы** (список файлов с собственным
  полем фильтра) и **Содержание** (кликабельное содержание с отступами, построенное
  по заголовкам открытого документа, — клик прокручивает к нужному месту).
* Отрисованный Markdown — заголовки, абзацы, **жирный/курсив**, `инлайн-код`,
  блоки кода, цитаты, нумерованные и маркированные списки, таблицы, разделители и
  кликабельные ссылки — тем же набором шрифтов, что и остальной редактор.

> Любой `.md`-файл, который вы положите в `Documentation/RU` (как этот), появляется
> здесь автоматически. Если папка `Documentation` вообще не найдена, панель так и
> сообщит и предложит **Обновить**.

### 13.3 О программе

**Справка → О программе** открывает окно **О IceBox Engine**: имя студии, название и

## 14. Уровни, диалоги и скрипты

**Уровни.** Уровень — это файл `.icemap` (см. [Ассеты](Assets-RU-DOC.md#419-уровень-icemap)).
Заголовок Вьюпорта показывает открытый уровень и `*`, когда есть несохранённые
изменения. Сохранение записывает сущности, папки и мировые объёмы Иерархии,
Настройки мира и скрипт уровня в этот один файл. Отдельно редактор держит
**StartScene** в `.iceproject` указывающим на открытый уровень, поэтому запуск игры
стартует именно его.

Создание или открытие уровня очищает стеки отмены сцены и файлов, сбрасывает папки и
мировые ассеты Иерархии и Настройки мира, а также вызывает соответствующие
Python-события редактора (`scene_new`, `scene_loaded`, `scene_saved`) — см.
[Python API](PythonAPI-RU-DOC.md).

**Диалоги.**

| Диалог | Когда | Кнопки |
| ------ | ----- | ------ |
| **Новый уровень** | Файл → Новый уровень | Выбор папки + имя + предпросмотр пути (+ предупреждение «уже существует») → **Создать** / **Отмена**. `Enter` создаёт, `Esc` отменяет; **Создать** заблокирована при пустом имени или существующем пути. |
| **Открыть уровень** | Файл → Открыть уровень | Выбор `.icemap` → **Открыть** / **Отмена**. **Открыть** заблокирована, пока не выбран существующий файл; `Esc` отменяет. |
| **Несохранённые изменения** | Выход с «грязным» уровнем | **Сохранить** (сохранить и выйти) / **Не сохранять** (выйти) / **Отмена**. |

Двойной клик по `.icemap` в Браузере контента открывает уровень напрямую, без
диалога.

**Скрипт уровня.** **Файл → Редактор скриптов уровня** открывает редактор
собственного скрипта уровня — колбэков `OnLevelStart()`, `OnLevelUpdate(dt)` и
`OnLevelEnd()`. Он сохраняется внутри `.icemap`.

* В **кодовом проекте** это Lua-редактор с подсветкой синтаксиса, кнопкой
  **Сохранить**, кнопкой **Компилировать** с инлайновым значком `OK`/`Ошибка`
  (проблемная строка отмечается, а сообщение показывается подсказкой), индикатором
  позиции курсора и общими помощниками редактирования Lua (автодополнение и
  оверлеи). В его строке меню есть Файл → Сохранить уровень и Правка →
  Отменить/Повторить/Копировать/Вставить.
* В **проекте с визуальным скриптингом** — или когда в уровне уже сохранён граф —
  это же окно вместо текста содержит **граф Visual Script** с кнопками
  **Сохранить**, **Компилировать** и строкой статуса; при сохранении граф
  компилируется в Lua.
* Нажатие `Ctrl+S`, когда окно Скрипта уровня в фокусе **во время режима игры**,
  горячо перезагружает скрипт в запущенную игру, а не сохраняет уровень.

**Lua-скрипты.** Самостоятельный ассет `.lua` открывается в **Редакторе
Lua-скриптов** — это тот же редактор кода, что и в редакторе класса, только сам
по себе: **Сохранить** (`Ctrl+S`, когда окно в фокусе), **Компилировать** с
индикатором `OK`/`Ошибка` (строка с ошибкой помечается, текст показывается в
подсказке), позиция курсора и общие Lua-помощники — отмена/повтор, поиск и
замена, переход к строке, навигатор функций, шаблоны-сниппеты, автодополнение и
необязательная автокомпиляция. Каждый скрипт получает собственное докируемое
окно; закрытие с несохранёнными правками спрашивает Сохранить / Не сохранять /
Отмена. Создаются скрипты из браузера контента: **Прочее ▸ Создать Lua-скрипт**
(см. [Ассеты](Assets-RU-DOC.md)).

**Текстовые заметки.** Обычные заметки `.txt` открываются в небольшом встроенном
текстовом редакторе с заголовком `Текстовая заметка: <имя>`, где есть Файл → Сохранить
(`Ctrl+S`) и Правка → Отменить / Повторить / Копировать / Вырезать / Вставить /
Выбрать всё (см. [Ассеты](Assets-RU-DOC.md)).

## 16. FAQ и устранение проблем

**Моя раскладка панелей сломалась — как сбросить?**
Удалите `imgui.ini` рядом с редактором и перезапустите; раскладка по умолчанию
пересоберётся. Отдельные панели можно снова открыть из меню [Окно](#33-окно).

**Я закрыл Консоль / Иерархию / Свойства — куда они делись?**
Снова включите их из меню **Окно** (Консоль — это `Окно → Показать консоль`).

**Почему мои изменения исчезли после остановки режима игры?**
Режим игры работает со **снимком**; сцена восстанавливается в состояние до запуска,
когда вы нажимаете СТОП. Делайте правки в режиме редактирования или **Извлеките**
камеру во время игры, помня, что правки временны.

**`Ctrl+Z` отменил не то.**
Отмена следует за фокусом. Когда в фокусе Браузер контента, она отменяет последнюю
**файловую** операцию; когда редактор ассета — отменяет внутри него; иначе отменяет
последнее изменение **сцены**. Сначала кликните по нужной панели. В режиме игры
отмена полностью заблокирована.

**Изменения экземпляра класса сбрасываются при перезагрузке.**
Включите **Переопределить значения класса** для этой сущности в панели
[Свойства](#71-заголовок-сущности-и-переопределения-класса) или отредактируйте сам
класс, чтобы все экземпляры унаследовали изменение.

**Не могу найти кнопку «Добавить компонент».**
У сущности её нет — компоненты принадлежат **классу**. Откройте класс сущности
(двойной клик в Иерархии или **Редактировать класс** в контекстном меню вьюпорта),
добавьте компонент там, и все экземпляры его подхватят. См.
[7.2](#72-компоненты).

**Я отредактировал файл вне редактора, и ничего не произошло.**
Редактор следит за всей папкой `Content/` и перезагружает автоматически — проверьте
окно **Изменения файлов** и Консоль. Если файл лежит вне `Content/` или нужен
принудительный проход, используйте **Файл → Обновить все ассеты** (`Ctrl+R`). См.
[2.4](#24-живое-отслеживание-контента).

**Настройка в Настройках не сработала.**
Нажмите **Применить** (или **Применить всё**) — большинство настроек меняют
работающий редактор только при применении, — и учтите, что некоторым нужен
**перезапуск**: изменениям MSAA, значениям лимитов шейдеров на вкладке Оптимизация и
числу рабочих потоков физики. Используйте **Сохранить** / **Сохранить всё**, чтобы
настройки сохранялись.

**Этому уровню нужна другая гравитация/освещение, чем остальной игре.**
Используйте [Настройки мира](#8-настройки-мира), чтобы переопределить физику и/или
рендеринг только для этого уровня. Их можно подстраивать даже во время игры.

**Удалённый предпросмотр никак не подключается.**
Он слушает только localhost, поэтому устройство должно достучаться через
`adb reverse` — используйте **Развернуть на устройство**, эта кнопка всё настраивает,
устанавливает приложение-компаньон и запускает его. Помните также, что кадры
отправляются только **в режиме игры**, а на macOS функция недоступна. См.
[Раздел 12](#12-удалённый-предпросмотр).
