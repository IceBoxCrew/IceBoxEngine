## 1. Введение и модель ассетов

В IceBox Engine **ассет** — это любой переиспользуемый кусок игрового контента,
сохранённый в виде файла в папке `Content/` вашего проекта. Уровни ссылаются на ассеты,
ассеты ссылаются на другие ассеты, а движок подгружает их по требованию как во время
редактирования, так и во время выполнения (runtime).

Система ассетов построена на нескольких осознанных проектных решениях:

| Принцип | Что это значит на практике |
| ------- | -------------------------- |
| **Человекочитаемость** | Нативные ассеты движка — это обычный текстовый **JSON**. Они дают чистые diff'ы в системе контроля версий, их можно просматривать и править вручную. |
| **Ссылки по путям** | Ассеты ссылаются друг на друга по **относительному пути** (например, `Content/Sprites/Hero.ice_sprite`), нормализованному с прямыми слешами. |
| **Неразрушающий импорт** | Исходные файлы (`.png`, `.wav`, `.ttf`, `.mp4`) *никогда* не изменяются. Настройки импорта хранятся в отдельном файле-**сайдкаре** рядом с исходником. |
| **Безопасность при перемещении** | При переименовании или перемещении ассета браузер переписывает ссылки в зависимых ассетах и, при необходимости, создаёт **редиректор**, чтобы ничего не сломалось. |
| **Упаковка для релиза** | Россыпь файлов во время разработки; опциональный единый сжатый архив **IcePak** (`.icepak`) для релизных сборок — с идентичными загрузчиками во время выполнения. |

Две половины системы:

* **Файлы ассетов и сайдкары** — представление на диске (Разделы 2 и 4).
* **Браузер контента** — панель редактора, которая их создаёт, организует, импортирует и
  редактирует (Раздел 3).

У каждого типа ассета есть свой **редактор**, открывающийся по двойному клику.
Полный каталог по типам, включая то, какой редактор открывается для каждого, — в
[Разделе 4](#4-справочник-типов-ассетов) и
[сводной таблице](#71-расширения-типы-и-редакторы).

## 2. Как ассеты хранятся на диске

### 2.1 Ассеты на основе JSON

Все нативные ассеты движка (всё, что начинается с `.ice_`, плюс уровни `.icemap`)
сериализуются как **форматированный JSON** (отступ 4 пробела). Сохранение и загрузка идут
через общий сериализатор, который:

* пишет JSON по пути ассета;
* при загрузке сначала ищет файл на диске, затем обращается к смонтированному архиву
  **IceVFS**, затем разрешает путь через реестр **редиректоров** и, наконец, через
  платформенный слой ввода-вывода (так один и тот же код работает и для россыпи файлов, и
  для упакованных сборок, и для встроенных ассетов Android/Web).

Минимальный ассет выглядит как обычный JSON. Например, **флипбук** (`.ice_flipbook`) на
диске:

```json
{
    "DefaultFPS": 12.0,
    "Loop": true,
    "MaterialMode": 0,
    "OverrideShadingMode": 0,
    "OverrideBlendMode": 0,
    "OverrideAlphaClipThreshold": 0.5,
    "OverrideMaterialPath": "",
    "Frames": [
        { "SpritePath": "Content/Sprites/Run_0.ice_sprite", "Duration": 0.0833 },
        { "SpritePath": "Content/Sprites/Run_1.ice_sprite", "Duration": 0.0833 }
    ]
}
```

> **Обычно вы не правите это руками.** У каждого ассета есть специализированный редактор.
> Формат JSON описан здесь, чтобы вы понимали diff'ы в контроле версий и связи между
> ассетами.

### 2.2 Сайдкары (файлы-спутники)

Исходные медиа — изображения, аудио, шрифты и видео — **не** являются нативными ассетами
движка. Они сохраняют свой исходный формат нетронутым. Вместо этого движок хранит их
*настройки импорта* в **сайдкаре**: скрытом JSON-файле, который лежит рядом с исходником и
имеет то же базовое имя, но другое расширение.

| Исходный файл | Сайдкар | Что хранит |
| ------------- | ------- | ---------- |
| `T_Hero.png` | `T_Hero.ice_texture` | Фильтрацию, режим обёртывания, мипмапы, sRGB, макс. размер, формат пикселей, флаг атласа … |
| `S_Jump.wav` | `S_Jump.ice_sound` | Громкость, питч, группу, 3D-затухание, фильтры, реверберацию … |
| `F_Title.ttf` | `F_Title.ice_font` | Размер по умолчанию, сглаживание, диапазоны глифов, размер атласа … |
| `V_Intro.mp4` | `V_Intro.ice_video` | Ширину, высоту, FPS, длительность (считанные метаданные) |

Сайдкары **скрыты** в Браузере контента — вы никогда не увидите записей `.ice_texture` /
`.ice_sound` / `.ice_font` / `.ice_video`. Вместо этого вы видите исходный файл (например,
`.png`) и правите его настройки через соответствующую панель (Texture Settings, Sound
Settings, Font Editor, Video Player). Сайдкар создаётся автоматически при импорте
(Раздел [3.9](#39-импорт-внешних-файлов)) и всегда перемещается, копируется,
переименовывается и удаляется **вместе** со своим исходником
(Раздел [3.10](#310-перемещение-копирование-и-переименование-с-учётом-сайдкаров)).

> Сайдкары также служат входными данными для **подготовки (cooking)**: например, флаги
> `sRGB` и `MaxTextureSize` текстуры или объявленные диапазоны глифов шрифта определяют,
> что подготовщик (cooker) выдаст для релизной сборки. См.
> [Профайлинг и сборка игр](Profiling-And-Building-RU-DOC.md).

### 2.3 Ссылки на ассеты и редиректоры

Поскольку ассеты ссылаются друг на друга по **пути**, перемещение или переименование
ассета обычно сломало бы каждый ассет, который на него указывает. IceBox предотвращает это
системой **редиректоров (Asset Redirector)**.

Когда вы перемещаете или переименовываете ассет через Браузер контента, движок:

1. **Переписывает ссылки** во всех зависимых ассетах внутри `Content/`, чтобы они указывали
   на новый путь.
2. Если что-то всё ещё ссылалось на старый путь, создаёт **редиректор** — небольшой файл
   `.ice_redirect`, записанный в **`Saved/Redirectors/`**, который сопоставляет
   `СтарыйПуть → НовыйПуть`. Любая последующая загрузка по старому пути прозрачно
   разрешается в новый.
3. Сбрасывает кэши и просит менеджер ассетов обновиться.

Файлы редиректоров хранят исходный путь, новый путь и метку времени; имя файла — это
закодированный исходный путь, поэтому весь реестр помещается в одну плоскую папку.
Редиректоры лежат **вне** `Content/` намеренно: это метаданные проекта, а не контент, —
поэтому они никогда не появляются в браузере, не попадают в сборку и не мешают сканированию
ссылок.

Реестр загружается один раз и держится в памяти. При загрузке движок:

* **Удаляет устаревшие редиректоры** — если цель редиректора больше не существует, файл
  редиректора удаляется.
* **Мигрирует старые редиректоры** — любые файлы `.ice_redirect`, оставшиеся внутри
  `Content/` от прежних версий движка, автоматически переносятся в `Saved/Redirectors/`.

Цепочки редиректоров проходятся вплоть до предела безопасности (20 переходов). Вы можете
**исправить** редиректоры (свернуть цепочки, переписать файлы, которые всё ещё
указывают на старые пути, и удалить ненужное) из контекстного меню пустого пространства —
см. [Раздел 3.7](#37-создание-ассетов); в пункте меню показано текущее количество
редиректоров, и он недоступен, когда их нет. Движок также автоматически консолидирует
редиректоры непосредственно перед сборкой.

Подсистема редиректоров также обеспечивает работу **просмотрщика ссылок (Asset References)**
(Раздел [3.12](#312-просмотрщик-ссылок-asset-references)), который сканирует проект, чтобы
показать, что ссылается на ассет (входящие) и на что ссылается сам ассет (исходящие).

### 2.4 Виртуальная файловая система (IceVFS)

Во время выполнения игра может читать ассеты либо как **россыпь файлов** в `Content/`,
либо из одного или нескольких смонтированных архивов **IcePak** (`.icepak`). Слой
**IceVFS** делает оба варианта прозрачными:

* Паки монтируются **слоями**; более поздние монтирования перекрывают более ранние (так
  DLC- или патч-паки могут затенять базовый контент).
* Каждое чтение сначала пробует смонтированные паки, затем разрешает путь через реестр
  редиректоров, а затем откатывается к файлу-россыпи в платформенной файловой системе.

Именно поэтому *один и тот же* код загрузки ассетов работает и при запуске россыпью в
редакторе, и при поставке россыпью, и при поставке упакованного `Content.icepak`. Формат
IcePak и параметры упаковки описаны в
[Профайлинг и сборка игр](Profiling-And-Building-RU-DOC.md).

### 2.5 Внешние изменения и авто-обновление

Пока редактор открыт, он **следит за всей папкой `Content/`**, так что работать
исключительно через Браузер контента не обязательно. Отслеживаются все расширения ассетов —
все типы `.ice_*`, `.icemap`, изображения, аудио, шрифты, видео, `.lua` и `.txt`, — включая
вложенные папки.

Когда файл **создан** вне редактора (скопирован Проводником/Finder, создан внешним
инструментом, подтянут системой контроля версий), движок делает ту же работу с сайдкарами,
что и импортёр: недостающие `.ice_texture`, `.ice_sound`, `.ice_font` или `.ice_video`
создаются с настройками по умолчанию. Поэтому положить `.png` прямо в `Content/Textures/` —
вполне рабочий способ добавить графику.

Когда файл **создан, изменён или удалён**, редактор:

* обновляет менеджер ассетов, так что открытые редакторы, миниатюры и вьюпорт подхватывают
  новое содержимое;
* перезагружает все экземпляры классов в открытом уровне, так что изменённый класс
  обновляется на месте;
* перезагружает таблицы игровой локализации, если менялся `.ice_localization`;
* перечисляет изменения в небольшом окне уведомлений об **изменившихся файлах** (каждая
  запись держится несколько секунд; **Clear** очищает список).

Небольшая задержка после собственных записей редактора не даёт его же сохранениям вызвать
лавину перезагрузок. Учтите, что наблюдатель **не переписывает ссылки**: перемещение или
переименование ассетов вне редактора по-прежнему ломает связи, потому что пути никто не
переписывает и редиректор не создаётся. Реорганизуйте через Браузер контента
([3.10](#310-перемещение-копирование-и-переименование-с-учётом-сайдкаров)); файловую систему
используйте для *добавления* и *правки* файлов.

## 3. Браузер контента

**Браузер контента** (`Окно → Браузер контента`) — центральный хаб для всего контента
проекта. Его корень — папка `Content/` вашего проекта, и он работает только внутри неё.

### 3.1 Раскладка

Панель разделена на **верхнюю панель** и две колонки с изменяемым размером:

```
┌─────────────────────────────────────────────────────────────────┐
│ [Назад]  Текущий: Content/Sprites   [Поиск…] [X]  [+ Импорт]    │   ← Верхняя панель
├──────────────┬──────────────────────────────────────┬───────────┤
│ Дерево папок │           Область контента           │  Фильтры  │
│ ▸ Content    │   ▢ T_Hero   ▢ Hero.ice_sprite  …    │  ☐ Уровни │
│   ▸ Sprites  │   ▢ …        ▢ …                     │  ☐ Спрайты│
│   ▸ Audio    │                                      │  ☐ Аудио  │
│   …          │                                      │  …        │
└──────────────┴──────────────────────────────────────┴───────────┘
```

* **Левая колонка** — рекурсивное **дерево папок** с корнем `Content`.
* **Правая колонка** — **область контента** (сетка миниатюр текущей папки) плюс узкая
  **панель фильтров** вдоль её правого края.

### 3.2 Навигация и дерево папок

* **Дерево папок** отражает структуру каталогов внутри `Content/`. Клик по папке делает её
  текущей; дерево автоматически разворачивается, чтобы показать текущую папку.
* **Двойной клик по папке** в области контента входит в неё; **двойной клик по ассету**
  открывает его редактор (Раздел [3.8](#38-контекстное-меню-элемента) перечисляет редакторы
  по типам). Вход в папку также **очищает поле поиска**, так что вы всегда попадаете на
  реальное содержимое папки.
* Кнопка **Назад** на верхней панели (показывается, когда вы ниже корня) переходит в
  родительскую папку.
* Вы можете **перетаскивать элементы на папки** — в дереве или в области контента — чтобы
  переместить их
  (Раздел [3.10](#310-перемещение-копирование-и-переименование-с-учётом-сайдкаров)).
  Сброс на корень **Content** перемещает элементы на верхний уровень.
* Дерево запоминает, какие папки вы разворачивали, и автоматически разворачивает весь путь
  до текущей папки, когда вид куда-то «прыгает» (например, из
  [просмотрщика ссылок](#312-просмотрщик-ссылок-asset-references) или из скрипта).

### 3.3 Верхняя панель и поиск

| Элемент | Функция |
| ------- | ------- |
| **Назад** | Переход в родительскую папку (скрыта в корне). |
| **Текущий: …** | Показывает путь текущего каталога. |
| **Поиск…** | Живой, регистронезависимый фильтр по имени файла — см. ниже. |
| **X** | Очищает поле поиска (показывается, только когда в поле есть текст). |
| **+ Импорт** (зелёная) | Открывает нативный диалог выбора нескольких файлов для импорта внешних файлов в текущую папку — см. [Раздел 3.9](#39-импорт-внешних-файлов). |

**Поиск рекурсивный.** Как только вы что-то набрали, браузер перестаёт показывать только
текущую папку:

| Где вы находитесь | Что охватывает поиск |
| ----------------- | -------------------- |
| Корень **Content** | **Весь проект** — все папки, рекурсивно. |
| Любая **подпапка** | Эту папку **и всё, что внутри неё**. |

Совпадения из вложенных папок подписаны **путём относительно корня поиска**
(например, `Enemies/Boss/SP_Boss`), а не просто именем файла, — так всегда видно, где
результат лежит на самом деле. Очистите поиск (или войдите в папку двойным кликом), чтобы
вернуться к обычному списку одной папки.

### 3.4 Фильтры типов

Узкая **панель фильтров** справа от области контента позволяет показывать только
определённые категории ассетов. Каждый фильтр — цветовой переключатель; включение одного
или нескольких фильтров ограничивает вид этими типами (в сочетании с полем поиска).
Доступные фильтры:

`Уровни`, `Классы`, `Views`, `Cinema`, `Спрайты`, `Флипбуки`, `Анимации`, `Скелеты`,
`Тайлсеты`, `Тайлмапы`, `Материалы` (материал / экземпляр / функция / коллекция), `FX`,
`Виджеты`, `Текстуры`, `Аудио`, `Шрифты`, `Локализация`, `AI`, `Видео`, `Скрипты`, `Текст`.

Кнопка **Все** вверху панели снимает все фильтры разом; пока ни один фильтр не активен, она
подсвечена зелёным.

Как и поиск, **активный фильтр типов делает вид рекурсивным** — он собирает подходящие
ассеты из текущей папки и всего, что ниже (из всего проекта, когда вы в корне). Сами папки
при включённом фильтре скрыты, потому что результат — это плоский список ассетов, а не
список каталога.

Когда **ни один** фильтр не активен, показывается всё (сайдкары и файлы редиректоров
остаются скрытыми).

### 3.5 Миниатюры и живые превью

**Папки всегда идут первыми**, затем файлы, а область контента отрисовывает богатые
миниатюры с учётом типа:

* **Текстуры** показывают само изображение (с шахматным фоном под прозрачностью), уважая
  настройки фильтрации текстуры и её пропорции.
* **Спрайты** показывают только свою область `SourceRect` из текстуры, поверх шахматного
  фона, — так спрайт, вырезанный из листа, выглядит именно как спрайт, а не как весь лист.
* **Флипбуки** показывают первый кадр и **анимируются при наведении курсора**, с
  собственным покадровым таймингом. Уводите курсор — превью сбрасывается.
* У **аудио**-файлов в центре плитки есть **кнопка воспроизведения**: клик по ней
  прослушивает клип (с его настройками `.ice_sound`, принудительно без 3D и без
  зацикливания); во время проигрывания иконка превращается в «стоп», повторный клик
  останавливает. Одновременно играет только одно превью, и оно само останавливается в конце.
* **Видео**-файлы показывают декодированный **первый кадр** в рамке-киноленте.
* **Шрифты** отрисовываются вживую как образец `Aa` с настройками самого шрифта.
* **Тайлсеты** показывают исходную текстуру с наложенной **сеткой тайлов** (по размеру
  тайла из тайлсета) в оранжевой рамке.
* **Тайлмапы** рендерятся вживую — нарисованные слои плюс зелёная сетка ячеек
  (прореженная для очень больших карт).
* **Виджеты** рендерятся вживую как миниатюра холста: прямоугольники элементов, цвета,
  спрайты/флипбуки, текст, nine-slice, тогглы, чекбоксы и заливки прогресса/слайдера, —
  включая элементы, **унаследованные от родительского виджета**, и результат раскладки
  [Желаемого размера](#4131-общие-свойства-элементов).
* **FX**-ассеты показывают небольшое статичное превью частиц, собранное по модулям эмиттера.
* **Материалы и классы** рендерятся **вживую** в закадровые миниатюры специальными
  мини-рендерерами, так что миниатюра материала показывает реальный скомпилированный шейдер
  (с превью-светом), а миниатюра класса — собранную сущность.
* Всё, у чего превью нет (уровни, скрипты, заметки, AI, Cinema, View, экземпляры/функции/
  коллекции материалов, типы из плагинов), показывается цветной плиткой со **значком типа**.

Миниатюры и разобранные данные ассетов кэшируются. Кэш перепроверяет метки времени файлов
примерно дважды в секунду и пересобирает только изменившееся, а кэш текстур подрезается,
когда превышает бюджет, — поэтому папка с тысячами ассетов остаётся отзывчивой. Строки за
пределами экрана вообще пропускаются.

**Наведение** на ассет на полсекунды показывает подсказку с его типом
(например, `.ice_sprite (Sprite)`).

**Значки типов** ассетов (двухбуквенные сокращения, например `SP`, `MA`, `TM`) и цвета
типов помогают опознавать элементы с первого взгляда — см.
[сводную таблицу](#71-расширения-типы-и-редакторы).

### 3.6 Выбор элементов

| Действие | Результат |
| -------- | --------- |
| **Клик** | Выбрать один элемент. |
| **Ctrl + Клик** | Добавить/убрать элемент из выделения. |
| **Shift + Клик** | Выбрать диапазон от последнего кликнутого элемента. |
| **Ctrl + A** | Выбрать всё, что сейчас видно (с учётом поиска и фильтров). |
| **Протяжка по пустому месту** | **Рамка выделения** — выбирается всё, чего касается прямоугольник. Удерживайте **Ctrl**, чтобы добавить результат рамки к текущему выделению, а не заменить его. |
| **Клик по пустому месту** | Снять выделение (с `Ctrl` — сохраняется). |
| **Перетаскивание элемента** | Начать перемещение (или перетаскивание в сцену — см. [3.15](#315-перетаскивание-ассетов-в-сцену)). |

### 3.7 Создание ассетов

**Клик правой кнопкой по пустому пространству** в области контента открывает меню
*создания*. Новые ассеты создаются в текущей папке:

* **Новая папка**
* **(Типы из плагинов)** — здесь, в самом верху меню, появляется любой тип ассета,
  зарегистрированный установленным плагином. Плагин задаёт расширение, отображаемое имя,
  текст значка и цвет плитки, поэтому его ассеты выглядят и ведут себя в браузере как
  встроенные; см. [Плагины и моды](Plugins-And-Mods-RU-DOC.md).
* **Logic ▸**
  * **Создать Ice класс** (`.ice_class`) — переиспользуемый игровой объект с компонентами и скриптингом.
  * **Создать Синематику** (`.ice_cinema`) — таймлайн камеры/событий (кат-сцена).
  * **Создать AI мозг** (`.ice_ai`) — дерево поведения.
* **Graphics ▸**
  * **Создать спрайт** (`.ice_sprite`)
  * **Создать тайлсет** (`.ice_ts`)
  * **Создать тайлмап** (`.ice_tm`)
  * **Создать Флипбук** (`.ice_flipbook`)
  * **Создать Анимацию** (`.ice_animation`)
  * **Создать Скелет** (`.ice_skeleton`)
  * **Создать FX эффект** (`.ice_fx`)
  * **Создать Вид** (`.ice_view`)
* **Materials ▸**
  * **Создать Материал** (`.ice_material`)
  * **Создать Коллекцию параметров материалов** (`.ice_mpc`)
  * **Создать Материальную функцию** (`.ice_matfunc`)
  * **Создать экземпляр материала** (`.ice_matinst`)
  * **Создать декаль** (`.ice_decal`)
* **UI ▸**
  * **Создать Интерфейсный виджет** (`.ice_widget`)
  * **Создать Локализацию** (`.ice_localization`)
* **Other ▸**
  * **Создать Lua-скрипт** (`.lua`)
  * **Создать Текстовую заметку** (`.txt`)
* **Исправить редиректоры (n)** — свернуть и очистить реестр редиректоров. Число в
  подписи — это сколько редиректоров есть прямо сейчас; при `0` пункт недоступен.

Новые ассеты получают **префикс типа и уникальное имя по умолчанию** (`SP_NewSprite`,
`M_NewMaterial`, `CL_NewActor`, …), а при занятом имени — числовой суффикс; см.
[Раздел 7.4](#74-имена-по-умолчанию-для-новых-ассетов). Создание записывается в стек отмены
([3.13](#313-отмена-и-повтор-файловых-операций)).

> Некоторые типы ассетов также создаются **контекстно** из исходного файла — например,
> клик правой кнопкой по текстуре предлагает *Создать спрайт (.ice_sprite)* / *Создать тайлсет (.ice_ts)*. См.
> [Раздел 3.8](#38-контекстное-меню-элемента).

### 3.8 Контекстное меню элемента

**Клик правой кнопкой по элементу** даёт действия, зависящие от его типа. Полный набор:

| Действие | Доступно на | Эффект |
| -------- | ----------- | ------ |
| **Создать спрайт (.ice_sprite)** | текстурах | Создать `.ice_sprite` (`SP_<имя>`) из всего изображения. |
| **Создать тайлсет (.ice_ts)** | текстурах | Создать `.ice_ts` (`TS_<имя>`) из изображения, размер тайла 64. |
| **Нарезать спрайтлист…** | текстурах | Открыть [нарезчик спрайт-листов](#421-нарезчик-спрайт-листов-spritesheet-slicer), чтобы разрезать лист на спрайты. |
| **Импортировать таблицу спрайтов Aseprite** | файле Aseprite `.json` в проекте | Собрать спрайты/флипбук из данных Aseprite — см. [5.1](#51-импортёр-aseprite). |
| **Создать тайлмап (.ice_tm)** | тайлсетах | Создать `.ice_tm` (`TM_<имя>`), у которого этот тайлсет уже стоит в первом слое. |
| **Создать дочерний класс** | классах | Создать подкласс, наследующий родительский класс (и заготовку скрипта, вызывающую родителя). |
| **Создать дочерний виджет** | виджетах | Создать виджет, наследующий настройки холста и элементы родителя. |
| **Создать экземпляр материала (.ice_matinst)** | материалах | Создать `.ice_matinst` с родителем-материалом. |
| **Создать декаль (.ice_decal)** | текстурах | Создать `.ice_decal` (`DC_<имя>`), у которого это изображение уже стоит первым вариантом текстуры. |
| **Создать флипбук из спрайтов** | выбран один или несколько спрайтов | Собрать `.ice_flipbook` из выбранных спрайтов, упорядоченных по имени файла. |
| **Массовое редактирование (Property Matrix)** | 2+ ассетах одного вида | Открыть [Property Matrix](#314-массовое-редактирование--property-matrix). |
| **Переименовать** | одном элементе | Переименовать, перемещая сайдкар и исправляя ссылки. |
| **Copy / Cut / Paste** | любом | Операции с буфером обмена (`Ctrl+C` / `Ctrl+X` / `Ctrl+V`). |
| **Ссылки ассета** | одном файле | Открыть [просмотрщик ссылок](#312-просмотрщик-ссылок-asset-references). |
| **Мигрировать в...** | любом | Скопировать выделение **вместе с зависимостями** в другой проект — см. [3.16](#316-перенос-ассетов-в-другой-проект). |
| **Удалить** | любом | Удалить с проверками безопасности ссылок ([3.11](#311-удаление-ассетов-и-безопасность-ссылок)). |

Клик правой кнопкой по элементу, который **не** входит в текущее выделение, сначала
выделяет его, — так меню всегда действует на то, что подсвечено. Пункты, зависящие от типа,
показываются только для одного выбранного элемента; буфер обмена, перенос и удаление
работают со всем выделением.

### 3.9 Импорт внешних файлов

Есть два способа добавить внешние файлы:

1. **Перетащить** файлы из ОС в Браузер контента.
2. Кнопка **+ Импорт** на верхней панели (нативный выбор нескольких файлов).

**Куда попадёт сброшенный файл.** Пока вы тащите файлы над редактором, папка под курсором
подсвечивается — в дереве папок *или* в сетке контента — и именно туда файлы и попадут.
Сбросьте в любое другое место панели — и они попадут в **текущую** папку. Кнопка
**+ Импорт** всегда импортирует в текущую папку.

При импорте движок:

* **Автоматически добавляет префикс** к имени файла по типу медиа, чтобы контент оставался
  упорядоченным: `T_` для текстур, `S_` для аудио, `F_` для шрифтов, `V_` для видео
  (пропускается, если имя уже содержит префикс).
* **Автоматически создаёт сайдкар** с настройками по умолчанию: `.ice_texture` для
  изображений, `.ice_sound` для аудио, `.ice_font` для шрифтов, `.ice_video` для видео
  (последний прозванивается на ширину/высоту/FPS/длительность через FFmpeg, когда он
  доступен).
* Для файлов **`.gif`** запускает [импортёр GIF](#52-импортёр-gif) (создаёт флипбук из
  спрайтов) вместо простого копирования.
* Для файлов **`.json`**, являющихся экспортами **Aseprite**, запускает
  [импортёр Aseprite](#51-импортёр-aseprite) (автоматически находя соответствующий PNG).
  `.json`, который *не* является экспортом Aseprite, сообщается в Консоли и пропускается.
* Записывает импорт в стек отмены, так что ошибочный сброс отменяется одним `Ctrl+Z`.

**Если имя уже занято**, появляется **диалог конфликта файлов** с тремя вариантами:

| Выбор | Эффект |
| ----- | ------ |
| **Заменить** | Перезаписать существующий файл (перезаписываемая версия сначала кладётся в стек отмены, так что её можно вернуть). |
| **Пропустить** | Оставить существующий файл и пропустить этот. |
| **Оставить оба** | Импортировать под уникальным именем (`name_1`, `name_2`, …), вместе с сайдкарами. |

Отметьте **Применить ко всем конфликтам**, чтобы ответить один раз за всю пачку; иначе диалог появится
для каждого конфликтующего файла по очереди. Тот же диалог обрабатывает совпадения имён при
**перемещении** и **вставке** ассетов внутри проекта.

### 3.10 Перемещение, копирование и переименование (с учётом сайдкаров)

Все структурные операции учитывают сайдкары и ссылки:

* **Перемещение** (перетаскивание на папку или Cut + Paste) — перемещает ассет **вместе с
  его сайдкаром**, обновляет ссылки в зависимых ассетах и создаёт редиректор, если старый
  путь всё ещё был в использовании. Перемещение **папки** переписывает пути всего, что
  внутри неё, одной пачкой.
* **Копирование** (Copy + Paste) — дублирует ассет **вместе с его сайдкаром**; коллизии
  имён автоматически разрешаются уникальным суффиксом. Вставка в ту же папку, где элемент
  уже лежит, ничего не делает — чтобы получить дубликат, вставляйте в *другую* папку.
  Вырезанный буфер очищается после вставки, а скопированный сохраняется, так что его можно
  вставить в несколько папок.
* **Переименование** (`F2` или **Rename** в контекстном меню) — открывается небольшой
  диалог с уже подставленным именем и активным полем ввода; `Enter` подтверждает, `Esc`
  отменяет. Вы вводите **только базовое имя** — расширение сохраняется автоматически (у
  папок редактируется всё имя). Переименование также переименовывает сайдкар в соответствие,
  обновляет ссылки и (при необходимости) создаёт редиректор. Кэши/миниатюры по типу для
  переименованного ассета сбрасываются, чтобы превью обновились.

Редиректор создаётся **только если после переписывания ссылок что-то всё ещё указывает на
старый путь**, поэтому в аккуратном проекте их почти не накапливается.

Поскольку эти операции учитывают ссылки, вы можете свободно реорганизовывать папку
`Content/`, не ломая уровни или перекрёстные связи ассетов. Каждая из них отменяема
([3.13](#313-отмена-и-повтор-файловых-операций)), пока браузер в фокусе, а пачка
(перемещение множественного выделения, вставка нескольких файлов) отменяется **одним шагом**.

### 3.11 Удаление ассетов и безопасность ссылок

Удаление открывает диалог подтверждения, который сначала **сканирует весь проект на ссылки**
на всё, что вы собираетесь удалить.

**Если ссылок нет**, вы получаете зелёную пометку «удалять безопасно» и простое
подтверждение **Yes / Cancel** (`Enter` подтверждает, `Esc` отменяет).

**Если ссылки есть**, диалог перечисляет каждый ссылающийся ассет (с пометкой типа; при
наведении — полный путь), предупреждает, что эти ссылки сломаются, и предлагает
**Заменить ссылки на** — [выбор ассета](#общее-поведение-редакторов), ограниченный теми же
расширениями, что и у удаляемых ассетов. Далее ваши варианты:

| Выбор | Эффект |
| ----- | ------ |
| **Заменить и удалить** | Перенаправить все ссылки на ассет-замену, затем удалить. Появляется, когда выбрана корректная замена. |
| **Удалить принудительно** | Удалить в любом случае. Зависимые, указывавшие на него, не смогут разрешить путь (или откатятся к редиректору, если он есть). |
| **Cancel** | Прервать. |

Важные детали:

* Удаление **папки** собирает и удаляет все ассеты внутри неё (с теми же проверками).
* **Сайдкары** удаляются вместе со своими исходниками.
* Удаление **файла класса** также удаляет классы, наследующие от него, рекурсивно —
  дочерний класс не может существовать без родителя. Они собираются в момент выполнения
  удаления, **после** подтверждения, поэтому сам диалог перечисляет только то, что вы
  выделили. Если не уверены, сколько классов от него наследуется, сначала посмотрите
  [Asset References](#312-просмотрщик-ссылок-asset-references) у базового класса.
* Удаление записывается в стек отмены **вместе с содержимым файлов**, так что `Ctrl+Z`
  восстанавливает файлы (включая целые деревья папок и удалённые дочерние классы) и их
  сайдкары.

### 3.12 Просмотрщик ссылок (Asset References)

Действие **Asset References** (контекстное меню элемента, один файл) открывает диалог с
двумя списками:

* **Referenced by** (входящие) — каждый ассет, указывающий *на* этот ассет, с пометкой
  типа ссылающегося ассета.
* **References to** (исходящие) — каждый ассет, на который указывает *этот* ассет.

При наведении на строку показывается полный путь. **Двойной клик** по любой записи
переходит к этому ассету в браузере (вид переходит в его папку, разворачивает дерево и
выделяет его). Это самый быстрый способ понять зависимости ассета перед его перемещением
или удалением.

### 3.13 Отмена и повтор файловых операций

Браузер контента записывает структурные операции (создание, переименование, перемещение,
копирование, удаление, вставка, импорт, перезапись) в **стек отмены файловых операций**, так
что вы можете откатить случайную реорганизацию.

`Ctrl+Z` и `Ctrl+Y` (или `Ctrl+Shift+Z`) действуют именно на **этот** стек, пока
Браузер контента в фокусе, и на стек отмены **сцены** в остальных случаях, — поэтому отмена
перемещения файла никогда случайно не отменит перемещение сущности, и наоборот.

Отмена/повтор восстанавливает файлы (и их сайдкары, и целые деревья папок с содержимым) и
применяет заново либо откатывает связанные обновления ссылок. Операции, затронувшие сразу
много файлов, объединяются в **одну пачку** и отменяются вместе. Стек хранит последние
50 записей (никогда не разрывая пачку).

### 3.14 Массовое редактирование — Property Matrix

Выберите несколько ассетов **одного вида**, кликните правой кнопкой и выберите
**Массовое редактирование (Property Matrix)**, чтобы открыть панель **Property Matrix**.

Это не таблица — это **объединённый лист свойств**. Панель показывает один набор элементов
управления на всё выделение; изменение любого из них записывает значение **в каждый**
выбранный ассет. Там, где выбранные ассеты сейчас различаются, поле подсвечивается и
показывает `---` (у чекбоксов появляется пометка `(*)`), — так сразу видно, какие свойства
одинаковы, а какие нет.

| Элемент | Значение |
| ------- | -------- |
| **Выбранные ассеты** (сворачиваемый) | Список файлов, которые вы редактируете. |
| **Применить ко всем** | Записать текущие значения во все выбранные файлы. |
| **Откатить всё** | Перечитать с диска и отбросить незаписанные правки. |
| маркер несохранённого | Показывается, пока есть незаписанные изменения. |

У панели свои отмена/повтор (`Ctrl+Z` / `Ctrl+Y`, пока она в фокусе).

Поддерживаемые виды — панель сама подбирает нужный набор свойств и отказывается работать со
смешанным выделением:

| Вид | Что можно править массово |
| --- | ------------------------- |
| **Текстуры** | Весь сайдкар `.ice_texture`: фильтрация, обёртывание, мипмапы, sRGB, premultiply, макс. размер, анизотропия, LOD bias, формат пикселей, компрессия, атлас. |
| **Спрайты** | Точка опоры, режим материала + shading/blend/alpha clip, флаги столкновений, density/friction/restitution, события, one-way, группа и режим столкновений. |
| **Звуки** | Всё определение `.ice_sound`: воспроизведение, группа, приоритет, обрезка и фейды, рандомизация, 3D/затухание/конус и цепочка DSP. |
| **Флипбуки** | Default FPS, зацикливание, режим материала и переопределения shading/blend/alpha-clip. |
| **Тайлсеты** | Размер тайла, материал, общие атрибуты рендеринга и общие настройки физики/теней тайлов. |
| **Тайлмапы** | Настройки карты, чанкинг, показ координат и настройки воспроизведения анимированных тайлов. |
| **Классы** | Экземпляры компонентов по типам — коллайдеры, источники света и другие повторяющиеся экземпляры в выбранных классах. |
| **Виджеты** | Настройки холста (размер, желаемый размер, масштабирование под экран, режим растягивания, безопасная зона). |
| **FX** | Настройки эмиттеров во всех эмиттерах всех выбранных эффектов. |

Это идеально для крупных однотипных правок, которые были бы утомительны по одному ассету, —
например, перевести сотню пиксель-арт текстур на фильтрацию `Nearest` или задать всем звукам
шагов одну группу и затухание.

### 3.15 Перетаскивание ассетов в сцену

Перетащите ассет из области контента в **Viewport** или **Level Outliner**, чтобы
использовать его в уровне. Браузер помечает перетаскивание полезной нагрузкой, понятной
остальному редактору:

* **Классы** (`.ice_class`) используют отдельную полезную нагрузку, так что их сброс
  **инстанцирует класс** как новую сущность.
* Остальные ассеты используют общую полезную нагрузку, которую цель сброса интерпретирует
  по типу (например, сброс спрайта создаёт сущность-спрайт; сброс материала назначает его).

Ту же полезную нагрузку принимает **любой выбор ассета** в редакторе, так что спрайт можно
перетащить прямо из браузера на поле *Sprite* в панели Properties, в Class Editor, в Widget
Editor и так далее — поле принимает только те типы, которые разрешает.

Множественные выделения перетаскиваются группой (в превью перетаскивания видно, сколько
элементов).

### 3.16 Перенос ассетов в другой проект

**Мигрировать в...** (контекстное меню элемента) копирует выбранные ассеты — **вместе со всем,
от чего они зависят** — в другой проект IceBox, сохраняя структуру папок.

1. Выберите любое сочетание ассетов и папок и выберите **Мигрировать в...**. Папки
   разворачиваются в ассеты, которые в них лежат.
2. Диалог показывает результат двумя группами:
   * **Выбранные ассеты** — то, что вы выбрали.
   * **Зависимости** — всё, на что эти ассеты ссылаются, найденное сканированием проекта.
     Кнопки **Выбрать все** / **Снять все** включают или исключают группу зависимостей
     (сами выбранные ассеты остаются отмеченными).
3. Выберите **Целевой проект** в выпадающем списке — он заполняется проектами, известными
   Лаунчеру, за вычетом открытого — либо нажмите **Обзор...** и укажите любую папку проекта.
   (Выбор папки `Content` проекта понимается как выбор самого проекта.) Выбрать уже открытый
   проект нельзя.
4. Строки, которые уже существуют в целевом проекте, становятся **оранжевыми**, а
   предупреждение сообщает, сколько файлов будет перезаписано. Снимите с них галочки, если
   хотите сохранить версии из целевого проекта.
5. Нажмите **Мигрировать**. Каждый ассет копируется по *тому же пути относительно `Content/`* в
   целевом проекте (недостающие папки создаются), **вместе с сайдкарами**. Строка статуса
   сообщает, сколько скопировано и сколько не удалось.

Кнопка недоступна, пока не отмечен хотя бы один элемент и не выбрана цель. Операция только
**пишет в целевой проект** — в текущем ничего не меняется — и не входит в стек отмены,
поэтому перед подтверждением просмотрите список.

### 3.17 Справочник клавиш и мыши

Сочетания работают, пока Браузер контента в фокусе и не активен диалог или поле ввода.

| Ввод | Действие |
| ---- | -------- |
| `Ctrl + C` | Копировать выделение. |
| `Ctrl + X` | Вырезать выделение. |
| `Ctrl + V` | Вставить в текущую папку (перемещение после вырезания, дублирование после копирования). |
| `Ctrl + A` | Выбрать всё, что сейчас видно. |
| `Delete` | Удалить выделение (откроется диалог подтверждения). |
| `F2` | Переименовать выбранный элемент. |
| `Ctrl + Z` / `Ctrl + Y` (или `Ctrl + Shift + Z`) | Отменить / повторить последнюю файловую операцию — браузер должен быть в фокусе, иначе они отменяют правки сцены. |
| `Esc` | Закрыть открытый диалог. |
| `Enter` | Подтвердить диалог переименования / удаления. |
| Двойной клик | Войти в папку / открыть редактор ассета. |
| Клик + протяжка по пустому месту | Выделение рамкой. |
| `Ctrl` + рамка | Добавить к текущему выделению. |

## 4. Справочник типов ассетов

Этот раздел описывает каждый тип ассета: что это, его расширение на диске, его сайдкар
(если есть), редактор, который его открывает, и данные, которые он хранит. Имена полей
совпадают с ключами JSON, чтобы вы могли читать diff'ы в контроле версий.

> **Общие атрибуты материала.** Многие визуальные ассеты (спрайты, флипбуки, скелеты,
> тайлсеты) разделяют три атрибута рендеринга:
> * **Shading Mode** (режим затенения) — `Lit` (подвержен 2D-освещению и теням) или `Unlit`.
> * **Blend Mode** (режим смешивания) — `Masked` (с отсечением по альфе), `Additive`,
>   `Translucent` или `Opaque`.
> * **Alpha Clip Threshold** (порог отсечения альфы) — отсечка для смешивания `Masked`
>   (по умолчанию `0.5`).
> Они также поддерживают назначение **кастомного материала** вместо стандартного.

### Общее поведение редакторов

Каждый редактор ассета — обычная докируемая панель, и все они следуют одним правилам:

* **Одна панель на ассет.** Двойной клик по ассету открывает *его собственный* экземпляр
  панели, так что можно держать рядом три спрайта, два материала и тайлмап и разложить их
  по разным докам или вкладкам. Открытие уже открытого ассета просто **фокусирует**
  существующую панель. Закрытие панели закрывает только этот ассет.
* **Явное сохранение.** Редакторы работают с копией в памяти. Кнопка **Save** (и `Ctrl+S`
  там, где панель это поддерживает) пишет файл; пока есть незаписанные правки, в шапке
  показывается маркер **несохранённых изменений**. Сохранение обновляет менеджер ассетов,
  так что открытые уровни, миниатюры и работающие превью сразу подхватывают изменение.
* **Отмена/повтор на панель.** У каждого редактора своя история `Ctrl+Z` / `Ctrl+Y` по
  редактируемому ассету, независимая от сцены и от других редакторов.
* **Поля ассетов используют общий выбор ассета.** Везде, где один ассет ссылается на другой,
  используется один и тот же элемент: кнопка с текущим ассетом (и миниатюрой, где она есть),
  **X** для очистки и выпадающий список с **полем поиска**, где перечислены все подходящие
  ассеты проекта по имени и относительному пути. Список ограничен типами, которые допускает
  поле, и одновременно является **целью сброса** — ассет можно перетащить на него прямо из
  Браузера контента.
* **Живая обратная связь.** Редакторы, которые могут показывать превью, показывают его
  (воспроизведение флипбука, симуляция FX, анимация виджета, компиляция материала, поза
  скелета), а переименование или перемещение ассета при открытом редакторе перенацеливает
  панель, а не ломает её.

### 4.1 Исходные файлы и их сайдкары

Это сырые медиафайлы. Вы импортируете их, правите настройки в их **сайдкаре** и ссылаетесь
на них (напрямую или через спрайты/шрифты и т. п.). Исходный файл остаётся неизменным
байт-в-байт.

#### 4.1.1 Текстуры и сайдкар `.ice_texture`

**Исходник:** `.png`, `.jpg`, `.jpeg`  **Сайдкар:** `.ice_texture`  **Редактор:** Texture Settings

Сайдкар текстуры хранит настройки импорта для GPU:

| Настройка | Значения / примечания |
| --------- | --------------------- |
| **Min/Mag Filter** | `Nearest`, `Linear` и четыре комбинации с мипмапами. |
| **Wrap S / Wrap T** | `Repeat`, `ClampToEdge`, `MirroredRepeat`, `ClampToBorder`. |
| **Generate Mipmaps** | Построить цепочку мипмапов. |
| **sRGB** | Трактовать как цвет sRGB (в отличие от линейного). |
| **Premultiply Alpha** | Домножить RGB на альфу при загрузке. |
| **Max Texture Size** | Ограничить наибольшую сторону (`0` = размер исходника). Используется при подготовке. |
| **Anisotropic Level** | Уровень анизотропной фильтрации. |
| **LOD Bias** | Смещение выбора мипа. |
| **Border Color** | Цвет для `ClampToBorder`. |
| **Pixel Format** | `Auto`, `RGBA`, `RGB`, `RG`, `R`, `Grayscale`. |
| **Compression** | `Авто (с проверкой)`, `Без потерь (пиксель в пиксель)`, `Всегда сжимать`. Используется при подготовке. |
| **Use Atlas** | Разрешить упаковку этой текстуры в общую страницу атласа. |

Для пиксель-арта установите **Min/Mag = Nearest** и отключите мипмапы; для гладких
интерфейсных/фотографических текстур используйте **Linear** с мипмапами.

**Compression** определяет, что подготовщику разрешено делать с пикселями. В режиме `Авто`
кукер кодирует текстуру форматом, выбранным для сборки, декодирует результат обратно и
сравнивает с исходником; если разница была бы заметна (а именно это WebP с потерями и
блочные GPU-форматы делают с пиксель-артом с резкими краями), результат отбрасывается и
текстура сохраняется без потерь — так подготовленная сборка совпадает с неподготовленной
пиксель в пиксель. `Без потерь` вообще пропускает попытку сжатия с потерями,
`Всегда сжимать` оставляет формат сборки без проверки.

**Панель Texture Settings** разделена на живое превью и список настроек:

* **Превью** заново загружает текстуру при каждом изменении настройки, так что фильтрация,
  обёртывание, мипмапы, максимальный размер и формат пикселей показываются такими, какими
  будут на самом деле. **Колесо** — зум (к курсору), **средняя кнопка** — панорамирование;
  в подвале показаны исходное разрешение и текущий зум.
* Кнопки **R / G / B / A** над превью изолируют отдельные каналы — самый быстрый способ
  осмотреть альфа-маску или упакованную data-текстуру.
* Настройки сгруппированы в **Фильтрацию**, **Обёртывание**, **Мипмапы**, **Дополнительно**
  и **Атлас**; у каждого поля есть подсказка, а **Max Texture Size** — список пресетов
  (`Full`, 32 … 4096).
* **Save** пишет сайдкар (и перезагружает зависимые ассеты), **Reset** возвращает значения
  движка по умолчанию, а кнопка **Create Sprite** в углу создаёт `.ice_sprite` на всё
  изображение, не возвращаясь в браузер.

#### 4.1.2 Аудио и сайдкар `.ice_sound`

**Исходник:** `.wav`, `.mp3`, `.ogg`, `.flac`  **Сайдкар:** `.ice_sound`  **Редактор:** Sound Settings

Сайдкар звука — это полноценное определение микширования и DSP для одного клипа:

* **Воспроизведение** — Default Volume (громкость), Default Pitch (питч), Pan (−1 слева …
  +1 справа), Loop (зацикливание), **Group** (`Master`, `Music`, `SFX`, `Voice`,
  `Ambient`, `UI`), Priority (приоритет, 0–255).
* **Рандомизация** — Volume / Pitch / Pan Variation (±) для естественно звучащих
  повторов.
* **Обрезка и фейды** — Start Time, End Time, Fade In, Fade Out (в секундах).
* **3D / пространственный звук** — переключатель Spatial, Force Mono, **Attenuation Model**
  (`None`, `Inverse`, `Linear`, `Exponential`), Min/Max Distance, Rolloff,
  Doppler Factor и направленный **конус** (Inner/Outer angle, Outer volume).
* **Эффекты (DSP)** — Low-Pass фильтр, High-Pass фильтр, Lo-Shelf EQ, Hi-Shelf EQ,
  Delay/Echo (время, decay/обратная связь, wet, dry) и Reverb (decay, wet, room size,
  damping).

**Панель Sound Settings** начинается с блока **Превью**: кнопка Play/Stop, прогресс-бар,
следующий за позицией воспроизведения, и строка с **длительностью, частотой дискретизации и
числом каналов** клипа. Превью использует ваши текущие (ещё не сохранённые) настройки, так
что точки обрезки, фейды, питч и цепочку DSP можно прослушать до сохранения. Остальная часть
панели — сгруппированный список настроек: Воспроизведение, Группа, Рандомизация, Обрезка и
фейды, 3D и Эффекты, — а внизу **Save** и **Reset to Defaults**.

> В Браузере контента есть собственное превью в один клик прямо на плитке аудио
> ([3.5](#35-миниатюры-и-живые-превью)); оно всегда играет без 3D и без зацикливания, чтобы
> зацикленный эмбиент не «убежал».

#### 4.1.3 Шрифты и сайдкар `.ice_font`

**Исходник:** `.ttf`, `.otf`  **Сайдкар:** `.ice_font`  **Редактор:** Font Editor

Сайдкар шрифта (`FontSettings`) управляет генерацией атласа глифов:

| Настройка | Примечания |
| --------- | ---------- |
| **Default Size** | Размер в пикселях, под который запекается атлас (по умолчанию 24). |
| **Antialiased** | Сглаживание краёв глифов. |
| **Nearest Filter** | Чёткий/пиксельный рендеринг шрифта. |
| **Bold / Italic** | Флаги синтетического стиля. |
| **Char Range Start / End** | Диапазон кодпоинтов для запекания (по умолчанию `32`–`1103`, покрывает латиницу + кириллицу). |
| **Additional Ranges** | Дополнительные диапазоны кодпоинтов (например, блоки CJK, символы). |
| **Atlas Width / Height** | Размер текстуры атласа глифов (по умолчанию 1024×1024). |

Рендерер поддерживает **письмо справа налево** (арабский, иврит) и двунаправленный текст.
Объявленные диапазоны глифов также управляют **сабсеттингом (subsetting)** шрифта при
подготовке.

**Font Editor** показывает живое превью запечённого шрифта рядом с настройками:

* **Превью** — введите любой образец текста, отмасштабируйте его, поменяйте цвет или
  включите **Show Atlas**, чтобы посмотреть на саму текстуру атласа глифов (самый быстрый
  способ понять, что диапазоны в атлас не влезают).
* **Пресеты** — диапазоны символов в один клик: `ASCII`, `Extended`, `Cyrillic`, `Chinese`,
  `Japanese`, `Arabic`, `Hebrew`, `Hindi` и `All languages`. Они заполняют основной диапазон
  и дополнительные диапазоны за вас.
* **+ Добавить диапазон** добавляет пару «начало/конец» кодпоинтов для всего, чего нет в пресетах
  (символы, блоки эмодзи, области частного использования).
* **Loaded font info** сообщает, под какой размер шрифт реально запечён, высоту строки и
  ascender/descender.
* **Save Settings** пишет сайдкар; **Apply & Reload** перезапекает атлас, чтобы все виджеты
  и весь текст в редакторе сразу подхватили изменение.

> Большие диапазоны (особенно CJK) могут не поместиться в атлас 1024×1024 — увеличьте
> **Atlas Width/Height**, если глифы начинают пропадать.

#### 4.1.4 Видео и сайдкар `.ice_video`

**Исходник:** `.mp4`, `.avi`, `.mkv`, `.mov`, `.webm`  **Сайдкар:** `.ice_video`  **Редактор:** Video Player

Декодирование видео использует **FFmpeg**. При импорте движок прозванивает файл и пишет в
сайдкар **Width, Height, FPS** и **Duration**. Видео можно воспроизводить в игре как
полноэкранные ролики или как текстуры на поверхностях (управляется из скрипта).

**Панель Video Player** декодирует и проигрывает клип прямо в редакторе кнопкой
**Play/Pause** и показывает блок **Info** с разрешением, кадровой частотой и длительностью,
считанными из сайдкара. Браузер контента использует тот же декодер, чтобы взять **первый
кадр** для миниатюры плитки.

> Подготовка видео (перекодирование в VP9) выполняется на этапе сборки и ограничена по
> платформам — см. [Раздел 6](#6-подготовка-ассетов-cooking--обзор).

### 4.2 Спрайт (`.ice_sprite`)

**Редактор:** Sprite Editor

**Спрайт** оборачивает текстуру (или её подпрямоугольник) точкой опоры (pivot),
опциональным кастомным материалом, точками крепления и полигоном столкновений. Это
фундаментальная 2D-визуальная единица.

| Поле | Значение |
| ---- | -------- |
| `TexturePath` | Исходная текстура. |
| `PivotOffset` | Нормализованная точка опоры (по умолчанию центр `0.5, 0.5`). |
| `SourceRect` | Подпрямоугольник внутри текстуры (для листов). |
| `MaterialMode` | `Default` (материал движка) или `Custom` (`MaterialPath`). |
| `DefaultShadingMode` / `DefaultBlendMode` / `DefaultAlphaClipThreshold` | Атрибуты рендеринга по умолчанию (см. общее примечание выше). |
| `AttachPoints[]` | Именованные локальные якоря (имя, позиция, поворот) — например, *muzzle*, *hand* — для прикрепления эффектов или других сущностей. |
| `CollisionPolygon[]` | Выпуклый/замкнутый полигон для физики (до 32 точек). |
| Физика столкновений | `CollisionDensity`, `CollisionFriction`, `CollisionRestitution`, `CollisionIsSensor`, переключатели событий contact/sensor/hit/pre-solve, флаг односторонней платформы + направление, индекс группы столкновений и **режим столкновений** (`No Collision`, `Query Only`, `Physics Only`, `Query and Physics`). |

**Sprite Editor** — это превью слева и список свойств справа:

* **Превью** — показывает спрайт (область `SourceRect`, а не весь лист) с наложенными
  точкой опоры, точками крепления и полигоном столкновений. **Клик** в превью задаёт точку
  опоры, **колесо** — зум, **средняя кнопка** — панорамирование; в подвале показаны текущий
  зум и точка опоры. Если текстура не назначена, превью предлагает **перетащить текстуру**
  на него.
* **Точка опоры** — точное нормализованное значение плюс сетка 3×3 из **кнопок-пресетов**
  (от верх-лево до низ-право).
* **Source Rectangle** — `X / Y / Ширина / Высота` в пикселях, с кнопкой
  **Сбросить на всю текстуру**.
* **Материал** — `Default` или `Custom` (выбор ассета) плюс общие атрибуты shading / blend /
  alpha clip.
* **Точки крепления** — добавляйте, переименовывайте, задавайте позицию и поворот именованных
  сокетов; каждый показан в превью и его можно перетаскивать.
* **Столкновения** — переключатель оверлея, перетаскивание точек прямо в превью, ручное
  добавление/удаление точек, **Очистить коллизию**, либо кнопка **Генерировать коллизию**, которая обводит
  контур по альфа-каналу текстуры с порогом из ползунка **Alpha Threshold**. Ниже — значения
  физики (плотность, трение, упругость), флаги сенсора и односторонней платформы с
  направлением, переключатели событий contact/sensor/hit/pre-solve, группа столкновений и
  режим столкновений.
* Внизу — **Save** / **Revert** и маркер несохранённых изменений.

Точки крепления (сокеты) — это то, к чему привязывается система привязки к сокету.
У экземпляра Sprite или Flipbook — в **Class Editor** и в панели **Properties** —
задайте *Прикрепить к сокету*, и движок будет держать этот экземпляр приклеенным к
сокету каждый кадр, корректно с учётом поворота сущности, её масштаба и FlipX.
*Источник сокета* выбирает, какой компонент предоставляет сокет («Авто» ищет сначала
в скелете, затем в спрайтах, затем во флипбуках), *Индекс источника* сужает поиск до
одного экземпляра (`-1` — любой), а *Наследовать Flip X* зеркалит прикреплённую
графику вместе с владельцем. *Смещение от сокета* и *Доворот от сокета*
накладываются поверх сокета в его пространстве — можно подвинуть графику (или
анимировать отдачу из скрипта), не трогая сам сокет. Флипбук отдаёт сокеты
**текущего кадра**, поэтому привязка следует за анимацией покадрово. Из Lua то же
самое — `AttachSpriteToSocket` / `AttachFlipbookToSocket`.

#### 4.2.1 Нарезчик спрайт-листов (Spritesheet Slicer)

**Нарезать спрайтлист…** на текстуре (контекстное меню элемента) открывает **Spritesheet
Slicer** — отдельную панель, которая за один проход режет лист на множество `.ice_sprite`.
Каждый открытый лист получает свою панель нарезчика.

**Режимы нарезки**

| Режим | Как работает |
| ----- | ------------ |
| **Grid** | Регулярные ячейки: **Cell Width/Height**, **Offset X/Y** (пропустить поля) и **Padding X/Y** (зазор между ячейками). При открытии нарезчик подбирает размер ячейки, на который изображение делится нацело (64, 32, 16, 48 или 24). |
| **Auto** | Находит спрайты **заливкой по непрозрачным пикселям**. **Alpha Threshold** решает, что считать пустотой; **Min Width / Min Height** отбрасывают мусор. Результаты сортируются в порядке чтения (сверху вниз, слева направо) и перенумеровываются. |
| **Manual** | Рисуйте прямоугольники сами: **протяжка правой кнопкой** в превью добавляет новый. |

**Превью** — **колесо** для зума, **средняя кнопка** для панорамирования, плюс помощники
**Подогнать к окну**, **Сбросить масштаб** и **Квадрат**. Каждая нарезка обведена и пронумерована;
выбор в списке подсвечивает её.

Режимы Grid и Auto применяются кнопкой **Нарезать сетку** / **Автоопределение** — поменяли
настройку, нажали ещё раз, список пересобрался.

**Список нарезок** — каждый прямоугольник с чекбоксом. **Все / Ничего / Инвертировать**
управляют тем, что будет экспортировано; **Delete** удаляет прямоугольник; **Очистить всё**
очищает список.

**Имена и точка опоры** — **Базовое имя** и **Начальный индекс** дают `Name_0`, `Name_1`, …
(префикс `SP_` добавляется автоматически, если вы его не ввели), **Перенумеровать** заново
применяет нумерацию после правок, а **Пресет опоры** (9 позиций плюс **Custom**)
применяется ко всем генерируемым спрайтам.

**Вывод** — **Сгенерировать спрайты** пишет по одному `.ice_sprite` на каждую отмеченную нарезку
рядом с текстурой. Отметьте **Также создать флипбук** и задайте **FPS**, чтобы дополнительно
создать флипбук `FB_<BaseName>`, кадры которого — эти спрайты по порядку.

> **Повторная нарезка неразрушающая.** Если сгенерированный файл спрайта уже существует,
> нарезчик сначала загружает его и переписывает только **путь текстуры, `SourceRect` и точку
> опоры** — точки крепления, полигон коллизии, настройки столкновений и кастомный материал,
> которые вы настроили, сохраняются. Поэтому повторная нарезка листа после правок художника
> не выбрасывает вашу работу.

### 4.3 Флипбук (`.ice_flipbook`)

**Редактор:** Flipbook Editor

**Флипбук** — это покадровая анимация, собранная из последовательности спрайтов — самый
простой способ анимировать.

| Поле | Значение |
| ---- | -------- |
| `DefaultFPS` | Кадровая частота по умолчанию; `Duration` каждого кадра по умолчанию = `1/FPS`. |
| `Loop` | Зацикливать в конце. |
| `Frames[]` | Упорядоченный список `{ SpritePath, Duration }`. |
| `MaterialMode` + `Override…` | `From Sprites` (каждый кадр берёт материал и атрибуты рендеринга своего спрайта) или `Override` (одни shading/blend/alpha-clip/материал на весь флипбук). |

Быстро создать можно, выбрав несколько спрайтов и выбрав
**Создать флипбук из спрайтов**, либо из импорта GIF / Aseprite / спрайт-листа.

**Flipbook Editor** состоит из трёх частей:

* **Превью** — проигрывает анимацию кнопками **Play / Pause / Stop**, показывая номер
  текущего кадра. Опциональные оверлеи рисуют **точки крепления** и **полигон коллизии**
  текущего кадра, — так можно проверить, что сокет не «уезжает» по всей анимации.
* **Таймлайн** — все кадры лентой миниатюр. Клик выбирает, перетаскивание меняет порядок,
  **Добавить кадр** / **Удалить кадр** правят последовательность, а спрайты можно
  **перетаскивать из Браузера контента** и сбрасывать на слот `+` (множественное выделение
  добавляется по порядку).
* **Настройки** — `Default FPS` и `Loop`, **спрайт** выбранного кадра (выбор ассета) и его
  **длительность в секундах**, плюс **Set from FPS**, чтобы вывести длительность из кадровой
  частоты по умолчанию, и **Apply to All**, чтобы применить её ко всем кадрам разом. Ниже —
  блок режима материала с переключением между *From Sprites* и *Override*.

### 4.4 Анимация / Машина состояний (`.ice_animation`)

**Редактор:** Animation Editor

**Ассет анимации** — это **машина состояний (state machine)**, которая определяет, какой
флипбук воспроизводится, на основе параметров.

* **Параметры** — типизированные переменные, которые задаёт геймплей: `Bool`, `Int`,
  `Float`, `Trigger`.
* **Состояния (States)** — каждое воспроизводит `FlipbookPath` со `SpeedMultiplier`,
  опционально зацикленно, размещено на графе редактора.
* **Переходы (Transitions)** — направленные рёбра между состояниями с **условиями**
  (параметр сравнивается через `==`, `!=`, `>`, `<`, `>=`, `<=`), опциональной
  **длительностью бленда**, **Has Exit Time / Exit Time** (переход только после доли клипа)
  и **Priority** (приоритетом).
* **Переходы Any-State** — переходы, которые могут сработать из любого состояния (например,
  *получение урона* или *смерть*). Any-State-переходы никогда не используют exit time — они
  предназначены для прерывания.
* **Default State** — состояние, с которого начинает машина.

**Animation Editor** — это нодовый граф с инспектором:

* **Панель параметров** — добавляйте типизированные параметры (`Bool`, `Int`, `Float`,
  `Trigger`), переименовывайте их и задавайте значение, используемое для превью.
* **Граф** — **Добавить состояние** создаёт новую ноду; перетаскивайте ноды, чтобы разложить их
  (позиции сохраняются в ассете), тяните от одной ноды к другой, чтобы создать **переход**,
  колесо — зум. Состояние по умолчанию помечено; **Set as Default** назначает выбранное, а
  контекстное меню удаляет состояния и переходы.
* **Инспектор** — для **состояния**: имя, `Flipbook` (выбор ассета), множитель скорости и
  зацикливание. Для **перехода**: список условий (**Добавить условие** → параметр, оператор,
  значение), **Duration** (бленд), **Has Exit Time** + **Exit Time** и **Priority** —
  когда из состояния одновременно выполняются несколько переходов, побеждает наивысший
  приоритет.
* **Превью** — проигрывает флипбук выбранного состояния, чтобы проверить скорость и
  зацикливание, не выходя из панели.

### 4.5 Скелет (`.ice_skeleton`)

**Редактор:** Skeleton Editor

Полноценная система **2D-скелетной анимации** (кости, слоты, скины, меши, ограничения,
события и физика) — сопоставима с риггами в стиле Spine.

| Группа | Содержимое |
| ------ | ---------- |
| **Кости (Bones)** | Иерархия с позицией, поворотом, масштабом, сдвигом (shear), длиной и флагами наследования поворота/масштаба. |
| **Слоты (Slots)** | Слоты отрисовки, привязанные к кости, с цветом, режимом смешивания (`Normal`/`Additive`/`Multiply`/`Screen`) и текущим аттачментом. |
| **Аттачменты (Attachments)** | `Region` (текстурированный квад), `Mesh` (взвешенный деформируемый меш с вершинами/UV/треугольниками/весами), `Point` или `BoundingBox`. |
| **Скины (Skins)** | Именованные наборы переопределений слот→аттачмент (например, варианты костюмов). |
| **Анимации** | Таймлайны по цели: `Rotate`, `Translate`, `Scale`, `Shear`, `SlotColor`, `SlotAttachment`, `Deform`, `DrawOrder`, `IKMix`. Ключевые кадры поддерживают кривые `Linear`/`Stepped`/`Bezier`. Плюс **события** в определённые моменты времени. |
| **Ограничения (Constraints)** | **IK** (цель, mix, softness, изгиб, compress/stretch), **Transform** (миксы rotate/translate/scale/shear + смещения) и **Path** (следование по сплайну). |
| **Физические кости** | Физика на кость (форма с локальным смещением, плотность, трение, шарниры с лимитами/моторами). Управляет анимированными коллайдерами костей и рэгдоллом. |

Глобальные настройки включают скин по умолчанию, анимацию по умолчанию, пикселей на юнит и
общие атрибуты рендеринга.

**Skeleton Editor** — это вьюпорт с инспектором на вкладках:

* **Вьюпорт** — живая поза. Выбирайте и перетаскивайте кости, слоты и point-аттачменты;
  поза отражает текущее время анимации, поэтому вы видите ровно то, что даст рантайм.
* Вкладка **Bone** — иерархия костей (**Добавить кость**, смена родителя, удаление) с позицией,
  поворотом, масштабом, сдвигом, длиной и флагами наследования поворота / масштаба.
* Вкладка **Slot** — слоты отрисовки, привязанные к кости, с цветом, режимом смешивания,
  порядком отрисовки и аттачментом по умолчанию. **Добавить регион / меш / точку / бокс** создают аттачменты; **Преобразовать в меш** превращает region в редактируемый меш. Для мешей
  правятся позиции вершин, добавляются **веса** костей и есть **Normalize**; bounding box
  принимает произвольный список точек. **Скины** группируют переопределения
  слот→аттачмент — **Добавить скин** и **Сделать активным** переключают костюмы.
* Вкладка **Animation** — таймлайн. **Добавить анимацию**, задайте длительность, затем ставьте
  ключи по дорожкам `Rotate`, `Translate`, `Scale`, `Shear`, `Slot Color`,
  `Slot Attachment`, `Deform` и `Draw Order`; ключевые кадры поддерживают интерполяцию
  `Linear`, `Stepped` и `Bezier`. **Добавить событие** ставит именованное событие в момент времени,
  на который может реагировать геймплей. **Play / Pause / Stop** прокручивают анимацию во
  вьюпорте.
* Вкладка **Constraints** — **IK** (целевая кость, mix, softness, направление изгиба,
  compress / stretch), **Transform** (миксы rotate/translate/scale/shear плюс смещения) и
  **Path** (сплайн из точек со spacing, флагом замкнутости и позицией в процентах).
* Вкладка **Physics** — физика на кость: включение, форма с локальным смещением, шириной и
  масштабом длины, плотность, трение, упругость, тип шарнира с нижним/верхним **лимитом**,
  **моментом мотора**, **силой разрыва** и флагом самостолкновения. Это управляет
  анимированными коллайдерами костей и рэгдоллом.

`Point`-аттачменты — это **сокеты** скелета. Во вьюпорте Skeleton Editor они рисуются
ромбовидным маркером со стрелкой направления и именем аттачмента, в позиции по живой
позе кости своего слота. Кликом можно выбрать, перетаскиванием — переместить: drag
пишет обратно в локальный к кости `Offset` аттачмента, поэтому вы видите ровно то, что
в рантайме вернёт `GetSkeletonAttachPointWorld`. Так как позиции сокетов берутся из
живой позы, они следуют и за оверрайдами костей (`SetSkeletonBoneOverride`), и за
IK-констрейнтами, и за рэгдоллом.

### 4.6 Тайлсет (`.ice_ts`)

**Редактор:** Tileset Editor

**Тайлсет** нарезает текстуру на сетку тайлов и хранит данные по каждому тайлу,
используемые при рисовании тайлмапов.

* `TexturePath`, `TileSize`, опциональный кастомный материал + общие атрибуты рендеринга.
* Данные по тайлу **`TileData`** (по индексу тайла):
  * **Коллайдер** — вкл/выкл, **точки коллайдера** в режиме **Polygon** или **Chain**.
  * **Флаги** — sensor, destructible, one-way (с направлением).
  * **События** — переключатели contact / sensor / hit / pre-solve.
  * **Физический материал** — плотность, трение, упругость.
  * **Фильтрация** — индекс группы столкновений и режим столкновений (`No Collision`,
    `Query Only`, `Physics Only`, `Query and Physics`).
  * **Тени** — отбрасывание тени вкл/выкл, режим (`Contour` или `Colliders`), начало тени
    (`Top` / `Center` / `Bottom`), Z-порядок, затухание края и флаг «не блокировать тени».
  * **Фрагменты** (когда тайл разрушаемый) — количество фрагментов и **шаблон** разлома
    (`Grid`, `Radial`, `Random`), время жизни и время затухания, масштаб гравитации,
    плотность, трение, упругость, флаг сенсора, переключатели событий, группа столкновений и
    собственные настройки теней фрагментов.
  * Опциональное **имя/тег данных**, которое можно прочитать из скрипта, чтобы опознать тип
    тайла.

**Tileset Editor** показывает текстуру, нарезанную на сетку, слева и свойства выбранного
тайла справа:

* Задайте **Tile Size** — оверлей сетки обновляется вживую. Перетащите текстуру из
  Браузера контента, чтобы (пере)назначить её. Лист и превью коллайдера зумируются
  независимо.
* **Клик по тайлу** выбирает его, после чего коллайдер правится прямо на увеличенном превью
  тайла: перетаскивайте точки, **+ Добавить точку**, **- Удалить последнюю** или используйте
  **пресеты** — *Полный тайл*, *Верхняя половина*, *Нижняя половина* и четыре *Треугольник*
  по углам. **Пиксельная привязка** удерживает точки на пиксельной сетке.
* Остальные группы свойств соответствуют списку `TileData` выше; подсказки объясняют, когда
  настройка ни на что не влияет (тени нужен коллайдер, сенсор не даёт физического отклика,
  а chain-коллайдеры — это открытые линии, а не сплошные фигуры).

### 4.7 Тайлмап (`.ice_tm`)

**Редактор:** Tilemap Editor

**Тайлмап** — это многослойная сетка, рисуемая из одного или нескольких тайлсетов, с
поддержкой нескольких проекций.

| Возможность | Подробности |
| ----------- | ----------- |
| **Размеры** | `Width`, `Height`, `TileSize`. |
| **Проекция** | `Orthogonal`, `Isometric` или `Hexagonal` (с шириной/высотой ячейки, длиной стороны гекса, осью и индексом смещения). |
| **Слои** | Несколько `MapLayer` — каждый с именем, видимостью, блокировкой и сеткой тайлов. |
| **Тайлсеты** | Первичный тайлсет плюс до 127 дополнительных; ID тайлов кодируются с индексом тайлсета, так что одна карта может смешивать тайлсеты. |
| **Поворот тайлов** | Каждая закрашенная ячейка хранит шаг поворота рядом с ID тайла — 4 шага по 90° на ортогональных/изометрических картах и 6 шагов по 60° на гексагональных. Спрайт, коллайдер, источник тени, отпечаток в нав-сетке и осколки при разрушении поворачиваются вместе, поэтому один угловой тайл закрывает все ориентации. |
| **Размер тайла (растяжение)** | Поставленный тайл может занимать больше одной клетки. Блок растёт **вправо (`+X`)** и **вверх (`+Y`)** от своей опорной клетки, до `64 x 64` клеток, а графика тайла (статичная **или** флипбук) растягивается на весь блок. Коллайдер, источник 2D-тени, отпечаток в нав-сетке и осколки при разрушении масштабируются вместе с ним. Только для ортогональных карт. |
| **Анимированные тайлы** | Тайлы-плейсхолдеры, воспроизводящие флипбук, каждый с множителем скорости, собственными **покадровыми коллайдерами** и тем же полным набором настроек физики, событий, теней и разрушаемых фрагментов, что и у статичного тайла. |
| **Чанкинг** | Опциональное хранение по чанкам с настраиваемым размером чанка и флагами «пустоты» на чанк для быстрого отсечения больших карт. |
| **Show Coordinates** | Оверлей координат сетки в редакторе. |

**Tilemap Editor** — это холст с боковой панелью инструментов:

* **Рисование** — всё по активному слою, тайлом, выбранным в палитре:

  | Ввод | Инструмент |
  | ---- | ---------- |
  | **Протяжка ЛКМ** | Рисовать. |
  | **Протяжка ПКМ** | Стирать. |
  | **Alt + ЛКМ** | **Заливка** непрерывной области под курсором. |
  | **Alt + ПКМ** | **Пипетка** — взять тайл (или анимированный тайл) под курсором как активный. |
  | **Shift + протяжка ПКМ** | **Выделить прямоугольник** и запомнить его как **штамп**. |
  | **Shift + протяжка ЛКМ** | **Штамповать** запомненный блок с превью под курсором. |
  | **`Q` / `E`** | **Повернуть кисть** на шаг против часовой / по часовой стрелке. |
  | **`Ctrl+Q` / `Ctrl+E`** | **Повернуть уже стоящий под курсором тайл** на месте. |
  | **`Shift+D` / `Shift+A`** | **Растянуть / сжать тайл под курсором** на клетку **вправо**. |
  | **`Shift+W` / `Shift+S`** | **Растянуть / сжать тайл под курсором** на клетку **вверх**. |
  | **`Shift+колесо`** | Растянуть (вверх) / сжать (вниз) тайл под курсором сразу по **обеим** осям. |
  | **Средняя кнопка / колесо** | Панорамирование / зум холста. |

  Ячейка под курсором обведена и показывает полупрозрачный **призрак тайла, который будет
  поставлен**, уже с учётом поворота — так ориентацию можно подобрать до клика. У палитры
  есть собственный зум редактора.
* **Поворот тайла** — боковая панель показывает текущий поворот кисти в градусах и номер
  шага, рядом кнопки **против часовой / по часовой / сброс** и подсказки по `Q` / `E`.
  Поворот — свойство *поставленной ячейки*, а не тайлсета, поэтому один и тот же тайл может
  стоять на карте в разных ориентациях. Вместе с тайлом поворачивается всё, что ему
  принадлежит: спрайт (или кадр флипбука), полигон коллайдера, источник тени, отпечаток в
  нав-сетке и осколки, на которые он разлетается. Тайл с обычным коллайдером на всю клетку поворот не меняет, поэтому склейка
  боксов и чанкинг работают ровно как раньше. Пипетка также берёт поворот ячейки, с которой
  снимает тайл.
* **Размер тайла** — тайл не обязан быть одной клеткой. Боковая панель показывает текущий
  размер кисти (`Ш x В` и общее число клеток) с кнопками **Уже / Шире**, **Ниже / Выше**,
  **Меньше / Больше** и **Сброс** рядом с подсказками по `Shift+A/D/S/W` и `Shift+колесо`.
  Блок всегда растёт **вправо** и **вверх** от своей опорной клетки — той, куда вы рисовали, —
  поэтому клетка под кистью никуда не сдвигается. Нарисуйте кистью `2 x 1` — и получите тайл
  шириной в две клетки одним кликом; либо поставьте обычный тайл, наведите на него курсор и
  нажмите `Shift+D`, чтобы расширить уже стоящий. Текстура тайла (или кадр флипбука)
  **растягивается на весь блок**, поэтому куст, нарисованный шириной в два тайла, остаётся
  одним флипбуком, а не режется пополам. Уменьшение работает только на увеличенном тайле —
  обычный тайл `1 x 1` уже минимум. Растяжение поверх занятых клеток затирает их (`Ctrl+Z`
  отменяет), а у края карты просто останавливается. Вместе с блоком масштабируется всё, что
  тайлу принадлежит: коллайдер (обычные боксы по-прежнему склеиваются с соседями, а
  пользовательские полигоны и chain растягиваются на блок), источник 2D-тени, отпечаток в
  нав-сетке, столкновение частиц и осколки при разрушении — попадание в любую клетку
  разрушаемого блока уничтожает блок целиком. Стирание, заливка, штамп и пипетка на любой
  клетке блока работают с ним как с одним тайлом. Размер тайла хранится по ячейке в файле
  `.ice_tm` и работает **только на ортогональных** картах; на изометрических и гексагональных
  панель сообщает об этом, а сочетания клавиш ничего не делают.
* **Слои** — **+ Добавить слой**, **Переименовать**, **Удалить**, **Переместить вверх / вниз**, плюс переключатели
  видимости и блокировки на слой. Рисование всегда идёт в выбранный слой, заблокированные
  слои пропускаются.
* **Тайлсеты** — выпадающий список **Активный тайлсет** переключает палитру; перетащите
  `.ice_ts` из Браузера контента на палитру, чтобы добавить его в карту. Поскольку ID тайлов
  несут индекс тайлсета, одна карта свободно смешивает тайлсеты.
* **Настройки карты** — `Width`, `Height`, `Tile Size`, **Проекция** (`Orthogonal`,
  `Isometric`, `Hexagonal` с шириной/высотой ячейки, длиной стороны гекса, осью смещения
  `X`/`Y` и индексом смещения `Even`/`Odd`) и **Show Coordinates**.
* **Оптимизация** — **Enable Chunking** с **Chunk Size** и живой сводкой по чанкам. Для
  очень больших карт появляется предупреждение с предложением включить чанкинг.
* **Анимированные тайлы** — **+ Добавить анимированный тайл** создаёт плейсхолдер, который вы рисуете
  как обычный тайл; назначьте флипбук (перетащите его), задайте множитель скорости и
  правьте коллайдеры **по кадрам** (**+ Добавить коллайдер для кадра** / удалить, либо **Копировать на все
  кадры**, чтобы применить одну форму ко всей анимации). Доступны те же пресеты
  коллайдеров, физика, события, тени и настройки фрагментов, что и у статичного тайла.

### 4.8 Материал (`.ice_material`)

**Редактор:** Material Editor

**Материал** — это **шейдер на нодовом графе**. Вы строите внешний вид, соединяя ноды в
**Material Output**; граф компилируется в шейдер времени выполнения.

* **Shading Mode** (`Lit`/`Unlit`), **Blend Mode** (`Masked`/`Additive`/`Translucent`/
  `Opaque`), **Domain** (`Surface`, `PostProcess` или `Decal`) и **Alpha Clip Threshold**.
* **Ноды и связи** хранятся со стабильными ID и позициями в редакторе.

Палитра нод обширна. Меню **Добавить узел** делит её на девять подменю:

| Меню | Ноды |
| ---- | ---- |
| **Constants** | Float, Vector2, Color (RGB), Color (RGBA). |
| **Textures** | Texture Sample. |
| **Coordinates** | Texture Coordinates, Vertex Color, Camera Position, Panner, Rotator, Tiler. |
| **Math** | Add, Subtract, Multiply, Divide, Lerp, Clamp, One Minus, Power, Abs, Floor, Ceil, Frac, Sign, Step, SmoothStep, Min, Max, Sine, Cosine, Tangent, ATan2, Saturate, Fmod, Sqrt, Round, Remap, If. |
| **Vector Operations** | Dot Product, Distance, Length, Normalize, Append, Cross Product. |
| **Make / Break** | Make Float2/3/4, Break Float2/3/4, Component Mask. |
| **Utility** | Time, Desaturate, Fresnel, Simple Noise, Sphere Mask, Linear Gradient, Radial Gradient, World Position, Screen UV, Pixel Size, Scene Color, Custom Expression. |
| **Parameters** | Scalar Param, Vector Param, Texture Param, Collection Param. |
| **Functions** | Material Function Call. |

Внутри **функции материала** граф получает ещё два вида нод — **Function Input** и
**Function Output**, см. [4.10](#410-функция-материала-ice_matfunc).

Типы пинов: `Float`, `Vector2`, `Vector3`, `Vector4` и `Texture`. Значения преобразуются
автоматически при соединении пинов разной ширины (`Float`, поданный в `Vector3`,
размножается по компонентам, а `Vector4`, поданный во `Float`, берёт свой первый компонент).

#### 4.8.1 Справочник нод материала

Каждая нода палитры, её пины и то, что она вычисляет. **Вход** перечисляет входные пины (у
каждого — значение по умолчанию, используемое, когда пин не подключён), **Выход** —
выходные пины.

##### Material Output

Единственный корневой узел любого материала. Его нельзя удалить, и компилируется только то,
что до него дошло, — недостижимые ноды игнорируются.

| Вход | Тип | По умолчанию | Значение |
| ---- | --- | ------------ | -------- |
| **Base Color** | Vector3 | `1,1,1` | Альбедо. Если не подключён, берётся собственная текстура сущности, умноженная на это значение. |
| **Alpha** | Float | `1` | Непрозрачность. Если не подключён, берётся альфа текстуры сущности, умноженная на это значение. С ней же `Masked` сравнивает **Alpha Clip Threshold**. Игнорируется при Blend Mode `Opaque`. |
| **Emissive** | Vector3 | `0,0,0` | Самосвечение, добавляется после освещения — свет на него не влияет, зато оно питает bloom. |
| **Normal** | Vector3 | `0.5,0.5,1` | Карта нормалей в тангенциальном пространстве (кодировка `0..1`, распаковывается в `-1..1`). Только для `Lit`, игнорируется при `Additive`. |
| **Metallic** | Float | `0` | Только `Lit`. |
| **Roughness** | Float | `0.5` | Только `Lit`. |
| **Ambient Occlusion** | Float | `1` | Только `Lit`. |

| **Refraction** | Float | `0` | Подмешивает сцену за поверхностью, сэмплируя её по экранным UV со смещением, зависящим от этого значения. Читается только при Blend Mode `Translucent`, и подключение этого пина заставляет материал сэмплировать **Scene Color**. |

##### Custom Expression

Нода **Custom Expression** вставляет чистый GLSL в генерируемый шейдер. Это запасной выход для эффектов, которые нельзя
выразить палитрой нод — циклы, итеративная выборка, попиксельный raymarching, собственная фильтрация.

| Настройка | Значение |
| --- | --- |
| **Тип результата** | Тип GLSL выходного пина `Result` и переменной `output`: `float`, `vec2`, `vec3` или `vec4`. |
| **Число входов** | Сколько входных пинов у ноды, от `0` до `8`. В коде они называются `input0`, `input1`, ... |
| **input0..inputN** | Тип GLSL каждого входного пина. Значения из связей приводятся к этому типу автоматически. |
| **Код GLSL** | Сам блок инструкций, до 8191 символа. |

Внутри блока кода:

* каждый вход — локальная переменная `input0`, `input1`, ... того типа, который выбран для этого пина;
* переменная `output` уже объявлена с выбранным типом результата и обнулена;
* **присвойте результат переменной `output`**;
* блок имеет собственную область видимости, поэтому локальные переменные, циклы `for`/`while` и ветвления `if` разрешены
  и не конфликтуют с остальным сгенерированным шейдером;
* униформы материала доступны — `uTime`, `uCameraPosition`, `uScreenSize`, любой `uParam_<Имя>` из ноды Scalar или Vector
  Parameter, а также любой `uTexture<N>`, созданный нодой Texture Sample.

```glsl
// тип результата = float, 2 входа (vec2, float)
float acc = 0.0;
for (int i = 0; i < 16; i++) {
    vec2 p = input0 + vec2(float(i)) * 0.01;
    acc += texture(uTexture0, p).r;
}
output = acc / 16.0 * input1;
```

> **Старые ноды.** Код без идентификатора `output` по-прежнему трактуется как одно выражение, с необязательным ведущим
> `return`, ровно как раньше. Существующие материалы вида `return input0;` продолжают работать без изменений.

> Так как код вставляется дословно, синтаксическая ошибка GLSL проявится как ошибка компиляции материала с логом шейдера —
> смотрите баннер ошибки в редакторе материалов.

##### Parameters

| Нода | Вход | Выход | Что делает |
| ---- | ---- | ----- | ---------- |
| **Scalar Param** | — | `Value` (Float) | Именованное число, открытое для **экземпляров материала** и для `SetMaterialScalar` из скрипта. |
| **Vector Param** | — | `RGBA`, `RGB`, `R`, `G`, `B`, `A` | Именованный цвет/вектор, открытый так же. |
| **Texture Param** | `UV` (Vector2) | `RGB`, `R`, `G`, `B`, `A` | Именованный слот текстуры, который экземпляр может подменить. |
| **Collection Param** | — | `Value` (Float), `Vector` (Vector4) | Читает именованный параметр из [коллекции параметров материала](#411-коллекция-параметров-материала-ice_mpc) — одно глобальное значение, которое сразу подхватывают все читающие его материалы. Коллекция и имя параметра выбираются на ноде. |

**Имя**, которое вы дали ноде-параметру, — это ключ, по которому его находят экземпляры и
скрипты, поэтому переименование ломает переопределения, ссылавшиеся на старое имя.

##### Functions

| Нода | Вход | Выход | Что делает |
| ---- | ---- | ----- | ---------- |
| **Material Function Call** | (из функции) | (из функции) | Встраивает подграф `.ice_matfunc`. Пины берутся из объявлений Function Input / Function Output этой функции; после изменения сигнатуры нажмите **Reload Pins**. |
| **Function Input** *(внутри функций)* | — | `Value` | Объявляет один входной пин функции: имя, тип, **индекс** (порядок пинов на вызывающей ноде) и значение по умолчанию, если вызывающий оставил пин неподключённым. |
| **Function Output** *(внутри функций)* | `Value` | — | Объявляет один выходной пин функции. |

**Material Editor** — это граф плюс живое превью:

* **Граф** — клик правой кнопкой по пустому месту открывает меню **Добавить узел**
  (сгруппированное по категориям выше). Тяните между пинами, чтобы связать, перетаскивайте
  ноды, чтобы разложить, и выделяйте рамкой сразу несколько. Контекстное меню ноды даёт
  **Copy**, **Duplicate** и **Delete** (ноду *Material Output* удалить нельзя) и действует
  на всё выделение, если кликнуть внутри него.
* **Convert to Parameter / Convert to Constant** — превращает константную ноду в открытый
  параметр `Scalar`/`Vector` (чтобы экземпляры материала могли его переопределять) и
  обратно, сохраняя значение, позицию и все существующие связи.
* **Неподключённые входы** правятся прямо на месте: поле float, образец цвета или выбор
  текстуры прямо на ноде, — так что константная нода ради одного значения обычно не нужна.
* Ноды **Material Function Call** принимают ассет `.ice_matfunc`; **Reload Pins** заново
  считывает входы и выходы функции после изменения её сигнатуры.
* **Compile** собирает граф и сообщает **OK** либо ошибку шейдера; превью перекомпилируется
  автоматически по мере правок, а **Refresh** принудительно пересобирает.
* **Превью** — живой квад, отрисованный скомпилированным материалом. Когда материал `Lit`,
  доступен и превью-**свет**: цвет, интенсивность, радиус, спад и переключатель
  **прожектора** с углом, — так можно проверить реакцию материала на освещение, не помещая
  его в уровень.
* **Настройки** — Shading Mode, Blend Mode, Alpha Clip Threshold и **Domain**. Переключение
  домена в `PostProcess` превращает материал в тот, который можно подключить в стек
  кастомной пост-обработки [View](#414-view--объём-пост-обработки-ice_view), — панель об
  этом сообщает. Переключение в `Decal` делает материал назначаемым ассету
  [Декали](#421-декаль-ice_decal); материал декали использует те же пины Material Output,
  что и поверхностный, и дополнительно получает ноду **Данные декали**.

### 4.9 Экземпляр материала (`.ice_matinst`)

**Редактор:** Material Instance Editor

Лёгкое **переопределение** родительского материала — меняйте открытые параметры без
дублирования графа.

```json
{
    "Name": "MI_Hero_Red",
    "ParentMaterial": "Content/Materials/M_Character.ice_material",
    "AlphaClipOverride": 0.4,
    "ScalarOverrides": { "Roughness": 0.2 },
    "VectorOverrides": { "Tint": [1.0, 0.2, 0.2, 1.0] },
    "TextureOverrides": { "BaseColor": "Content/Textures/T_Hero_Red.png" }
}
```

Хранит путь к родителю плюс карты переопределений **scalar / vector / texture** и
опциональное переопределение alpha-clip.

**Material Instance Editor** начинается с выбора **родительского материала**. Как только
родитель задан, панель перечисляет его открытые параметры тремя группами — **Scalar**,
**Vector** и **Texture**, — показывая значение родителя, пока вы его не переопределили. Она
также показывает режимы затенения и смешивания, унаследованные от родителя (экземпляр никогда
не меняет граф, только его входы), и даёт единственное структурное переопределение, доступное
экземпляру, — **Alpha Clip Threshold**. Если родителя загрузить не удалось, панель сообщает
об этом, а не показывает молча пустой список.

### 4.10 Функция материала (`.ice_matfunc`)

**Редактор:** Material Function Editor

Переиспользуемый **подграф** с типизированными **Function Inputs** и **Function Outputs**.
Вызывайте его из любого материала через ноду **Material Function Call**, чтобы разделять
общую шейдерную логику (например, кастомный бленд или стилизацию). Хранится как ноды/связи
плюс объявления входов и выходов.

**Material Function Editor** — это тот же редактор графа, что и Material Editor, но без
настроек материала и с двумя дополнительными видами нод: **Function Input** (имя, тип, индекс
и значение по умолчанию, используемое, когда вызывающий оставил пин неподключённым) и
**Function Output**. **Индекс** входа определяет порядок пинов на вызывающей ноде — после его
изменения нажмите **Reload Pins** у вызывающих.

### 4.11 Коллекция параметров материала (`.ice_mpc`)

**Редактор:** MPC Editor

**Глобальный** набор именованных **скалярных** и **векторных** параметров, которые любой
материал может читать через ноду **Collection Parameter**. Установка значения один раз (из
скрипта или редактора) обновляет каждый материал, который его читает — идеально для
глобальных эффектов вроде времени суток, цвета команды или глобального фактора
«мокрости». Каждый параметр хранит значение по умолчанию и текущее значение; коллекцию
можно сбросить к значениям по умолчанию.

**MPC Editor** намеренно небольшой: **имя коллекции**, кнопки **Add Scalar** и
**Add Vector** и два списка параметров. Каждая строка — имя плюс значение, и именно по имени
материалы находят параметр: переименование ломает ноды **Collection Parameter**, ссылавшиеся
на старое имя, поэтому сначала проверьте
[Asset References](#312-просмотрщик-ссылок-asset-references).

### 4.12 FX / Система частиц (`.ice_fx`)

**Редактор:** FX Editor

Мощная **система частиц**. FX-ассет содержит один или несколько **эмиттеров**, у каждого —
стеки модулей **Spawn**, **Initialize** и **Update** плюс модуль **Render** — стековая
архитектура, сопоставимая с современными нодовыми/стековыми VFX-системами.

**Настройки эмиттера:** длительность, зацикливание, максимум частиц, задержка старта, время
прогрева, стадии симуляции, симуляция на **CPU или GPU** и собственный **трансформ**
эмиттера (позиция, поворот, масштаб), чтобы один эффект мог собирать несколько смещённых
эмиттеров.

**Модули** (каждый можно включать/выключать) по категориям:

| Категория | Модули |
| --------- | ------ |
| **Spawn** | Spawn Rate, Spawn Burst, Spawn Shape (Point/Circle/Box/Edge/Ring), Spawn Per Unit (по дистанции). |
| **Initialize** | Initial Lifetime, Velocity, Size, Color, Rotation. |
| **Update — движение** | Velocity Over Life, Gravity, Drag, Acceleration, Orbit, Noise, Attractor, Curl Noise, Vortex Force, Wind Force, Spring Force. |
| **Update — внешний вид** | Size Over Life, Color Over Life, Rotation Over Life, Opacity Over Life, Sub-UV Over Life, Stretch Over Life, Size/Color By Speed, Scale By Density. |
| **Update — взаимодействие** | Collision (None/Destroy/Bounce/Slide), Particle Collision, Kill Condition (box/sphere/speed), Event Handler (спавн FX на collision/death/spawn), Conditional Module, Sub-FX (спавн другого FX), Custom Script. |
| **Особые** | **Light** (частицы излучают 2D-свет), **Fluid** (симуляция жидкости SPH с рендерингом метаболами или частицами, опциональная двусторонняя связь с физическими телами). |
| **Render** | Sprite Renderer (спрайт/материал, режим смешивания, анимация суб-изображений) или Ribbon Renderer (шлейфы). |

Кривые (`FXCurve`) и градиенты (`FXGradient`) управляют свойствами «по жизни» с
редактируемыми ключевыми кадрами и пресетами (Linear, EaseIn/Out/InOut, Bell, FadeIn/Out…).

**FX Editor** состоит из четырёх областей:

* **Эмиттеры** — список эмиттеров с **+ Добавить эмиттер** / **Remove**; выбор эмиттера определяет
  всё остальное. У каждой строки есть имя и **чекбокс включения**, так что эмиттер можно
  заглушить, не удаляя. У каждого свой блок настроек (длительность, зацикливание, максимум
  частиц, задержка старта, прогрев, стадии симуляции, CPU/GPU) и свой трансформ.
* **Стек модулей** — четыре списка друг под другом: **Spawn**, **Initialize**, **Update** и
  **Render**, у каждого кнопка `+`, меню которой предлагает только модули, допустимые для
  этой стадии. У каждой строки есть чекбокс включения, кнопка `X` для удаления, и её можно
  **перетаскиванием менять местами** внутри своего стека (порядок важен — модули Update
  выполняются сверху вниз). Клик правой кнопкой по модулю даёт **Копировать настройки /
  Вставить настройки** — так настроенный модуль переносится между эмиттерами или между
  эффектами.
* **Свойства модуля** — параметры выбранного модуля, каждый с подсказкой и, где применимо, с
  редактируемой **кривой** или **градиентом** и пресетами формы. Сверху — короткое описание,
  что модуль делает.
* **Превью** — эффект симулируется вживую кнопками **Play / Pause / Restart** и
  **Refresh Preview**; каждая правка применяется сразу, а *Restart* очищает существующие
  частицы, чтобы честно оценить стартовый залп.

Что стоит знать:

* **Бессмертные частицы** — *Initial Lifetime* можно перевести в режим immortal; именно им
  пользуются жидкости и постоянные шлейфы, и тогда реальным ограничением становится
  максимум частиц эмиттера.
* **Симуляция на GPU** задаётся на эмиттер. Модуль **Fluid** всегда считается на CPU;
  режим GPU при этом по-прежнему действует на всё остальное в этом эмиттере.
* **Sub-FX** спавнит другой `.ice_fx` со своим смещением, поворотом, масштабом, задержкой
  старта и таймингом — так собираются многослойные взрывы без одного гигантского эмиттера.

#### 4.12.1 Настройки эмиттера

У каждого эмиттера в списке свой блок настроек, независимый от его модулей.

| Настройка | Значение |
| --------- | -------- |
| **Name** | Подпись в списке эмиттеров. |
| **Enabled** | Заглушить эмиттер, не удаляя его. |
| **Duration** | Длительность одного цикла эмиттера в секундах (по умолчанию `5`). |
| **Looping** | Перезапускать цикл по истечении длительности (по умолчанию включено). |
| **Max Particles** | Жёсткий предел живых частиц этого эмиттера (по умолчанию `1000`). Для бессмертных частиц именно он становится реальным ограничением. |
| **Start Delay** | Секунды до начала спавна. |
| **Warmup Time** | Пред-симулирует эффект на эту длительность при создании, чтобы на первом же кадре он выглядел уже работающим. |
| **Simulation Stages** | Число под-шагов обновления за кадр; больше — точнее и дороже. |
| **Simulation Mode** | `CPU` (многопоточное обновление) или `GPU` (обновление на вычислительном шейдере). |
| **Emitter Transform** | Смещение позиции, смещение поворота и множитель масштаба — позволяет одному эффекту собирать несколько смещённых эмиттеров. |

#### 4.12.2 Справочник модулей FX

Все модули, сгруппированные по стеку, которому они принадлежат. Модули включаются по
отдельности, а модули **Update** выполняются сверху вниз в порядке их следования в стеке.

##### Spawn

| Модуль | Параметры |
| ------ | --------- |
| **Spawn Rate** | **Spawn Rate** — частиц в секунду (непрерывный спавн). |
| **Spawn Burst** | **Burst Time** — время эмиттера, в которое срабатывает залп; **Burst Count** — частиц за один залп; **Cycle Time** — период повтора залпа (`0` — один раз). |
| **Spawn Shape** | **Shape** — `Point`, `Circle`, `Box`, `Edge`, `Ring`; **Radius** (круг/кольцо); **Inner Radius** (кольцо — частицы спавнятся между внутренним и внешним радиусом); **Size** (бокс/грань); **Spawn On Edge** — спавнить только по контуру, не заполняя площадь; **Random Direction (Radial Velocity)** — запускать частицы наружу от центра фигуры вместо настройки скорости. |
| **Spawn Per Unit** | Спавн по пройденному эмиттером пути. **Distance Per Spawn** — сколько пикселей должен пройти эмиттер до следующей партии; **Particles Per Spawn** — частиц за партию. |

##### Initialize

| Модуль | Параметры |
| ------ | --------- |
| **Initial Lifetime** | **Immortal** — частицы не умирают (ограничивайте их модулем Kill Condition; на этом строятся жидкости и фоновые эффекты); иначе **Min Lifetime** / **Max Lifetime** в секундах. |
| **Initial Velocity** | **Velocity Min** / **Velocity Max** (диапазон по осям); **Local Space** — трактовать скорость в локальном пространстве эмиттера, чтобы она поворачивалась вместе с ним; **Inherit Emitter Velocity** + **Inherit Scale** — передавать новым частицам долю собственного движения эмиттера (выхлопы, шлейфы, искры снарядов). |
| **Initial Size** | **Uniform Size** — одно значение на обе оси; далее **Size Min** / **Size Max** либо **Size Min XY** / **Size Max XY** при неравномерном размере. |
| **Initial Color** | **Color Min**; **Random Color** — выбирать стартовый цвет случайно между **Color Min** и **Color Max**. |
| **Initial Rotation** | **Rotation Min** / **Rotation Max** в градусах; **Align To Velocity** — разворачивать частицу по направлению движения. |

##### Update — движение и силы

| Модуль | Параметры |
| ------ | --------- |
| **Velocity Over Life** | **Velocity Multiplier** — кривая масштабирования скорости по жизни частицы. |
| **Gravity** | **Gravity** — постоянный вектор ускорения (по умолчанию тянет вниз). |
| **Drag** | **Drag Coefficient** — сопротивление среды; замедляет частицы пропорционально скорости. |
| **Acceleration** | **Acceleration** — постоянный вектор, добавляемый каждый кадр. |
| **Orbit** | **Orbit Speed** (град/с) и **Orbit Radius** — частицы вращаются вокруг эмиттера. |
| **Noise** | **Noise Strength** — турбулентность, расталкивающая частицы; **Noise Frequency** — пространственный масштаб (меньше — крупнее завихрения). |
| **Curl Noise** | Бездивергентная турбулентность — дым, магия, завихрения огня. **Strength**; **Frequency** (меньше — крупнее завихрения); **Animation Speed**; **Octaves** (слои детализации); **Lacunarity** (шаг частоты между октавами); **Persistence** (спад амплитуды между октавами). |
| **Attractor** | **Attractor Position**; **Strength** (положительное притягивает, отрицательное отталкивает); **Attractor Radius** — радиус влияния; **Attractor Falloff** — как сила слабеет с расстоянием; **Relative To Emitter** — размещать относительно эмиттера, а не в мировых координатах. |
| **Vortex Force** | Вращательная сила вокруг точки — торнадо, порталы, водовороты. **Center**; **Tangential Strength** (положительное — против часовой стрелки); **Radius**; **Falloff**; **Inward Pull** (положительное втягивает, отрицательное выталкивает); **Relative To Emitter**. |
| **Wind Force** | **Direction**; **Strength**; **Turbulence Amount** и **Turbulence Frequency** (случайное поперечное смещение); **Gust Strength** и **Gust Frequency** (эпизодические порывы); **Wind Drag** — насколько сильно частицы подтягиваются к скорости ветра. |
| **Spring Force** | Тянет частицы обратно к точке спавна — желе, мягкие тела, упругие эффекты. **Stiffness** (сила возврата); **Damping** (потеря скорости на колебаниях). |

##### Update — внешний вид

| Модуль | Параметры |
| ------ | --------- |
| **Size Over Life** | **Size Multiplier** — кривая масштабирования размера по жизни частицы. |
| **Color Over Life** | **Color Gradient** — градиент, сэмплируемый по возрасту частицы. |
| **Rotation Over Life** | **Speed Min** / **Speed Max** в градусах в секунду. |
| **Opacity Over Life** | **Opacity** — кривая множителя альфы по жизни частицы. |
| **Stretch Over Life** | Кривые **Stretch X** и **Stretch Y** (множитель размера по осям) плюс **Velocity Stretch** — растягивает частицу вдоль X пропорционально её скорости. |
| **SubUV Over Life** | Привязывает кадр спрайт-листа к возрасту частицы (`0..1`), так что лист проигрывается ровно один раз за жизнь. Задайте **Sub-Images H/V** в Sprite Renderer. |
| **Size By Speed** | **Size At Rest**; **Size At Max Speed**; **Speed Range** — скорость, при которой достигается максимальный множитель. |
| **Color By Speed** | **Speed Gradient** — цвет по скорости; **Speed Range** — скорость, соответствующая правому краю градиента. |
| **Scale By Density** | Масштабирует размер частицы по локальной SPH-плотности — требует модуль **Fluid**. **Size At Low Density**; **Size At High Density**. |

##### Update — взаимодействие и логика

| Модуль | Параметры |
| ------ | --------- |
| **Collision** | **Collision Response** — `None (Pass Through)`, `Destroy`, `Bounce`, `Slide`; **Bounce Factor** (только отскок); **Friction** (только скольжение); **Radius Scale** — радиус столкновения относительно визуального размера; **Destroy On Second Hit**; **Ignore Sensors** — пропускать коллайдеры-триггеры; **Sensor Overlap Events** — сообщать в Lua о перекрытии с сенсорами через `OnFXSensorOverlap` (зоны урона, проверки «в воде») без какой-либо физической реакции. |
| **Particle Collision** | Частицы сталкиваются друг с другом — шарики, бусины, мрамор. **Collision Radius**; **Bounce**; **Repulsion Force** — дополнительное расталкивание, предотвращающее слипание. |
| **Kill Condition** | **Condition Type** — `Box Zone`, `Sphere Zone`, `Speed Min`, `Speed Max`; **Mode** — `Kill Inside`, `Kill Outside`, `Contain (Bounce Back)`; **Zone Center**; **Zone Size** (бокс) или **Zone Radius** (сфера); **Speed Threshold** (условия по скорости); **Relative To Emitter**. |
| **Event Handler** | **Trigger** — `On Spawn`, `On Collision`, `On Death`; **FX-ассет** для спавна; **Spawn Count**; **Inherit Velocity** + **Velocity Scale**. |
| **Conditional** | Логика If/Else на каждую частицу. **Check Value** — `Speed`, `Age`, `Size`, `Alpha`, `Density (Fluid)`; **Comparison** — `>`, `<`, `=`; **Threshold**; затем **Action** и **Value** для ветки TRUE и для ветки FALSE. Действия: `Do Nothing`, `Multiply Alpha`, `Multiply Size`, `Multiply Velocity`, `Kill Particle`. |
| **Sub FX** | Присоединяет другой `.ice_fx` как дочерний эффект, следующий за этим эмиттером. **FX Asset**; **Position Offset**; **Scale**; **Rotation**; **Start Delay**. |
| **Custom Script** | Фрагмент на Lua, выполняемый для каждой частицы каждый кадр; может читать и менять поля частицы. |

##### Update — особые

| Модуль | Параметры |
| ------ | --------- |
| **Light** | Каждая частица излучает точечный свет. **Light Color**; **Light Intensity**; **Light Radius**; **Light Falloff** (`1` — линейный, `2` — квадратичный); **Inherit Particle Color** — использовать собственный цвет частицы; **Cast Shadows** — разрешить этим огонькам отбрасывать 2D-тени (дорого при большом числе частиц). |
| **Fluid** | SPH-симуляция жидкости между частицами эмиттера. Разбита на шесть блоков — см. таблицу ниже. |

**Параметры модуля Fluid**

| Блок | Параметры |
| ---- | --------- |
| **SPH Core** | **Rest Density** — целевая плотность (меньше — жидкость более разрежена); **Stiffness (Pressure)** — насколько сильно частицы расталкиваются выше плотности покоя; **Near Stiffness** — ближнее давление, не дающее частицам схлопываться друг в друга, ключ к «жидкому» виду; **Viscosity** — сглаживание скоростей между соседями (мало — вода, много — мёд); **Surface Tension** — сцепление, минимизирующее площадь поверхности; **Interaction Radius** — радиус поиска соседей, оптимально ~2–4 размера частицы; **Particle Mass**. |
| **Stability & Control** | **Velocity Damping** за кадр (`1.0` — без затухания); **Max Speed** — предотвращает численный «взрыв»; **Collision Damping** — дополнительная потеря скорости при ударе о коллайдер; **Sub-Steps** за кадр (обычно достаточно 2–3); **Allow Sleep** — прекращать симуляцию устоявшегося водоёма и возобновлять её при возмущении (большая экономия CPU; автоматически отключается при наличии силового модуля), а вместе с ним **Sleep Speed** — скорость, ниже которой должны быть все частицы, чтобы жидкость уснула (`0` отключает сон). |
| **Water / Pool Settings** | **Pre-Fill Area** — мгновенно заполнить фигуру спавна на первом кадре (используйте со Spawn Shape типа Box/Circle); **Pre-Fill Count**. |
| **Render Mode** | **Fluid Render** — `Particles` (отдельные спрайты) или `Metaball (Surface)` (гладкая слитая поверхность); **Surface Threshold** — порог плотности на краю (меньше — гуще жидкость); **Blob Scale** — вклад плотности каждой частицы (больше — глаже, но размытее). |
| **Physics Interaction** | **Affect Rigid Bodies** — двусторонняя связь, чтобы объекты всплывали, тонули и уносились потоком; **Push Scale** — сколько импульса передаётся телам (`0` — жидкость реагирует на тела, но никогда их не двигает); **Body Drag** — вязкое сопротивление телам, движущимся сквозь жидкость. Требует модуль Collision и динамический Rigidbody. |
| **Fluid-To-Fluid** | **Interact With Other Fluids** — расталкиваться с частицами других эмиттеров жидкости, у которых это тоже включено, чтобы вода и лава не проходили друг сквозь друга; более лёгкая жидкость (с меньшей Particle Mass) всплывает наверх. **Separation** — сила расталкивания; **Mixing Drag** — насколько сильно жидкости увлекают друг друга. |

> Подсказки в панели: добавьте модуль **Collision**, чтобы жидкость взаимодействовала с
> коллайдерами, и модуль **Gravity**, чтобы она падала и собиралась в лужи.

##### Render

У эмиттера ровно один модуль рендера — либо спрайтовый, либо ленточный.

| Модуль | Параметры |
| ------ | --------- |
| **Sprite Renderer** | **Sprite Path** — `.ice_sprite`, отрисовываемый на каждую частицу; **Use Custom Material** + **Material Path** (`.ice_material` / `.ice_matinst`, домен `Surface`); **Blend Mode** — `Alpha`, `Additive` (свечение), `Multiply`; **Sub-Images H** / **Sub-Images V** — сетка спрайт-листа; **Animate Sprite** + **Animation Speed** (FPS) — проигрывать лист как анимацию; **Shading Mode** — `Unlit` или `Lit` (реагирует на свет сцены). Назначенный кастомный материал забирает на себя смешивание и затенение. |
| **Ribbon Renderer** | Рисует шлейфы за частицами. **Sprite Path**; **Texture Mode** — `Stretch`, `Tile`, `Distance Based`; **Use Custom Material** + **Material Path**; **Blend Mode**; **Ribbon Width**; **Max Segments** — число точек в шлейфе; **Min Vertex Distance** — расстояние до добавления новой точки (сглаживает шлейф); кривая **Width Over Life**; градиент **Color Over Life**. |

##### Кривые и градиенты

Любой параметр *Over Life* — это редактируемая **кривая** (`FXCurve`) или **градиент**
(`FXGradient`). В обоих редакторах ключи можно двигать, добавлять и удалять, и у обоих есть
пресеты в один клик: у кривых — `Linear`, `Constant`, `Ease In`, `Ease Out`, `Ease In/Out` и
`Bell`; у градиентов — `Solid White`, `Fade Out`, `Fade In` и `Fade In/Out`.

### 4.13 Виджет / UI (`.ice_widget`)

**Редактор:** Widget Editor

**Виджет** — это документ интерфейса: холст из UI-**элементов** с раскладкой, стилизацией,
анимацией и обработчиками событий. Это строительный блок для меню, HUD и диалогов.

Всего **19 типов элементов**, в пяти категориях: `Panel`, `Text`, `Button` и `Image`
(*Common*); `InputField`, `Slider`, `Checkbox`, `Toggle` и `Dropdown` (*Input*);
`ProgressBar` и `Throbber` (*Display*); `HorizontalBox`, `VerticalBox`, `SizeBox`,
`Overlay` и `ScrollView` (*Layout*); `Spacer`, `WidgetSwitcher` и `SubWidget` (*Misc*).
Каждый описан в [4.13.2](#4132-справочник-типов-элементов).

У каждого элемента один и тот же базовый набор свойств — трансформ и якоря,
необязательная подгонка размера под содержимое, глубина и пост-обработка, внешний вид,
подсказка, обрезка потомков, nine-slice, навигация геймпадом и колбэки взаимодействия —
плюс настройки холста на уровне документа. Все они разобраны по полям в
[4.13.1](#4131-общие-свойства-элементов).

**Widget Editor** — это иерархия, холст и инспектор:

* **Иерархия** — дерево элементов с **полем поиска**, кнопкой **Добавить элемент**
  (сгруппировано в *Common*, *Input*, *Display*, *Layout* и *Misc*), меню «добавить
  потомка» на элементе, **перемещением вверх/вниз** между соседями, **Move to Root**,
  копированием/вставкой и **Reparent** с обнаружением циклов. Элементы, унаследованные от
  родительского виджета, помечены.
* **Холст** — виджет в реальных пропорциях. Клик выбирает, перетаскивание двигает, а восемь
  **маркеров изменения размера** (четыре угла, четыре стороны) масштабируют. Переключатель
  **Сетка** привязывает перемещение и изменение размера; **средняя кнопка** панорамирует,
  **колесо** зумит. Виджет якорей в инспекторе показывает 9 пресетов плюс варианты
  растягивания.
* **Панель анимации** — включается с панели инструментов и пристыковывается под холстом.
  **Добавить дорожку** выбирает элемент (или корень виджета) и свойство — позиция X/Y, ширина/
  высота, поворот, масштаб X/Y, непрозрачность, цвет R/G/B/A, — затем **Добавить ключевой кадр**
  ставит ключ на позиции плейхеда с **easing** (`Linear`, `EaseIn`, `EaseOut`, `EaseInOut`,
  `Bounce`, `Elastic`). У анимаций есть длительность, флаги **loop** и **autoplay**, и они
  могут нести **события** по времени, вызывающие функцию скрипта с параметром.
  **Play / Stop** и кнопка сброса проигрывают анимацию прямо на холсте.
* **Вкладка Script** — либо текстовый редактор **Lua**, либо нодовый граф **Visual Script**,
  на выбор для каждого виджета, с кнопкой **Compile**, которая проверяет граф и показывает
  ошибку тут же.

> Колбэки событий ссылаются на имена функций скрипта; сам Lua API описан в
> [LuaAPI-RU-DOC.md](LuaAPI-RU-DOC.md).

#### 4.13.1 Общие свойства элементов

Эти группы инспектор показывает для **любого** элемента, именно в таком порядке. Группы,
специфичные для типа ([4.13.2](#4132-справочник-типов-элементов)), вставляются там, где они
применимы.

**Трансформ**

| Свойство | Значение |
| -------- | -------- |
| **Name** | Имя элемента — по нему же скрипты его находят. Уникально в пределах виджета. |
| **Position** | Смещение от якоря в пикселях холста. |
| **Size** | Ширина и высота. Только для чтения (и задаётся содержимым), пока включён **Desired Size**. |
| **Desired Size** | По умолчанию выключено. Пока включено, элемент сам подгоняет размер под содержимое вместо фиксированного: измеренный текст, пиксельный размер спрайта/флипбука, холст саб-виджета, диаметр тробера, границы потомков или поток горизонтального/вертикального бокса (spacing + padding), — а поле **Size** показывает актуальное вычисленное значение. |
| **Scale** | Множитель по X/Y, применяемый вокруг точки опоры. |
| **Pivot** | Нормализованная точка опоры для поворота и масштаба (по умолчанию `0.5, 0.5`). |
| **Rotation** | Градусы. |
| **Opacity** | `0..1`, умножается вниз по потомкам. |
| **Anchor** | Один из 9 угловых/краевых пресетов плюс 7 растягивающих вариантов (`StretchLeft/Center/Right`, `StretchTop/Middle/Bottom`, `StretchAll`). Выбор оставляет элемент на месте и лишь пересчитывает `Position`; **Shift + клик** вместо этого переносит его в `Position = 0,0` выбранного якоря. Растягивающие якоря заполняют прямоугольник родителя по своей оси, а `Scale` затем увеличивает или уменьшает этот прямоугольник вокруг точки опоры. |
| **Custom Anchors** | Свободные диапазоны **Anchor Min** / **Anchor Max** (`0..1`) вместо пресета, чтобы каждый край следил за родителем независимо. |
| **Z Order** | Порядок отрисовки внутри этого виджета. |
| **Global Z** | Сортировать элемент по Z относительно *сцены*, а не внутри UI-оверлея. Отрицательный Z Order с включённым Global Z превращает элемент в фон сцены. |
| **Post Processed** | Рисовать элемент внутри сцены, чтобы на него действовали bloom, экспозиция, глубина резкости и прочее. Выключено (по умолчанию) — элемент рисуется чётким оверлеем после пост-обработки. Для фона с Global Z включено принудительно и недоступно для правки. |
| **Visible** | Скрыть элемент (и его потомков), не удаляя. |

**Внешний вид**

| Свойство | Значение |
| -------- | -------- |
| **Color** | Оттенок (RGBA). Для Panel/Image это заливка; для спрайта — множитель. |
| **Lighting** | `Unlit` или `Lit` — участвует ли элемент в динамическом 2D-освещении и системе теней. Доступно у Image, Button, Throbber, Panel, ProgressBar, Slider, Checkbox, Dropdown, ScrollView, Text, InputField и Toggle. |
| **Shadow Receiver** | (только `Lit`) разрешить динамическим теням падать на этот элемент — как в мировых, так и в экранных виджетах. |
| **Sprite** | `.ice_sprite` **или** `.ice_flipbook` в качестве визуала элемента. Доступно у Image, Button, Throbber, InputField, Checkbox, Toggle и Dropdown. Назначение флипбука очищает спрайт и наоборот. |

**Подсказка** *(все элементы)*

| Свойство | Значение |
| -------- | -------- |
| **Tooltip Text** | Текст, показываемый при наведении на элемент во время игры. |
| **Tooltip Delay** | Секунды удержания курсора до появления подсказки. |
| **Font** / **Font Size** | Появляются, когда задан текст подсказки, — для типов элементов без собственного текстового блока. |

**Обрезка** *(все элементы)* — **Clip Children** обрезает потомков по прямоугольнику этого элемента.

**9-Slice** — у Panel, Button, Image, ScrollView, Slider, ProgressBar, InputField, Checkbox,
Toggle и Dropdown. **Use 9-Slice** растягивает спрайт, сохраняя размер углов; **Border
(L,T,R,B)** задаёт ширину границ в пикселях исходной текстуры.

**Навигация геймпадом** *(интерактивные элементы)* — **Nav Up / Down / Left / Right**
указывают на другой элемент либо на `Auto`, чтобы движок сам выбрал ближайшего соседа в этом
направлении.

**Взаимодействие**

| Свойство | Значение |
| -------- | -------- |
| **Interactable** | Разрешить элементу принимать наведение, клики и фокус. Всё нижеследующее появляется только при включённом флаге. |
| **OnClick / OnHover / OnUnhover / OnPressed / OnReleased** | Имена Lua-функций, вызываемых на этих событиях. |
| **OnValueChanged** | Только у Slider, InputField, Checkbox, Dropdown и Toggle. |
| **OnFocusGained / OnFocusLost** | Вызываются при получении и потере фокуса ввода. |
| **State Colors** | **Use Custom State Colors** заменяет встроенные оттенки наведения/нажатия на **Hovered Color** и **Pressed Color**. |
| **State Sounds** | **Use Custom State Sounds** проигрывает **Hovered Sound** и **Pressed Sound** при взаимодействии. |

**Настройки уровня документа** (самого виджета, а не элемента)

| Настройка | Значение |
| --------- | -------- |
| **Canvas Size** | Расчётное разрешение виджета. Только для чтения при включённом **Desired Size**, который заставляет холст обтягивать корневые элементы. |
| **Scale With Screen** | Масштабировать весь виджет вместе с окном вместо работы в чистых пикселях. |
| **Stretch Mode** | `Stretch`, `Letterbox`, `MatchWidth`, `MatchHeight`. |
| **Safe Area** + **Insets (L,T,R,B)** | Держать содержимое вне вырезов и скруглённых углов экрана. |
| **Parent Widget** | Наследовать настройки холста и элементы другого виджета. **Reparent** меняет родителя с обнаружением циклов; унаследованные элементы помечены в иерархии, и их можно переопределять по каждому полю. |
| **Is Element** | Помечает документ как переиспользуемый блок, предназначенный для встраивания через `SubWidget`, а не для показа сам по себе. Только виджеты с этим флагом можно выбрать в элементе SubWidget. |
| **Script** | Текстовый Lua-скрипт или граф Visual Script, на выбор для каждого виджета. |
| **Animations** | См. **панель анимации** выше. |

### 4.14 View / Объём пост-обработки (`.ice_view`)

**Редактор:** View Editor

**View** определяет **объём пост-обработки** и/или **объём навигационной сетки** с
границами, радиусом бленда и приоритетом — как объём камеры/пост-обработки, в который
вливается активная камера.

Стек пост-обработки обширен:

* **Bloom** (интенсивность, порог, радиус) и **Bloom Dirt**.
* **Color Grading** (насыщенность, контраст, гамма, тинт) и **LUT**.
* **Tonemap** (`None`/`Reinhard`/`ACES`) и **Auto Exposure** (компенсация, min/max,
  скорости).
* **Vignette**, **Film Grain**, **Chromatic Aberration**.
* **Ambient Occlusion (SSAO)**, **Screen-Space Reflections (SSR)**.
* **Godrays**, **Lens Flare**, **Lens Sharpen**, **CAS** (контрастно-адаптивная резкость).
* **Depth of Field**, **Motion Blur**.
* **Global Illumination** (radiance cascades), процедурное **Sky** (небо).
* **Fog** (Linear/Exp/Exp²) и **Volumetric Fog**.
* **Heat Haze** и **Underwater** (тинт, искажение, каустики).
* **Кастомные материалы пост-обработки** (материалы с `Domain = PostProcess`), у каждого —
  сила, переключатель включения и размещение **до/после** встроенного стека. Добавляются и
  удаляются в списке внизу панели.

Настройки **навигационной сетки** задают, как в этом объёме строится поиск пути для ИИ:
**Mode** (`Top View` для видов сверху или `Side View` для платформеров), **Cell Size**,
**Allow Diagonal**, **Auto Build From Colliders**, **Agent Radius** и **Agent Height**,
лимиты вида сбоку **Max Jump Height / Max Jump Distance / Max Fall Height** и собственные
границы (либо **Infinite / Unbound**).

**View Editor** повторяет структуру ассета: блок **настроек объёма** (имя, границы или
infinite/unbound, радиус бленда, приоритет), а затем два независимо включаемых раздела —
**Post-Process Volume** и **Nav Grid Volume**. Каждый эффект — сворачиваемая группа, которая
показывает параметры только во включённом состоянии, и у каждого поля есть подсказка.
Сохранение перестраивает объёмы пост-обработки в открытом уровне, так что изменения сразу
видны во вьюпорте.

> View используется путём размещения его как **мирового ассета** в уровне; о размещении и
> смешивании объёмов см. документ [Редактор](Editor-RU-DOC.md), а о том, что делает каждый
> эффект, — [Графика](Graphics-RU-DOC.md).

### 4.15 Cinema (`.ice_cinema`)

**Редактор:** Cinema Editor

**Cinema** — это **редактор на основе таймлайна** для кат-сцен и скриптовых движений
камеры.

* **Duration**, **Frame Rate**, **Loop**, **Playback Rate** и стартовые позиция/зум камеры.
* **Дорожки (Tracks)**, каждая содержит **ключевые кадры**, с именем и флагами **mute** /
  **lock**. Ключевой кадр — это либо ключ **Camera** (позиция + зум), либо ключ
  **Lua Callback** (вызвать именованную функцию в этот момент), с кривой **easing**
  (`Linear`, `EaseIn`, `EaseOut`, `EaseInOut`, `Bounce`, `Elastic`) и длительностью.

**Cinema Editor** — это интерфейс дорожек/таймлайна:

* **Панель инструментов** — длительность, кадровая частота, зацикливание, скорость
  воспроизведения, **Snap** (привязка плейхеда и ключевых кадров к целым кадрам) и зум
  таймлайна.
* **Стартовая камера** — позиция/зум, с которых начинается сцена, с кнопкой **Захватить старт**,
  чтобы взять текущую камеру редактора, и **Перейти к старту**, чтобы вернуть камеру редактора
  туда.
* **Дорожки** — **+ Добавить дорожку**, **Дублировать дорожку**, удаление, mute и lock. Ставьте ключевые
  кадры обоих типов, перетаскивайте их по таймлайну и выделяйте несколько, чтобы двигать
  разом.
* **Инспектор** — время, длительность, easing и содержимое выбранного ключевого кадра. Для
  ключа камеры **Захватить текущую камеру** записывает в ключевой кадр *текущую камеру редактора*
  (позицию и зум) — скомпонуйте кадр во вьюпорте и нажмите кнопку. **Перейти**
  делает обратное и перемещает камеру редактора к сохранённому значению.
* **Превью** — прокручивайте или проигрывайте таймлайн и смотрите, как камера редактора за
  ним следует.

> Позиции камеры хранятся **относительно размещения cinema в уровне**, поэтому одну и ту же
> кат-сцену можно переиспользовать в разных местах карты.

### 4.16 AI / Дерево поведения (`.ice_ai`)

**Редактор:** AI Editor

**Ассет ИИ** — это **дерево поведения (behavior tree)** плюс определения ключей его
**блэкборда (blackboard)**. Деревья тикаются для каждой сущности во время выполнения.

**Типы нод:**

| Вид | Ноды |
| --- | ---- |
| **Композиты** | `Selector`, `Sequence`, `Parallel` (политика require-one/require-all), `RandomSelector`. |
| **Декораторы** | `Inverter`, `Repeater` (число повторов), `RepeatUntilFail`, `Cooldown` (секунды), `BlackboardCondition` (ключ, операция, значение, **режим прерывания**), `ForceSuccess`, `ForceFailure`, `TimeLimit`. |
| **Задачи (Tasks)** | `Wait` (длительность), `MoveTo` (ключ цели в блэкборде + допустимый радиус), `SetBlackboardValue` (типизированное значение), `ClearBlackboardValue`, `PlayAnimation` (имя состояния), `RunEQS` (запрос + ключ результата), `CustomLua` (имя функции). |
| **Сервисы (Services)** | Периодические тики (интервал + Lua-функция), прикреплённые к ноде. |

Вспомогательные системы: **Blackboard** (типизированная память ключ/значение), **EQS**
(Environment Query System) для пространственных запросов с оценкой и **AI Perception**
(зрение/чувства). Условия и кастомные задачи могут вызывать Lua.

**AI Editor** — это нодовый граф с панелью блэкборда:

* **Ключи блэкборда** — **Добавить ключ**, имя и тип; каждая нода, потребляющая ключ, выбирает из
  этого списка, а не принимает произвольный текст, — так опечатка не сломает дерево молча.
* **Граф** — **Создать корень (Selector)** начинает дерево; контекстное меню каждой ноды
  предлагает **Добавить узел** (отфильтровано по тому, что эта нода допускает),
  **Добавить сервис** и **Удалить узел**. Потомки упорядочены слева направо — именно в этом порядке композиты их и
  выполняют.
* **Свойства ноды** — параметры выбранной ноды (таблица выше), каждый с подсказкой. У
  `BlackboardCondition` есть ещё режим **Прерывание (наблюдатель)**, который решает, может ли
  изменение ключа прервать уже выполняющуюся ветку, — стандартный способ заставить врага
  бросить своё занятие, когда он заметил игрока.
* Кастомные Lua-задачи возвращают дереву свой статус; панель напоминает об ожидаемых
  возвращаемых значениях.

### 4.17 Класс (`.ice_class`)

**Редактор:** Class Editor

**Класс** — это **переиспользуемый игровой объект** в IceBox: определение
сущности с компонентами, скриптингом и **наследованием**. Сбросьте класс в уровень
(перетаскиванием из браузера), чтобы инстанцировать его как сущность; создайте **дочерний
класс**, чтобы специализировать родителя.

Class Editor — это мини-сцена с:

* **Вьюпортом**, показывающим собранную сущность, с сеткой, превью lit/unlit и оверлеями
  отладки. **Reset Camera** заново кадрирует сущность; редактировать можно как **локальный**,
  так и **глобальный** трансформ.
* **Панелью компонентов** для добавления и настройки компонентов — Transform, Sprite
  Renderer, Collider (box/sphere/capsule), Tilemap Renderer, Flipbook, Audio, FX, Widget,
  Rigidbody (с настройками рэгдолла), Animator, Skeleton, Camera, Light (point/spot),
  Point Marker, Decal, AI, Joint, Stencil, Destructible, **Replication** (синхронизация в
  мультиплеере) и вложенные **Class Components** (композиция других классов).
* **Несколькими экземплярами на компонент.** Большинство визуальных и физических компонентов
  — это списки: класс может содержать сразу несколько спрайтов, коллайдеров, источников
  света, аудио-источников или шарниров. У каждого экземпляра есть имя, его можно
  переставлять (**вверх/вниз**) и у него свои настройки **привязки к сокету**. Клик правой
  кнопкой по компоненту даёт **Копировать настройки / Вставить настройки**.
* **Тремя вкладками** — **Компоненты** (список выше), **Наследование** (показывается, когда
  у класса есть родитель) и **Отладка** (флаги отладки вьюпорта, сохраняемые с ассетом).
* **Редактором скрипта**, предлагающим либо **текстовый Lua**-скрипт, либо нодовый граф
  **Visual Script** — на выбор для каждого класса — с кнопкой **Compile**. Дочерний класс
  показывает скрипт родителя рядом со своим, только для чтения.
* **Наследованием** — у класса может быть родитель; он наследует компоненты и скрипт
  родителя. Унаследованные компоненты помечены, их можно **переопределять** по полям и
  **сбрасывать к родителю** по отдельности, а вкладка *Наследование* показывает всю цепочку
  предков. **Reparent** меняет родителя с обнаружением циклов; **Show/Hide Parent**
  переключает показ графики родителя в превью.
* **Is Component** помечает класс как строительный блок, предназначенный для вложения в
  другие классы, а не для прямого размещения в уровне.

> Удаление класса из Браузера контента также удаляет классы, наследующие от него, — см.
> [3.11](#311-удаление-ассетов-и-безопасность-ссылок).

> Класс хранит данные компонентов и ссылки на скрипты. API скриптинга Lua/Visual за рамками
> этого документа — см. [LuaAPI-RU-DOC.md](LuaAPI-RU-DOC.md).

#### 4.17.1 Справочник компонентов

Меню **Добавить компонент** делит каталог на шесть подменю:

| Меню | Компоненты |
| ---- | ---------- |
| **Rendering** | Sprite Renderer, Tilemap Renderer, Animator, Skeleton, Flipbook, Camera. |
| **Lighting** | Point Light, Spot Light. |
| **Collisions** | Rigidbody, Box Collider, Sphere Collider, Capsule Collider, Joint, Destructible. |

| **UI** | Widget, Point Marker, Decal. |
| **Logic** | AI Brain, Class Component. |

**Stencil Mask** и **Replication** всегда доступны у сущности и не добавляются из этого
меню, а **Transform** есть у неё изначально. Компоненты, помеченные ниже как *(единственный)*,
существуют в одном экземпляре на класс; остальные — списки, в которые можно добавлять сколько
угодно экземпляров. Класс с флагом **Is Component** не может принимать единственные
компоненты (Animator, Skeleton, Camera, Rigidbody, Destructible, AI), потому что они
принадлежат классу-хозяину.

**Свойства, общие для всех экземпляров**

| Свойство | Значение |
| -------- | -------- |
| **Name** | Имя экземпляра — по нему на него ссылаются скрипты и поля *Attach To*. |
| **Local Transform** | Позиция, поворот и масштаб относительно сущности. |

**Копировать настройки / Вставить настройки**.

**Привязка** — доступна только у экземпляров **Sprite Renderer** и **Flipbook**:

| Свойство | Значение |
| -------- | -------- |
| **Attach To Socket** | Следовать за именованным сокетом (точкой привязки) спрайта, флипбука или скелета этой сущности; движок пересчитывает позицию и поворот каждый кадр, корректно с учётом поворота и масштаба сущности. |
| **Socket Source** | Какой компонент даёт сокет. `Auto` ищет сначала скелет, потом спрайты, потом флипбуки. |
| **Socket Source Index** | Индекс экземпляра компонента-источника (`-1` — искать во всех). |
| **Inherit Flip X** | Копировать Flip X у владельца сокета, чтобы привязанная графика отражалась вместе с персонажем. |
| **Socket Offset** / **Socket Offset Rotation** | Дополнительные смещение и поворот поверх сокета, в пространстве сокета — масштабируются вместе с сущностью и отражаются по Flip X. Пригодны для точной подгонки или для отдачи оружия из скрипта. |
| **Attach To Collider** | Следовать за частью-коллайдером **Separate Body** этой сущности (позиция и поворот). |

**Свойства теней** — общие для Sprite, Flipbook, Skeleton и коллайдеров:

| Свойство | Значение |
| -------- | -------- |
| **Cast Shadow** | Отбрасывает ли этот экземпляр 2D-тени. |
| **Cast Shadow Mode** | `Colliders` — тень строится по формам коллизии ассета; `Contour` — по силуэту альфа-канала текстуры, даже без коллайдера. (Sprite / Flipbook / Skeleton.) |
| **Shadow Origin** | Откуда отбрасывается тень по вертикальной оси источника: `Top`, `Center` или `Bottom`. |
| **Shadow Edge Fade** | Смягчает края тени, сжимая силуэт внутрь (`0` — резкий, `1` — полностью схлопнут). |
| **Shadow Z Order** | Смещение плоскости тени по Z относительно источника. Тень затемняет только объекты с меньшим Z отрисовки: отрицательное значение уводит её в фон, положительное выносит вперёд. |
| **Don't Block Shadows** | При глобально включённом *Colliders Block Shadows* этот объект всё равно пропускает тени сквозь себя. Выключайте только для рельефа/тайлов, чтобы они перекрывали тени. |

### 4.18 Локализация (`.ice_localization`)

**Редактор:** Localization Creator

Таблица **игровой локализации** — переводы, которые поставляет ваша *игра* (в отличие от
языка интерфейса самого редактора). Структура:

```json
{
    "Languages": ["en", "ru", "de"],
    "Keys": {
        "menu_play": { "en": "Play", "ru": "Играть", "de": "Spielen" },
        "menu_quit": { "en": "Quit", "ru": "Выход",  "de": "Beenden" }
    }
}
```

Во время выполнения игра загружает этот ассет, выбирает язык и ищет ключи (с аргументами
форматирования в стиле `{}` и автоматической обработкой RTL для арабского/иврита). Виджеты
могут привязывать текст напрямую к ключу локализации.

**Localization Creator** управляет списком языков и таблицей ключ/перевод:

* Открытая без ассета, панель предлагает **Сканировать папку Content** — найти все `.ice_localization` в
  проекте и открыть один из списка — и **Создать новый ассет локализации**, создающую новую таблицу в `Content/`.
* **+ Добавить** добавляет код языка (`en`, `ru`, `de`, …) новым столбцом; **+ Добавить ключ**
  добавляет строку. Удаление работает по выбранному ключу или языку.
* Поле **фильтра** сужает список ключей — это важно, когда в реальной игре их становятся
  сотни.
* Выбор ключа показывает его перевод для всех языков рядом, так что пропуски сразу заметны.

> Это локализация **игры**. Язык интерфейса самого редактора — это настройка в Preferences,
> см. [Редактор](Editor-RU-DOC.md).

### 4.19 Уровень (`.icemap`)

**Редактор:** главный Viewport / Level Outliner

**Уровень** (`.icemap`) — это сцена: сущности, их компоненты и настройки мира. Это
единственный ассет, который вы редактируете в **главном Viewport**, а не в отдельной
панели — двойной клик по нему загружает уровень. Уровни ссылаются на ассеты выше (спрайты,
тайлмапы, материалы, классы, виджеты и т. д.).

> Редактирование уровней, сущностей и компонентов — это область документации по редактору и
> скриптингу; этот документ сфокусирован на ассетах, которые потребляет уровень.

### 4.20 Скрипт (`.lua`) и Текст (`.txt`)

* **`.lua`** — самостоятельный Lua-скрипт (значок `LU`), создаётся через **Прочее ▸ Создать
  Lua-скрипт**. Новый скрипт сразу содержит заготовку модуля (`local M = {} … return M`),
  чтобы его можно было подключать в скриптах классов, уровня и виджетов через `require`.
  Двойной клик открывает **Редактор Lua-скриптов** — тот же редактор кода, что и в
  редакторе класса, только сам по себе и без всего остального: подсветка синтаксиса,
  **Сохранить** (`Ctrl+S`), **Компилировать** с индикатором `OK`/`Ошибка` (строка с
  ошибкой помечается, текст показывается в подсказке), позиция курсора и общие
  Lua-помощники — отмена/повтор, поиск и замена, переход к строке, навигатор функций,
  шаблоны-сниппеты, автодополнение и необязательная автокомпиляция. Скрипты
  перемещаются, переименовываются и удаляются как любой другой ассет (ссылки внутри них
  правятся, а на старом месте остаётся редиректор), проверяются командой
  **Компилировать скрипты** (`Ctrl+R`) и пошагово отлаживаются в
  **Отладчике Lua-скриптов**. **Язык Lua и API движка описаны отдельно** в
  [LuaAPI-RU-DOC.md](LuaAPI-RU-DOC.md).
* **`.txt`** — простая текстовая заметка (значок `NT`), создаётся через **Other ▸ Text
  Note**. Двойной клик открывает **редактор текстовых заметок**: нейтральный по синтаксису
  редактор кода с меню *File ▸ Save* (`Ctrl+S`) и меню *Edit* (отмена/повтор,
  копировать/вырезать/вставить, выделить всё). Полезна для проектных заметок, списков дел и
  небольших файлов данных.

### 4.21 Декаль (`.ice_decal`)

**Редактор:** редактор декалей

**Декаль** — это след, который игра оставляет на поверхности во время игры: дырка от пули,
брызги крови, копоть, отпечаток ноги, трещина. Один ассет `.ice_decal` описывает, как этот
след выглядит и ведёт себя, а всё остальное берёт на себя система декалей движка —
случайную вариативность, время жизни, появление и затухание, сортировку, отсечение,
пул и бюджет.

Создаётся через **Materials ▸ Создать декаль** либо правым кликом по текстуре —
**Создать декаль**, тогда ассет сразу будет ссылаться на неё. Двойной клик открывает
**редактор декалей**: слева живой предпросмотр, справа настройки.

**Варианты текстур** — список изображений, которые может использовать декаль. В каждой
строке текстура, **вес** (относительный шанс выпадения) и необязательная **область
текстуры** для выборки подкартинки из атласа. При каждом спавне выбирается случайный
вариант — именно поэтому десять дырок от пуль на одной стене не выглядят одинаково.
Оставьте один вариант, если след всегда должен быть одним и тем же.

**Материал** — необязательный материал с **Доменом = Декаль** (или его экземпляр
материала). Если он задан, он заменяет обычную отрисовку текстурой, а текстура декали
становится текстурой сущности этого материала, поэтому работает весь граф нодов: семплы
текстур, скалярные / векторные / текстурные параметры, функции материалов и коллекции
параметров. Нод **Данные декали** дополнительно отдаёт живое состояние декали — затухание,
возраст, нормализованный возраст, время жизни и постоянное случайное значение этой декали.

**Внешний вид** — размер (ноль берёт его из текстуры), разброс размера и сохраняет ли этот
разброс пропорции, опорная точка, оттенок, разброс оттенка, режим освещения (Lit / Unlit),
режим смешивания и порог отсечения по альфе для режима Masked.

**Поворот** — фиксированный, случайный (между минимумом и максимумом), по нормали, либо по
нормали со случайным разворотом на 180°. Сверху можно включить случайное отражение по
горизонтали и вертикали.

**Время жизни** — сколько живёт декаль (ноль = навсегда), за сколько она появляется и
затухает, и **Максимум экземпляров**: ограничение на ассет, при превышении которого самая
старая декаль этого вида начинает гаснуть.

**Размещение** — смещение по Z, которое поднимает декаль перед поверхностью, порядок
сортировки среди декалей, смещение вдоль нормали попадания, **Следовать за поверхностью**
(прикрепить к задетой сущности, чтобы декаль двигалась вместе с ней) и **Обрезать по
поверхности** (обрезать декаль по границам поверхности, чтобы кровь не свисала за край
персонажа).

Декали спавнятся из скрипта через API `Decal.*`, а также могут быть **расставлены вручную**
компонентом **Декаль** в редакторе классов. Скриптовая часть описана в
[LuaAPI-RU-DOC.md](LuaAPI-RU-DOC.md), раздел 62.

## 5. Импортёры

Помимо простого копирования-с-сайдкаром, два специализированных импортёра автоматически
превращают внешние форматы в нативные ассеты.

### 5.1 Импортёр Aseprite

Сбросьте **экспорт Aseprite в JSON** (файл `.json`, создаваемый функцией Aseprite *Export
Sprite Sheet* с данными JSON) на браузер, либо используйте **Импортировать таблицу спрайтов Aseprite** на уже
лежащем в проекте файле Aseprite `.json`. Импортёр:

* Определяет, является ли JSON файлом Aseprite, и **автоматически находит соответствующий
  PNG** (по ссылке на изображение в JSON); если PNG не найден, он сообщает об этом в Консоль,
  а не создаёт половину импорта.
* **Копирует лист в проект** как `T_<имя>.png` с сайдкаром `.ice_texture` по умолчанию.
* Нарезает лист на **спрайты** с именами `SP_<имя>_0`, `SP_<имя>_1`, … по прямоугольникам
  кадров, с центрированной точкой опоры.
* Восстанавливает **флипбуки** из **тегов кадров** Aseprite: по одному `FB_<имя>_<тег>` на
  тег (или единственный `FB_<имя>`, если тегов нет), с покадровыми длительностями из JSON и
  FPS по умолчанию, выведенным из реальной общей длительности. **Направление** тега
  учитывается: `reverse` переворачивает порядок кадров, а `pingpong` дописывает обратный ход.

Это самый быстрый путь от Aseprite к анимированным спрайтам в движке: нарисовали,
экспортировали с данными JSON, сбросили JSON в браузер — готово.

### 5.2 Импортёр GIF

Импорт **`.gif`** декодирует все кадры и создаёт полный готовый набор:

* Все кадры упаковываются в **единую текстуру спрайт-листа** (сетка, близкая к квадрату) с
  сайдкаром `.ice_texture` по умолчанию.
* По одному **спрайту** на кадр, указывающему на свою ячейку в этом листе.
* Один **флипбук**, покадровые длительности которого взяты из собственных задержек GIF.

Отлично для быстрого добавления анимированного пиксель-арта или референс-лупов.

## 6. Подготовка ассетов (cooking) — обзор

Во время разработки вы работаете с **россыпью несжатых** ассетов для быстрой итерации. Для
релизной сборки опциональный **подготовщик (cooker)** конвертирует сырые медиа в сжатые,
удобные для рантайма формы — обычно резко уменьшая размер сборки, при этом загрузчики
времени выполнения остаются неизменными.

Что умеет подготовка (кратко):

| Медиа | Подготовленные формы |
| ----- | -------------------- |
| **Текстуры** | WebP (с потерями/без потерь) или KTX2 (GPU-сжатие: UASTC высокого качества / ETC1S компактный). Управляется сайдкаром каждой текстуры (sRGB, макс. размер, Compression…). Результаты сжатия с потерями проверяются и заменяются на без потерь, если они заметно искажают арт. |
| **Аудио** | Ogg Vorbis или Opus с выбранным битрейтом. |
| **Видео** | VP9 с выбранным качеством (CRF), с опциональными ограничениями разрешения/FPS и обработкой звука. |
| **Шрифты** | Сабсет до объявленных диапазонов глифов (или авто-сабсет до используемых глифов). |
| **JSON / сайдкары** | Минификация. |

Сайдкары, которые вы создаёте в этом документе, являются **входными данными** для
подготовки. Полные настройки подготовки, ограничения по платформам, формат архива IcePak,
упаковка/разбиение, манифесты сборки и инсталляторы описаны в
[Профайлинг и сборка игр](Profiling-And-Building-RU-DOC.md).

## 8. FAQ и устранение проблем

**Почему я не вижу файлы `.ice_texture` / `.ice_sound` в браузере?**
Это **сайдкары**, и они скрыты намеренно. Выберите исходный файл (например, `.png`) и
откройте его панель настроек. Сайдкар перемещается/переименовывается/удаляется вместе с
исходником автоматически.

**Я переместил ассет, а ссылка всё ещё работает — как?**
Либо ссылка была переписана на новый путь, либо **редиректор** теперь разрешает старый
путь. Используйте **Asset References** для проверки зависимостей и периодически
**Исправить редиректоры** для наведения порядка.

**Где хранятся редиректоры?**
В **`Saved/Redirectors/`**, вне `Content/`, — это метаданные проекта, а не контент. Эту
папку можно удалить, если вы уверены, что ни один ассет больше не указывает на старый путь;
иначе используйте **Исправить редиректоры**, который сначала перепишет оставшиеся ссылки.
Редиректоры, чья цель больше не существует, удаляются автоматически.

**Почему поиск показывает файлы из других папок?**
Потому что поиск **рекурсивный** — из корня он охватывает весь проект, из подпапки — её
поддерево. Результаты вне текущей папки показываются с относительным путём. То же относится и
к фильтрам типов. Очистите поле поиска (кнопка **X**) или фильтры (кнопка **Все**), чтобы
вернуться к обычному списку папки.

**Я удалил класс, и другие классы тоже исчезли.**
Классы, **наследующие** от удалённого, удаляются вместе с ним — дочерний класс не может
существовать без родителя. Это происходит после подтверждения, поэтому в диалоге их нет;
`Ctrl+Z` (при активном браузере) восстанавливает всю пачку.

**Как скопировать ассеты в другой проект?**
Выделите их, кликните правой кнопкой, **Мигрировать в...**
([3.16](#316-перенос-ассетов-в-другой-проект)). Он тянет за собой зависимости и сохраняет
структуру папок, чего простое копирование файлов не делает.

**Можно ли держать открытыми два ассета сразу?**
Да — у каждого ассета своя панель-редактор, их можно свободно докировать и раскладывать по
вкладкам. Открытие уже открытого ассета фокусирует существующую панель, а не дублирует её.

**Можно ли править JSON ассета вручную?**
Да — ассеты движка это обычный JSON — но редакторы безопаснее (они сохраняют согласованность
ID, ссылок и кэшей). Ручная правка полезна в основном для понимания diff'ов.

**В чём разница между Material, Material Instance и MPC?**
**Material** — это нодовый граф шейдера. **Material Instance** дёшево переопределяет открытые
параметры материала. **MPC** — это *глобальный* набор параметров, который множество
материалов читают одновременно.

**В чём разница между Flipbook и ассетом Animation?**
**Flipbook** — это фиксированная последовательность кадров. Ассет **Animation** — это
*машина состояний*, которая выбирает, какой флипбук воспроизвести, на основе параметров и
переходов.

**Класс vs Уровень?**
**Класс** — это переиспользуемый игровой объект (можно инстанцировать множество во
множестве уровней). **Уровень** (`.icemap`) — это конкретная сцена, содержащая экземпляры.

**Как сделать игру меньше?**
Включите **Cook Assets** (и опционально **Pack Content**) на этапе сборки — см.
[Профайлинг и сборка игр](Profiling-And-Building-RU-DOC.md). Задавайте макс. размер текстур
и диапазоны глифов шрифтов в сайдкарах, чтобы дать подготовщику хорошие входные данные.
